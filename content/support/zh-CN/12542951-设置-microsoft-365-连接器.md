# 设置 Microsoft 365 连接器

本文指导管理员为其组织在 Claude 中启用 Microsoft 365 连接器，包括授予 Microsoft Entra 同意、限制访问和管理权限。设置完成后，租户中的用户可以将 Microsoft 365 连接到自己的 Claude 账户，以便从 Claude 中搜索 SharePoint、OneDrive、Outlook 和 Teams。您还可以启用写入工具，允许 Claude 代表成员发送电子邮件、管理日历事件、创建和更新文件以及发送 Teams 消息。

Microsoft 365 连接器适用于所有 Claude 计划：Free、Pro、Max、Ultra、Team 和 Enterprise。

**有关设置完成后连接和使用 Microsoft 365 的最终用户说明，请参阅 [连接到 Microsoft 365](https://support.claude.com/en/articles/15183774)。**

**重要提示：**本文涵盖工作和学校账户，这些账户需要 Microsoft Entra 租户。个人 Microsoft 账户无需管理员设置，不会在 Team 和 Enterprise 计划中显示。详细了解 **[连接到 Microsoft 365](https://support.claude.com/en/articles/15183774-connect-to-microsoft-365#h_cffabf2c6c)**。

## 设置概览

在组织中的任何人都可以连接 Microsoft 365 之前，需要进行两项操作，如果要启用写入工具，还需要进行可选的第三步：

1. **在 Team 和 Enterprise 计划上：**Claude 组织所有者为组织启用 Microsoft 365 连接器。

2. **在每个租户中：**Microsoft Entra 全局管理员授予一次性同意，授权为租户进行集成。

3. **启用写入工具：**Microsoft Entra 管理员同意更新的权限集，您为组织启用写入工具。请参阅下面的 **[启用写入工具](#h_a51d877afd)**。

完成这些步骤后，成员可以按照 **[连接到 Microsoft 365](https://support.claude.com/en/articles/15183774)** 中的步骤将 Microsoft 365 连接到自己的 Claude 账户。

## 为您的组织启用连接器

此步骤仅适用于 Team 和 Enterprise 计划。在 Free、Pro、Max 和 Ultra 计划上，请跳到下一部分。

1. 登录 Claude。

2. 导航到 **[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)**。

3. 单击页面顶部的 “+ 添加”，然后单击 “所有可用项。”

4. 找到 **Microsoft 365** 并单击 “添加到您的团队。”

## 授予 Microsoft Entra 管理员同意

租户中的 Microsoft Entra 全局管理员需要在任何人连接之前授权集成。有两种方法可以执行此操作。

### 选项 1：通过 Claude 同意

如果您的 Microsoft Entra 全局管理员有 Claude 账户，他们可以在标准连接流程中授予同意：

1. 导航到 **[自定义 > 连接器](https://claude.ai/customize/connectors)**。

2. 找到 **Microsoft 365** 并单击 “连接。”

3. 如果系统询问，请选择 “工作或学校账户。”

4. 使用 Microsoft 365 凭据进行身份验证。

5. 查看并接受请求的权限，勾选复选框以代表整个组织授予访问权限。

之后，同一 Entra 租户中的其他人可以按照标准最终用户步骤进行连接。他们不会看到同意提示，只需进行身份验证并开始使用集成。

### 选项 2：在 Microsoft Entra ID 中手动设置

如果您的 Microsoft Entra 全局管理员没有 Claude 账户，或者需要排查应用安装和权限设置问题，请使用此路径。您可以直接在 Microsoft Entra ID 中添加连接器应用并授予管理员同意。

此过程向租户添加两个服务主体。每个主体为两个 M365 MCP for Claude 应用注册之一建立服务级别标识，允许它们通过 Microsoft Graph API 访问和交互您的组织的数据和资源。

**1. 添加服务主体**

使用 Microsoft Graph Explorer，添加两个必需的服务主体：

M365 MCP Client for Claude：

```
POST https://graph.microsoft.com/v1.0/servicePrincipals
{"appId":"08ad6f98-a4f8-4635-bb8d-f1a3044760f0"}
```

M365 MCP Server for Claude：

```
POST https://graph.microsoft.com/v1.0/servicePrincipals
{"appId":"07c030f6-5743-41b7-ba00-0a6e85f37c17"}
```

**2. 授予管理员同意**

构造并在浏览器中访问以下 URL，将 {your-tenant-id} 替换为您的组织租户 ID。

M365 MCP Client for Claude：

```
https://login.microsoftonline.com/{your-tenant-id}/adminconsent?client_id=08ad6f98-a4f8-4635-bb8d-f1a3044760f0
```

M365 MCP Server for Claude：

```
https://login.microsoftonline.com/{your-tenant-id}/adminconsent?client_id=07c030f6-5743-41b7-ba00-0a6e85f37c17
```

访问每个 URL 时，系统会提示您同意集成所需的委派权限，代表您的组织。

**3. 完成设置**

- **Team 和 Enterprise 计划：**Claude 组织所有者需要在 **[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)** 中启用连接器。然后成员可以单独连接。

- **Free、Pro、Max 和 Ultra 计划：**成员可以导航到 **[自定义 > 连接器](https://claude.ai/customize/connectors)**，找到 **Microsoft 365**，然后单击 “连接。”如果系统询问，他们选择 “工作或学校账户。”

### 限制谁可以使用连接器

要限制租户中哪些人可以通过 Claude 向 Microsoft 365 进行身份验证：

1. 转到 entra.microsoft.com 的 Microsoft Entra 管理中心。

2. 导航到 **M365 MCP Server for Claude** 企业应用程序。

3. 转到 **属性**，将 **需要分配？**设置为 “是。”

4. 在 **用户和组** 下，添加应该有权访问的特定用户或组。

5. 对 **M365 MCP Client for Claude** 企业应用程序重复相同的步骤。

两个组件都需要限制为同一组授权人员。

### 限制连接器可以使用的权限

要限制集成可以访问的资源类型，请从默认授权范围集中选择性地撤销权限。这需要 Microsoft Entra 管理员访问权限。

1. 作为 Microsoft Entra 管理员，请转到 entra.microsoft.com。

2. 选择“企业应用程序。”

3. 在搜索框旁边，移除应用程序类型筛选器。

4. 搜索并点击“M365 MCP Server for Claude。”

5. 转到**权限**。

6. 在**管理员同意**选项卡下的 Microsoft Graph 权限列表中，选择要撤销的权限，然后点击“**…**”按钮。

7. 选择“撤销权限”并用“是，撤销。”确认

撤销后，尝试使用该权限访问资源将返回“调用工具失败”错误。

成员也可以在自己的 Microsoft 365 设置中单独关闭特定工具，以防止 Claude 尝试访问已撤销权限的工具。

要恢复已撤销的权限，请按照**选项 2：在 Microsoft Entra ID 中手动设置**中描述的步骤授予管理员同意。这将把权限恢复为默认状态。

## 启用写入工具

写入工具让 Claude 可以发送电子邮件、管理草稿和日历事件、更新邮箱设置，以及在 OneDrive 和 SharePoint 中创建和更新文件，并在 Microsoft Teams 中发送消息。无论是否启用写入工具，读取和搜索工具的工作方式相同。

**1. 重新同意更新的权限**

连接器的权限集现在包括额外的 Microsoft Graph 范围以支持写入工具。如果您的租户在写入工具或 Teams 写入工具推出前同意，Microsoft Entra 全局管理员需要在写入工具激活前审查并批准更新的权限集。在您租户的**企业应用程序**同意流程中审查并批准连接器的更新权限。

**2. 为您的组织启用写入工具**

转到**[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)**，找到“Microsoft 365，”并为每个写入工具选择一个设置：**始终允许**、**需要批准**或**已阻止**。您的更改在保存后立即生效。企业计划可以通过**[自定义角色](https://support.claude.com/en/articles/13930452-manage-custom-roles-on-enterprise-plans#h_979e558d00)**为用户子集启用写入工具。

对于 Microsoft Teams，请单独设置每个 Teams 写入工具：发送、发布和回复工具可以设置为**需要批准**或**已阻止**（成员确认每次发送），启动新聊天也可以设置为**始终允许**。如果您的组织在 2026 年 11 月 9 日之后首次添加 Microsoft 365 连接器，发送、发布和回复工具也可以设置为**始终允许**，成员随后可以为其选择**始终允许**。移除连接器并重新添加通常会保留您组织的原始安装日期。

如果您看到关于这些工具的通知，您现在可以在**审查写入工具**、**审查工具限制**或**工具**选项卡中将其设置为**始终允许**。对于您设置为**始终允许**的每个工具，限制立即结束，成员随后可以为其选择**始终允许**。某些成员过去可能已为该工具选择了**始终允许**。该早期选择可以立即生效，因此 Claude 可以停止询问他们。Claude 默认会询问所有其他人，直到他们选择为止。

如果您有多个 Microsoft 365 连接器，请在每个连接器上保存该工具。在 2026 年 11 月 9 日之前保存的**始终允许**不会结束限制，直到您再次保存。对于其余这些工具，成员必须继续批准每次使用，直到限制在 2026 年 12 月 9 日或之后移除。您到那时尚未设置的任何这些工具将更改为**需要批准**，除非整个连接器设置为**已阻止**。

您保存的更改立即生效。设置为**始终允许**的工具如果默认被阻止，会立即打开。使用**始终允许**，Claude 可能会在不先询问任何人的情况下使用工具，包括在“自动批准”模式和某些计划任务中，例如设置为“自动批准”的云计划任务或 Claude Code 例程。计划任务可能会失去对**需要批准**工具的访问权限。在 Cowork 中，成员只有在组织设置**允许连接器工具的“始终允许”**打开时，才能为写入工具选择**始终允许**。

将连接器的默认限制设置为**无限制**不会打开默认被阻止的工具。

已启用 HIPAA 的组织不属于这些默认阻止和限制的更改：他们不会收到通知，设置**始终允许**或首次添加连接器都不会结束此限制。

如果您的 Team 或 Enterprise 组织在 2026 年 11 月 9 日之前添加了连接器，两个限制将适用至少到 2026 年 12 月 9 日：

- 如果您的组织在写入工具或 Teams 写入工具推出前使用了连接器，某些写入工具默认被阻止，至少到 2026 年 12 月 9 日。要更早打开它们，请转到**[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)**，找到“Microsoft 365，”并为每个工具选择一个设置。在 2026 年 12 月 9 日或之后，任何仍默认被阻止的工具将设置为**需要批准**，除非整个连接器设置为**已阻止**。如果这些工具之一属于 Anthropic 将在该日期或之后移除限制的 11 个 Outlook、Calendar 和 Teams 工具，您现在可以将其设置为**始终允许**。它会立即打开。在您的每个 Microsoft 365 连接器上保存后，该工具的限制结束，成员可以为其选择**始终允许**。Claude 随后可能会在不先询问任何人的情况下使用它，包括在“自动批准”模式和某些计划任务中，例如设置为“自动批准”的云计划任务或 Claude Code 例程。计划任务可能会失去对**需要批准**工具的访问权限。已启用 HIPAA 的组织不属于这些默认阻止和限制的更改。企业计划可以通过**[自定义角色](https://support.claude.com/en/articles/13930452-manage-custom-roles-on-enterprise-plans#h_979e558d00)**为用户子集启用写入工具。

- 用户无法为 11 个工具选择**始终允许**，因此在聊天和 Cowork 中，他们确认每次使用。这些是发送电子邮件或 Teams 消息、创建、更改、删除或响应日历事件，或设置自动回复的工具。启动新的 Teams 聊天不是其中之一，可以设置为**始终允许**。

两个限制将在 2026 年 12 月 9 日或之后结束。请参阅下面的**[2026 年 12 月 9 日或之后推出：写入工具的更改](#h_2f203e56aa)**。

**3. 验证**

启用后，要求 Claude 执行低风险写入操作，例如“为我起草一封电子邮件，但不要发送，”以确认写入工具处于活动状态。

**注意：**Claude 发送的电子邮件包含标识其为代理启动的归属标头。文件写入、日历写入和 Teams 消息目前未标记。当 Claude 创建或更新日历事件时，Microsoft 365 会自动向与会者发送邀请或更新通知。写入工具不支持附件，因此发送、转发和起草都会拒绝包含附件的消息。写入工具还受到每用户写入、发送和收件人数量的限制。

## 2026 年 12 月 9 日或之后推出：写入工具的更改

这适用于在 2026 年 11 月 9 日之前添加 Microsoft 365 连接器的 Team 和 Enterprise 组织。

在 2026 年 12 月 9 日或之后，Anthropic 将移除对 11 个工具的限制。在此之前，在聊天和 Cowork 中，Claude 在每次使用这些工具前都会询问用户。

**11 个工具：**

- **Outlook：**发送电子邮件、转发电子邮件、发送草稿、设置自动回复

- **Calendar：**创建、更改、删除或响应事件

- **Teams：**发送聊天消息、在频道中发布、在频道中回复

**您现在可以做什么：**

- 为任何写入工具选择一个设置。您的更改在保存后立即生效。

- 如果您看到关于这些工具的通知，您现在可以将其设置为**始终允许**。用户必须继续批准每次使用，直到限制被移除。

- 当您将被阻止的工具设置为**始终允许**或**需要批准**时，它会立即打开。

- 设置为**自动批准**的云计划任务或 Claude Code 例程可以使用设置为**始终允许**的工具而无需询问任何人。计划任务可能会失去对**需要批准**工具的访问权限。

**当限制被移除时：**

- 您未单独设置的 11 个工具中的任何一个都将设置为**需要批准**，即使连接器的默认限制是**无限制**。

- 您保存的设置会保留。您设置为**已阻止**的工具保持**已阻止**。

- 用户只有在您将该工具设置为**始终允许**时，才能为这些工具之一选择**始终允许**。在 Cowork 中，**允许连接器工具的“始终允许”**也必须打开。默认情况下它是关闭的。

- 仍默认被阻止且您未更改的写入工具将被打开并设置为**需要批准**。要保持工具关闭，请将其设置为**已阻止**。

- 如果您已将整个连接器设置为**已阻止**，其工具保持被阻止。

移除连接器并重新添加不会移除限制。在 2026 年 11 月 9 日之后首次添加连接器的组织没有它。

## 权限参考

Microsoft 365 连接器使用**委派权限**，这意味着 Claude 代表每个用户行动，只能访问该用户已有权限在 Microsoft 365 中查看的数据。权限默认为只读。只有启用写入工具后，Claude 才能发送、创建或更新内容。

在身份验证期间，集成请求以下权限：

**基本访问**

- `User.Read`：登录并读取用户资料

- `openid`：使用组织帐户登录

- `offline_access`：保持对数据的访问权限

- `email`：查看电子邮件地址

- `profile`：查看基本资料信息

**电子邮件 (Outlook)**

- `Mail.Read`：读取电子邮件

- `Mail.ReadBasic`：读取电子邮件元数据（发件人、主题、日期）

- `Mail.Read.Shared`：读取用户有权访问的邮箱中的电子邮件

  - **注意：**共享邮箱访问权限通过 `Mail.Read.Shared` 权限包含。用户可以搜索他们在 Microsoft 365 中拥有委派访问权限的共享邮箱，包括完全访问和文件夹级别的委派。除了标准管理员同意和 Microsoft 365 中已配置的委派权限外，无需其他设置。

- `MailboxFolder.Read`：读取邮箱文件夹结构

- `MailboxItem.Read`：读取邮箱中的项目

- `MailboxSettings.Read`：读取邮箱设置，如用户的时区

**注意：**电子邮件搜索涵盖每个用户的主邮箱（包括其存档文件夹）以及他们可以访问的任何共享邮箱。它不涵盖单独的在线存档邮箱（也称为就地存档），因此保留策略移至该处的邮件不会出现在搜索结果中。

**日历**

- `Calendars.Read`：读取日历事件

- `Calendars.Read.Shared`：读取与用户共享的日历

**Teams 聊天**

- `Chat.Read`：读取 Teams 聊天消息

- `Chat.ReadBasic`：读取 Teams 聊天元数据

- `ChatMember.Read`：读取聊天参与者信息

- `ChatMessage.Read`：读取 Teams 聊天消息

**Teams 频道**

- `Team.ReadBasic.All`：读取团队的名称和描述

- `Channel.ReadBasic.All`：读取频道名称和描述

- `ChannelMessage.Read.All`：读取频道消息

**会议**

- `OnlineMeetings.Read`：读取在线会议

- `OnlineMeetingTranscript.Read.All`：读取会议记录

- `OnlineMeetingAiInsight.Read`：读取 AI 生成的会议见解

- `OnlineMeetingArtifact.Read.All`：读取会议录制和工件

- `OnlineMeetingRecording.Read.All`：读取会议录制

**文件 (OneDrive 和 SharePoint)**

- `Files.Read`：读取用户文件

- `Files.Read.All`：读取用户可以访问的所有文件

- `Sites.Read.All`：读取 SharePoint 网站中的项目

**写入权限**

以下权限支持写入工具，包含在更新的同意集中：

- `Mail.Send`：发送和转发电子邮件

- `Mail.ReadWrite`：创建、更新和删除草稿；移动和标记邮件

- `Calendars.ReadWrite`：创建、更新、删除日历事件并响应邀请

- `Files.ReadWrite.All`：在 OneDrive 和 SharePoint 中创建、更新和删除文件和文件夹。删除的项目进入回收站。

- `MailboxSettings.ReadWrite`：管理类别、收件箱规则和自动回复

- `ChatMessage.Send`**：**代表用户发送 Teams 聊天消息

- `ChannelMessage.Send`**：**在 Teams 频道中发布或回复

- `Chat.Create`：代表用户启动新聊天

- `People.Read`：在组织中查找人员以开始聊天

**用户目录**

- `User.ReadBasic.All`：读取组织中所有用户的基本个人资料信息（用于查找会议可用性）

Microsoft 365 连接器使用用户的权限在整个租户中搜索 SharePoint。不支持特定于网站的搜索限制。

## 隐私和安全

- **权限继承：**Claude 镜像每个用户现有的 Microsoft 365 权限。成员无法通过 Claude 访问他们在 Microsoft 365 中无法直接查看的任何内容。

- **按您的请求。**Claude 在您询问时或在您设置的计划任务需要时访问 Microsoft 365。

- **可撤销的访问权限：**成员可以通过 **[自定义 > 连接器](https://claude.ai/customize/connectors)** 断开自己的集成。Team 和 Enterprise 计划所有者也可以在 **[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)** 中为整个组织删除连接器。

有关更多详情，请参阅 **[Microsoft 365 连接器安全指南](https://support.claude.com/en/articles/12684923-)**。

## 故障排除

### 成员无法进行身份验证

1. 确认其帐户已关联到 Microsoft Entra 租户，而不是个人 Microsoft 帐户。

2. 确认其 Microsoft 365 许可证处于活跃状态。

3. 确认已使用上述选项 1 或选项 2 授予管理员同意。

4. 检查租户中的条件访问策略是否阻止连接。请参阅下文：**[条件访问阻止连接](#h_c7635fb6e2)**。

### 成员看到 “工具调用失败” 错误

权限可能已在 Microsoft Entra 中被选择性撤销。成员可以在其 Microsoft 365 设置中关闭相应的工具以抑制错误，或者您可以通过重复 **[选项 2：在 Microsoft Entra ID 中手动设置](#h_c5f095c9cf)** 中的管理员同意步骤来恢复权限。

### Teams 工具返回 403 “缺少范围” 错误

连接器的权限集现在包括 `Team.ReadBasic.All`，Claude 需要它来列出用户所属的团队。如果您的租户在添加此权限之前已同意，依赖它的 Teams 工具将返回 403 “缺少范围” 错误。要修复此问题，请让 Microsoft Entra 全局管理员重复 **[选项 1：通过 Claude 同意](#h_3617c79be6)** 或 **[选项 2：在 Microsoft Entra ID 中手动设置](#h_c5f095c9cf)** 中的管理员同意步骤。

**注意：**重复管理员同意会授予连接器的完整当前权限集，包括写入权限。如果您有意撤销任何写入权限，请之后再次撤销。

### 成员看不到写入工具

1. 确认 Microsoft Entra 管理员已同意包含写入范围的更新权限集。

2. 确认在 Microsoft 365 连接器配置中启用了写入工具，或成员被授予它们的基于角色的访问策略所覆盖。

3. 让成员在 **[自定义 > 连接器](https://claude.ai/customize/connectors)** 中断开并重新连接 Microsoft 365。

### Claude 找不到 SharePoint 搜索找到的文件

这仅在 SharePoint 自己的搜索找到文件而 Claude 没有找到时适用。当 Claude 搜索 SharePoint 和 OneDrive 文件时，它会向每个查询添加 `isDocument=true`，因此它只查找租户搜索索引标记为文档的文件。如果索引未标记某些文件，Claude 将找不到它们，并且不会显示错误。

要检查这是否是原因：

1. 以可以打开缺失文件的用户身份登录 Graph Explorer。如果系统要求，请同意 `Files.Read.All`。

2. 运行此搜索，将 `budget` 替换为缺失文件中的单词。选择很少其他文件包含的单词：

  1.

```
POST https://graph.microsoft.com/v1.0/search/query
{"requests":[{"entityTypes":["driveItem"],"query":{"queryString":"
(budget)"},"size":100,"sortProperties":
[{"name":"LastModifiedTime","isDescending":true}]}]}
```

3. 使用添加的文档筛选器再次运行它，使用相同的单词：

  1.

```
POST https://graph.microsoft.com/v1.0/search/query
{"requests":[{"entityTypes":["driveItem"],"query":{"queryString":"(budget) AND
isDocument=true"},"size":100,"sortProperties":
[{"name":"LastModifiedTime","isDescending":true}]}]}
```

4. 比较结果：

  1. 如果您期望的 Word、Excel、PowerPoint 或 PDF 文件仅出现在第一个搜索中，您的搜索索引未将其标记为文档。向 Microsoft 支持部门提交案例并共享两个搜索。

  2. 如果文件在两个搜索中都不出现，这不是原因。

### 条件访问阻止连接

条件访问阻止以三种方式之一显示：

- 用户在尝试连接时看到 “与 MCP 服务器的授权失败” 和以 `ofid_` 开头的参考代码。我们的支持团队可以查找该代码。

- 已连接的成员在 Claude 使用 Microsoft 365 工具时收到错误。错误包括 `AADSTS` 代码、请求被条件访问策略阻止的注意事项，以及您可以在 Entra 中搜索的跟踪 ID 和关联 ID。

- 成员被要求定期重新连接 Microsoft 365，频率远高于正常的 90 天过期周期。这通常意味着登录频率策略。

连接 Microsoft 365 涉及的不仅仅是成员看到的登录。成员在浏览器中登录 Microsoft 后，Claude 的服务器会交换该登录以获取访问令牌，稍后会交换这些令牌以代表成员获取 Microsoft 365 访问权限。在我们的测试中，Entra 根据这些服务器端请求评估您的条件访问策略，这些请求来自 Anthropic 的出站 IP 地址。它们识别成员并携带成员连接时记录的设备，而不是成员的当前设备或网络。因此，策略可以通过成员自己的登录，但仍会在稍后阻止连接，或在几天后阻止它。了解有关 **[Anthropic 的出站 IP 地址](https://platform.claude.com/docs/en/api/ip-addresses#outbound-ip-addresses)** 的更多信息

**查找阻止连接的策略**

1. 在 Microsoft Entra 管理中心，转到 **登录日志** 并打开 **用户登录（非交互式）** 选项卡。成员自己的登录出现在交互式选项卡上，通常显示为成功，因此阻止很少出现在那里。

2. 按受影响的成员进行筛选。被阻止的请求可以出现在 **Claude 的 M365 MCP 服务器** 或 **Claude 的 M365 MCP 客户端** 下，因此按成员筛选比按应用程序筛选更可靠。不要按资源筛选，这会隐藏某些行。

3. 打开失败的条目并选择 **条件访问** 选项卡。它命名阻止请求的策略。

错误代码告诉您策略的类型：

- `AADSTS70043`：登录频率策略。请参阅下一部分。

- `AADSTS53003`：设置为阻止访问的策略。条件访问选项卡告诉您是哪一个。如果它基于位置，请参阅下一部分。

- `AADSTS50076`：策略在服务器端请求上需要多因素身份验证。断开并重新连接 Microsoft 365 会清除它。如果它继续发生，请参阅 **[Microsoft 365 连接器安全指南](https://support.claude.com/en/articles/12684923-microsoft-365-connector-security-guide)**。

- `AADSTS53000`：策略需要兼容设备。类似代码 `AADSTS530003` 表示策略需要托管设备。在这两种情况下，成员都需要从满足策略的设备重新连接。在 **[Microsoft 365 连接器安全指南](https://support.claude.com/en/articles/12684923-microsoft-365-connector-security-guide)** 中了解更多信息。

**从登录频率和位置策略中排除 Anthropic 的 IP 范围**

由于服务器端请求来自 Anthropic 的 IP 范围，限制登录到您自己网络的策略或强制登录频率的策略会为每个成员阻止它们。仅从策略中排除两个 Claude 应用程序是不够的。我们建议也从策略中排除 Anthropic 的 IP 范围。

**注意：**不要将此排除项用于设备合规性策略。服务器端请求携带成员连接时记录的设备，因此设备策略仍适用于这些请求，排除 Anthropic 的 IP 范围会关闭连接器的设备检查。被设备策略阻止的成员需要从符合该策略的设备重新连接。详见 **[Microsoft 365 连接器安全指南](https://support.claude.com/en/articles/12684923-microsoft-365-connector-security-guide)**。

如果阻止请求的策略是登录频率或位置策略：

1. 在 Microsoft Entra 管理中心，转到 **条件访问 > 命名位置**并创建 IP 范围位置。从 Anthropic 的 **[出站 IP 地址](https://platform.claude.com/docs/en/api/ip-addresses#outbound-ip-addresses)**列表中完整添加每个当前 IPv4 范围。保持 **标记为受信任位置**未选中状态，以便排除项不会影响使用受信任位置的其他策略。如果 Anthropic 向该列表添加范围，也要将其添加到此位置。

2. 打开阻止请求的策略，转到 **条件 > 位置 > 排除**。

3. 添加您创建的命名位置。保持 Claude 应用程序的任何现有排除项不变。

4. 保存策略并等待几分钟以应用更改。

5. 让受影响的成员在 **自定义 > 连接器**中断开连接并重新连接 Microsoft 365。

**注意：**排除这些范围会对来自 Anthropic 地址的每个请求解除策略限制，这意味着所有成员的所有 Microsoft 365 连接器活动都不受限制。对于登录频率策略，这也意味着连接器的后台请求不再受其约束，因此连接在 90 天无活动后过期前保持登录状态。如果您希望保持定期重新连接，请保持策略不变。被要求重新连接的成员可以在浏览器中注销 Microsoft，或使用隐私浏览窗口，然后再重新连接。如果要在进行更改前检查其效果，请先以仅报告模式克隆该策略。

## 常见问题

### 如果成员在授予同意前尝试连接会发生什么？

他们会看到一条错误消息，指示管理员必须授予应用权限才能使用集成。在 Microsoft Entra 全局管理员批准必要权限之前，连接将失败。

### Microsoft 365 连接器可以与企业搜索一起使用吗？

可以。启用企业搜索后，它可以与其他连接的服务一起查询 Microsoft 365，实现跨 Slack、Google Workspace、Microsoft 365 等的统一搜索。

### 连接器可以读取哪些文件类型？

Claude 可以从 SharePoint 和 OneDrive 读取 Word、Excel、PowerPoint（包括较旧的 .doc、.xls 和 .ppt 文件）、PDF 和纯文本格式（如 .txt、.md 和 .csv）。其他格式（包括 OneNote）无法读取。完整列表见 **[连接到 Microsoft 365](https://support.claude.com/en/articles/15183774-connect-to-microsoft-365#h_ddeb82923f)**。

### 集成可以修改 Microsoft 365 数据吗？

仅在 Entra 管理员授予写入范围后才可以。启用写入工具后，Claude 可以发送电子邮件、管理草稿和日历事件、更新邮箱设置、在 OneDrive 和 SharePoint 中创建和更新文件，以及在 Microsoft Teams 中发送消息（在频道中发布/回复、发送聊天消息或代表用户启动新聊天），始终在每个成员现有的 Microsoft 365 权限范围内。没有这些权限，集成为只读。Claude 仍无法更改 Teams 设置或权限，只能发送消息。
