# 管理您组织的插件

插件市场让 Team 和 Enterprise 计划的所有者向其组织中的所有人分发精选插件。您可以创建市场、向其中添加插件，并精确控制团队成员可以看到和使用哪些插件。您分发的插件会出现在聊天中（网页版和 Claude Desktop 中的聊天标签页）、Claude Cowork 中，以及使用相同 Claude 账户登录的 Claude Code 会话中。

Team 和 Enterprise 计划的所有者和主要所有者可以在 **[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)** 中管理组织插件。在 Enterprise 计划中，具有包含管理组织库权限的自定义角色的成员也可以。

**要求：**在使用插件市场之前，必须为您的组织启用 Cowork 和技能。

有关这些控制的参考版本，请参阅 Claude Code 文档中的 **[管理您组织的插件](https://code.claude.com/docs/en/plugins/org)**。

**注意：**关闭您组织的技能也会停止技能和插件同步到 Claude Code，并删除已同步的插件。关闭 Cowork 不会影响到 Claude Code 的同步。要在 Claude 中保留技能和插件但仅停止同步，请在 Claude Code 托管设置中将 `syncClaudeAiSkills` 和 `syncClaudeAiPlugins` 设置为 `false`。详细了解 **[Claude Code 管理员设置](https://code.claude.com/docs/en/setup#advanced-setup)**。

**注意：**市场是所有者向其组织分发插件的方式。用户也可以与特定同事或群组共享他们构建的插件，或将其提交以发布到您组织的库。共享和发布由 **[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)** 中 “策略” 标签页的设置控制，插件提交在 “请求” 标签页进行审核。详细了解 **[在 Claude 中使用插件](https://support.claude.com/en/articles/13837440-use-plugins-in-claude)** 和 **[让用户发布技能和插件到您的组织](https://support.claude.com/en/articles/13119606-provision-and-manage-skills-for-your-organization#h_1abc45a27c)**[。](https://support.claude.com/en/articles/13119606-provision-and-manage-skills-for-your-organization#h_1abc45a27c)

## 查看您组织中的内容

“库存” 标签页列出您的组织管理的每项技能和插件，包括用户为自己创建的插件。技能和插件现在位于同一页面上，因此您无需在设置之间切换。

对于每个项目，表格显示其来源、版本、功能、受众以及过去 30 天内有多少人使用过它。

要查找项目，请按名称搜索或使用过滤器：

- **来源：**您的组织、组织库或特定市场

- **受众：**谁可以使用该项目

- **类型：**技能或插件

您的组织管理的技能显示在 **组织库** 下。您在 **市场** 标签页中管理插件市场。

要对项目进行操作，请单击其行末尾的菜单按钮。您可以查看详细信息和文件、查看版本历史记录以及更改默认访问权限和群组访问权限。

对于用户创建的技能和插件，库存标签页显示元数据和共享状态。它不显示文件本身。

## 使用 Anthropic 构建的市场

Anthropic 提供针对不同功能（如法律和财务）的内置插件市场。默认情况下，知识工作市场会添加到您的组织。

要添加 Anthropic 构建的市场：

1. 转到 **[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)** 并单击 “市场” 标签页。

2. 单击 “添加，” 然后选择 “添加市场。”

3. 选择 “浏览 Anthropic 来源。”

4. 单击 “添加” 以添加您希望为组织中的每个人显示的市场。

如果知识工作市场与您的团队无关，请将其删除：

1. 转到 **[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)** 并单击 “市场” 标签页。

2. 找到 **知识工作**。

3. 单击右上角的菜单按钮。

4. 选择 “删除。”

Anthropic 构建的市场显示可读名称，如 “知识工作，” 而不是底层存储库 slug。

## 创建您自己的市场

除了 Anthropic 构建的市场外，您还可以创建自己的市场。有两种方法可以向您创建的市场添加插件：

- **手动上传：**通过管理员 UI 上传单个插件 ZIP 文件。最适合快速迭代、一次性工具或不在 Git 存储库中保存插件的团队。

- **存储库同步：**连接私有 GitHub 或 GitLab 存储库，Claude 从中同步插件。最适合多个开发人员协作开发插件或您需要版本控制更新的情况。

您可以并行使用两种方法。例如，为核心插件运行 GitHub 同步市场，为临时工具运行单独的手动市场。

### 设置手动市场

1. 转到 **[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**。

2. 单击 “添加，” 然后选择 “上传插件。”

3. 如果这是您第一次设置市场，“上传到新市场” 会自动选中。稍后上传插件时，您将能够选择 “添加到现有市场。”

4. 输入市场的名称。

5. 将文件拖入，或单击上传提示并选择您的文件。文件必须是有效的 .zip 文件，大小不超过 200 MB。

6. 对要添加的每个插件重复此操作。

7. 单击 “上传” 将您的插件添加到新市场。

如果您上传的插件与现有插件同名，它会自动覆盖之前的版本。您无需先删除旧版本。

### 设置 GitHub 同步市场

GitHub 同步让您可以在存储库中将插件作为代码进行管理。推送更改时，您可以触发同步以更新市场，可以手动或自动进行。

**准备您的存储库**

您可以连接托管在 github.com 或您组织的 GitHub Enterprise 主机上的存储库。在 github.com 上，您的存储库必须是 **私有或内部**——组织市场不允许公开存储库。要从 GitLab 同步，请参阅 **[设置 GitLab 同步市场](#h_6be3dfbfbc)**。

GitHub 同步市场在 `marketplace.json` 中支持的 `source` 类型集比 Claude Code 更窄。相对路径指向市场存储库内的插件文件夹（例如，`"source": "./plugins/my-plugin"`）完全受支持，是最简单的选项。还支持 `github`、`url` 和 `git-subdir` 源类型。不支持 `npm`、`archive` 和 `command` 源类型。

插件源在三种情况下可以是私有的：

- 一个 github.com 源，共享您的市场仓库的所有者，组织同步通过 Claude GitHub App 获取。

- 您的组织 GitHub Enterprise 主机上的源，已在该仓库上安装了您的组织 GitHub Enterprise App。

- 与您的市场仓库位于同一 GitLab 主机上的 url 或 git-subdir 源。在 gitlab.com 上，该源还必须位于与市场仓库相同的顶级组或用户命名空间下。

所有其他源都在没有凭证的情况下获取，因此必须是 github.com、gitlab.com 或 bitbucket.org 上的公共仓库。任何其他主机上的源都会被拒绝。

如果您的插件代码位于不符合上述条件的私有仓库中，请将这些插件文件夹复制到市场仓库中，并将每个插件的源更改为相对路径（git 子树或供应文件的 CI 步骤效果很好）。

有关插件结构和格式的详细信息，请参阅**[插件清单参考](https://code.claude.com/docs/en/plugins/manifest-reference)**。

其他资源：

- **[创建市场](https://code.claude.com/docs/en/plugins/create-marketplace)**

- **[创建插件](https://code.claude.com/docs/en/plugins/create)**

- **[创建新的 GitHub 仓库](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)**

**连接仓库**

1. 确保为您的组织启用了 Cowork 和 Skills。

  1. **[启用 Cowork](https://support.claude.com/en/articles/13455879-use-cowork-on-team-and-enterprise-plans#h_71cdc52dfc)**

  2. **[启用 Skills](https://support.claude.com/en/articles/13119606-provision-and-manage-skills-for-your-organization#h_7673241237)**

2. 转到**[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**，然后点击“市场”标签。

3. 点击“添加插件”，然后选择“从 GitHub 同步”。

4. 以 `owner/repo` 格式输入仓库（例如 `acme-corp/claude-plugins`）。

您的个人 GitHub 令牌已验证以确认您有访问权限，然后 Cowork 使用其 GitHub App 安装令牌进行同步操作。

**看不到您的仓库？**确保 Claude GitHub App 已安装在该仓库中。

**同步工作原理**

连接仓库时会自动运行初始同步。在 GitHub 创建流程中，您也可以关闭“自动同步”（默认为开启）。启用后，当拉取请求合并到市场跟踪的分支或有人直接推送到该分支时，会运行同步。

打开或关闭自动同步的人必须在 GitHub 上对该仓库具有管理员级别的访问权限。这通过其个人 GitHub 连接进行检查，该连接与 Claude GitHub App 安装分开。没有管理员访问权限时，页面会显示“无法访问仓库。确保仓库存在且已安装 Claude GitHub App”，即使 App 安装正确且手动更新有效。

Claude GitHub App 的**Webhooks（读写）**权限也必须在安装中获得批准。在引入此权限之前创建的安装中，GitHub 会显示“Claude 正在请求更新的权限”提示，需要仓库或组织管理员批准。

启用后，GitHub 仓库的自动同步在包含插件版本更新的拉取请求合并到仓库的默认分支时运行。直接推送到默认分支不会触发同步。您可以随时通过点击市场上的“重新同步”手动触发同步。

同步期间，Cowork 将您仓库中的最新提交与上次同步的提交进行比较。如果没有任何更改，则跳过同步。如果有更改，Cowork 会读取清单、验证每个插件，并用仓库的当前状态替换市场中的所有插件。同步可能需要长达 30 分钟，具体取决于插件数量。

**重要：**如果同步失败，成员会保留每个插件的上次同步版本。检查失败消息，修复仓库，然后重新同步。

### 设置 GitLab 同步的市场

您可以从 gitlab.com 或自管理 GitLab 实例上的仓库同步组织市场。有关支持的插件源类型和哪些源可以是私有的，请参阅上面的**准备您的仓库**。

GitLab 支持处于测试阶段，仅适用于插件市场同步。Claude Code 云会话尚不支持 GitLab 仓库。

**开始前**

- **角色。**您需要所有者或主要所有者角色才能添加 GitLab 配置。

- **项目可见性。**在 gitlab.com 上，市场项目必须是私有或内部的。在自管理实例上，任何可见性都可以。

- **访问令牌。**为 Claude 创建 GitLab 访问令牌以读取市场项目和同一主机上的任何插件源项目。个人、组和项目访问令牌都可以。令牌的用户需要在这些项目上至少具有报告者角色。

  - 旧版（作用域）令牌：至少 `read_api` 作用域。

  - 细粒度个人访问令牌：项目：读取、分支：读取和仓库：读取权限。

  - 可选，用于自动 webhook 设置（第 3 步）：市场项目上的维护者角色加上 `api` 作用域（旧版）或 Webhook：创建和删除权限（细粒度）。没有这些，您需要手动添加一次 webhook（第 4 步）。

- **仅限自管理实例。**

  - 实例的主机名必须解析为公共 IP 地址，且实例必须接受来自**[Anthropic 出站 IP 地址](https://platform.claude.com/docs/en/api/ip-addresses#outbound-ip-addresses)**的 HTTPS 连接。

  - 如果私有证书颁发机构颁发了其 TLS 证书，请准备好 CA 证书 (PEM)。

  - 自动同步的 webhook 交付来自您的实例到 api.anthropic.com，因此实例必须能够向该主机发出出站 HTTPS 请求。

**第 1 步：添加 GitLab 配置**

要添加 GitLab 配置：

1. 转到**[组织设置 > Claude Code](https://claude.ai/admin-settings/claude-code)**。

2. 在**自托管基础设施**下，找到 **GitLab** 并点击“添加配置”。

3. 输入显示名称、主机名（gitlab.com 或您的实例主机名，如 gitlab.example.com）、访问令牌，以及对于具有私有 CA 的自管理实例，输入 CA 证书。

4. 点击“添加配置”。Claude 立即运行连接测试并在 **GitLab 连接测试**对话框中显示结果。

5. （可选）要检查令牌是否可以读取您的市场项目，请在**项目路径**下输入其路径（例如 `platform/claude-plugins`）并点击“测试同步访问”。

您可以随时从配置的菜单中使用**测试连接**重新运行测试。主机名之后无法更改。如果更改，请删除配置并添加新配置。

**第 2 步：添加市场**

要添加市场：

1. 转到**[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**，然后点击“市场”标签页。

2. 点击“添加”，然后选择“从 GitLab 同步”。

3. 在**GitLab 仓库 URL** 中，输入项目的 HTTPS URL，例如 `https://gitlab.example.com/platform/claude-plugins`。嵌套子组中的项目也可以使用。

4. 如果希望推送触发同步，请保持**自动同步**开启（参见**第 3 步**）。

5. 为市场包含的插件选择**默认访问权限**。

6. 点击“创建”。

Claude 会读取项目的默认分支并验证市场文件，然后创建以项目路径命名的市场。

**第 3 步：自动同步**

启用**自动同步**后，每次推送到项目的默认分支都会通过 GitLab 项目上的 webhook 触发同步。如果您的令牌可以管理 webhook（参见**开始前**），Claude 会为您创建 webhook，无需其他操作。

您可以稍后从市场菜单中打开或关闭**自动同步**。打开它会以相同方式设置 webhook。

**第 4 步：如果 Claude 无法创建 webhook**

如果令牌无法管理 webhook，Claude 会在屏幕上显示**在 GitLab 中完成 webhook 设置**消息，其中包含**Webhook URL** 和令牌。令牌仅显示一次，请在关闭消息前完成此步骤。

1. 在您的 GitLab 项目中，打开**设置 > Webhook** 并使用消息中的 URL 添加新的 webhook。

2. 将令牌粘贴到字段中。

  1. 如果消息显示**密钥令牌**，请将其粘贴到 GitLab 的

  2. 如果消息显示**签名令牌**（gitlab.com 和自管版本 19.1 或更高版本），请在 GitLab 中选择“生成签名令牌”，并将生成的值替换为 Claude 中的值。

3. 启用**推送事件**并保存。

4. （可选）在 GitLab 中的新 webhook 上使用**测试 > 推送事件**，并确认它报告 HTTP 200。

如果丢失令牌，请从市场菜单中打开**配置 webhook**，点击“移除 webhook”，然后点击“启用 webhook”以获取新令牌。旧令牌将停止工作。

### 在手动上传和仓库同步之间选择

| **场景**                   | **推荐方法**           |
| ------------------------ | ------------------ |
| 插件在版本控制中维护，配有 CI/CD      | GitHub 或 GitLab 同步 |
| 多个开发者协作开发插件              | GitHub 或 GitLab 同步 |
| 您希望自动传播更新                | GitHub 或 GitLab 同步 |
| 快速原型设计或一次性工具             | 手动上传               |
| 由非工程团队构建的插件              | 手动上传               |
| 无法访问 GitHub 或 GitLab 的环境 | 手动上传               |
| 在将插件添加到同步仓库前进行测试         | 手动上传               |

## 控制插件分发

市场包含插件后，您可以使用安装偏好设置控制它们的分发方式。对于每个插件，您可以设置以下四个选项之一：

| **偏好设置** | **功能**              | **成员看到的内容**                                                                            |
| -------- | ------------------- | -------------------------------------------------------------------------------------- |
| 默认安装     | 为所有组织成员预安装插件        | 插件出现在他们的列表中，无需任何操作。成员可以选择关闭它。                                                          |
| 可供安装     | 在**发现**标签页上列出       | 用户在**发现**标签页上看到它，可以自行添加。                                                               |
| 不可用      | 完全隐藏                | 用户无法看到或添加插件。适用于暂存或弃用插件。                                                                |
| 必需       | 为所有组织成员预安装插件，无法选择移除 | 该插件会在他们的列表中显示，无需任何操作，标记为“此插件是您的组织所需的。”用户无法关闭或移除它。在同步成员账户插件的 Claude Code 会话中，它也会保持启用状态。 |

**重要提示：**设置为“默认安装”或“必需”的插件也会在 Claude Code 中为使用 Claude 账户登录的用户安装。在 Claude Code 中，插件的钩子、子代理和 MCP 服务器在用户的计算机上运行，“必需”插件无法在那里禁用。在将插件设置为“必需”之前，请查看插件的钩子。在 Claude Code 文档中了解更多关于**[同步插件](https://code.claude.com/docs/en/plugins-reference#synced-plugins)**的信息。

### 设置偏好设置

1. 在**[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**中，点击“库存”标签页。

2. 找到该插件，点击其行末尾的菜单按钮。

3. 点击“默认访问权限，”然后在**安装**下选择一个选项。

4. 更改将在每个成员的下一个会话或插件刷新时生效。

### 成员体验

成员在**自定义 > 插件**中的**发现**标签页上浏览可用插件。您设置为“默认安装”或“必需”的插件会自动显示在他们的列表中。您设置为“可供安装”的插件会在**发现**上显示，供成员自行添加。

成员无法编辑组织管理的插件，这可以防止对共享工具进行冲突的更改。

## 按组自定义插件访问权限

企业管理员可以为特定组覆盖插件的组织范围安装偏好设置。例如，您可以为工程组自动安装插件，让法律部门可以自行安装，并将其隐藏在其他所有人面前。

组级插件访问权限在企业计划中可用。您可以在同一**组织设置 > 插件和技能**页面上设置它，这需要所有者或包含管理组织库的自定义角色。

### 组覆盖的工作原理

您的市场中的每个插件都有一个组织范围的安装偏好设置（默认安装、可供安装、必需或不可用）。默认情况下，每个组都继承该组织范围的设置。

当您为插件设置组级覆盖时，它会替换该组成员的组织范围设置。解析顺序为：组设置，然后是组织范围设置，然后是市场默认设置。

### 为组设置插件访问权限

1. 在**[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**中，点击“库存”标签页。

2. 找到您想要自定义的插件，点击其行末尾的菜单按钮。

3. 点击“组访问权限…”。

4. 在**安装目标**旁边点击“添加组”。

5. 选择组并选择上面列出的安装偏好设置之一。

手动创建的组和来自您的身份提供商的 SCIM 预配组都会显示在组选择器中，工作方式相同。

### 当成员属于多个组时会发生什么

如果成员属于两个或多个对同一插件有不同设置的组，则应用**最宽松的**设置。从最宽松到最严格的顺序是：必需 > 默认安装 > 可供安装 > 不可用。

例如，如果 A 组将插件设置为“不可用”，B 组将其设置为“默认安装，”则同时属于两个组的成员会默认安装该插件。

**注意：**这与组支出限制的解析方式不同。支出限制根据您的**多组支出限制**设置应用较高或较低的组值。插件访问应用最宽松的值，因为这里的组旨在为需要工具的团队启用访问权限，而不是充当安全边界。如果您需要硬性阻止插件，请将其组织范围偏好设置为“不可用”，仅向应该有权访问的组授予访问权限。

### 删除组时会发生什么

如果删除组（例如，从您的身份提供商中删除），覆盖仍会保留在管理 UI 中，但被标记为孤立。它对成员没有影响（因为没有人属于已删除的组），也不计入自定义访问徽章。您可以从插件的“组访问权限…”设置中清除孤立的覆盖。

### 组设置在市场重新同步后是否保持不变？

是的。当您重新同步 GitHub 或 GitLab 连接的市场时，组级覆盖会保持不变。仅当插件本身从市场中删除时，它们才会被移除。

## 限制用户可以添加的市场

所有者或主要所有者可以使用允许列表、阻止列表或两者来限制您的组织中的人员可以添加哪些插件市场。您可以在 Claude Code 托管设置中设置这些列表，但它们也适用于 Claude 和 Claude Cowork。

要设置允许列表或阻止列表：

1. 转到**[组织设置 > Claude Code](https://claude.ai/admin-settings/claude-code)**。

2. 找到**托管设置**。

3. 点击“管理。”

4. 将 strictKnownMarketplaces（允许列表）、blockedMarketplaces（阻止列表）或两者添加到 JSON。

5. 点击“添加设置”或“更新设置。”

输入您的 GitHub 组织名称，完全按照 GitHub 显示的方式，因为允许列表匹配区分大小写。如果源同时在两个列表中，则会被阻止。

设置列表后，每当您的组织中的某人在 Claude、Claude Desktop 或 Cowork 中从 Git 存储库添加市场时，Claude 都会检查这些列表。这涵盖用户在自定义中为自己添加的市场以及在**组织设置 > 插件和技能**中为整个组织添加的市场。Claude 拒绝列表不允许的任何存储库，除了 Anthropic 构建的市场。

请记住：

- 在组织设置中设置列表。部署到计算机的 managed-settings.json 文件或 MDM 策略仅适用于这些计算机上的 Claude Code。

- 现有市场不会被重新检查。在您设置列表之前添加的市场会保留，直到有人移除它们。

- 上传的插件不会被检查。要阻止用户上传插件文件，请在**[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**的“策略”标签页中关闭**用户创建的技能**。

有关列表接受的每种源类型，请参阅 Claude Code 文档中的**[限制用户可以安装的内容](https://code.claude.com/docs/en/plugins/org#restrict-what-users-can-install)**。

## 更新和移除插件

### 手动市场

要更新插件，请上传一个与现有插件同名的新 ZIP 文件。新版本会自动覆盖现有版本。插件名称是唯一标识符，因此 `legal` 将始终替换 `legal`。

要删除插件，请在**[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**中的“库存”标签页中删除它。

### GitHub 同步的市场

将更改推送到连接的存储库，然后转到**[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**，点击“市场”标签页，找到您的市场，然后点击“更新”以触发同步。每次同步都会用存储库的当前状态替换所有插件。如果所有者为市场启用了“自动同步”，当包含插件版本更新的拉取请求合并到存储库的默认分支时，也会运行同步。

对于 GitLab 同步的市场，请参阅**[设置 GitLab 同步的市场](#h_6be3dfbfbc)**。

要删除插件，请从存储库中删除它并触发同步。

## 命名规则

插件名称必须使用**由连字符分隔的小写单词**（例如 `deployment-tools`，而不是 `Deployment Tools`）。以下市场名称是保留的，不能使用：

- `claude-code-marketplace`

- `claude-code-plugins`

- `claude-plugins-official`

- `anthropic-marketplace`

- `anthropic-plugins`

- `agent-skills`

- `life-sciences`

冒充官方 Anthropic 市场的名称也被阻止。

**注意：**插件作者可以设置 `displayName`，以便插件在目录中显示可读的名称而不是其 slug。如果作者未设置，插件将显示其 slug（例如 `deployment-tools`）。

## 故障排除

### 上传被拒绝

常见原因：文件超过 200 MB、不是有效的 ZIP 文件，或市场已达到 1000 个插件的限制。检查文件大小和格式，如果已达到容量，请删除未使用的插件。如果启用了技能和插件扫描，插件也可能因被标记为恶意内容而被拒绝。查看原因，修复问题，然后重新上传插件。

### 插件未为成员显示

检查市场设置中插件的安装偏好。如果设置为**不可用**，成员将看不到它。还要确认为您的组织启用了 Cowork 和技能。

### 更新的插件未为成员反映

更改在每个成员的下一个会话或插件刷新时生效。在 Claude Code 中，用户在下次启动 Claude Code 时会获得更改。如果更新仍未显示，请通过检查市场中的插件版本来确认上传成功。

### GitHub 同步因内容错误而失败

您的存储库中的一个或多个插件的格式可能不正确。修复格式问题，将更新推送到 GitHub，然后再次触发同步。有关插件结构要求，请参阅**[插件清单参考](https://code.claude.com/docs/en/plugins/manifest-reference)**。

### 同步失败，显示“不支持外部插件源类型。支持的类型：git-subdir、github、url”或插件被跳过，显示“在 gitlab.com 上找不到存储库。检查 URL 并确保存储库是公开的。”

`marketplace.json` 中的一个或多个插件条目使用指向连接的存储库外部的 `source`（`github`、`url` 或 `git-subdir` 源），组织同步无法获取它。私有源仅在三种情况下有效：github.com 存储库与您的市场存储库共享所有者、您的组织的 GitHub Enterprise 主机上的存储库且已安装 GitHub Enterprise App，或与您的市场存储库位于同一 GitLab 主机上的 url 或 git-subdir 源（在 gitlab.com 上，也在同一顶级组或用户命名空间下）。

对于任何其他私有源，将插件文件夹移动到marketplace存储库中，并将每个条目的`source`更改为相对路径（例如，`"./plugins/my-plugin"`），然后推送并重新同步。或者，通过**[组织设置 > 插件和技能](https://claude.ai/admin-settings/skills)**单独上传受影响的插件。点击“添加”、“上传插件”，然后选择“添加到现有marketplace”。通过成员自己的自定义菜单上传的插件仅为该成员安装，不会分发到您的组织，但如果启用了共享，成员可以与特定同事或群组共享插件。

### 连接时看不到GitHub存储库

确保Claude GitHub应用已安装在该存储库中。首先检查您的个人GitHub令牌以确认访问权限，但同步本身使用GitHub应用安装令牌。

### 打开“自动同步”时出现“无法访问存储库”

如果手动更新有效，但打开“自动同步”显示“无法访问存储库。确保存储库存在且已安装Claude GitHub应用”，可能有两个原因：

- **您没有对存储库的管理员访问权限。**打开自动同步会创建一个webhook，这需要通过您的个人GitHub连接对存储库进行管理员级别的访问。请要求存储库管理员启用该切换，或升级您的GitHub访问权限。

- **Claude GitHub应用的Webhooks权限尚未获得批准。**在较旧的安装中，GitHub会显示“Claude正在请求更新的权限”提示。存储库或组织管理员需要批准安装上的**Webhooks（读取和写入）**权限。

### “您的组织尚未配置GitLab实例。在Claude Code设置中添加一个，然后在添加marketplace时返回此处”

如果在GitLab中添加marketplace时看到此消息，请确保您已先添加GitLab配置。请参阅**[设置GitLab同步的marketplace](#h_6be3dfbfbc)**下的**步骤1：添加GitLab配置**。

### “此URL不在已配置的GitLab实例上”

确保URL的主机名与已配置的GitLab主机名完全匹配。

### 添加gitlab.com项目失败，显示“无法创建marketplace。请重试。”

检查项目的可见性是否为私有或内部。公共gitlab.com项目不能用作组织marketplace。

### 连接测试在到达主机时失败（例如“无法解析主机名”、“连接被拒绝”或“GitLab未及时响应”），或在自管理实例上添加marketplace失败并显示通用错误

确认该实例可从公网通过HTTPS访问，且Anthropic的出站IP地址允许通过您的防火墙。“无法建立安全连接”通常表示CA证书丢失或错误。

### 以“认证到…失败”或“访问被拒绝”开头的错误

令牌已过期、被撤销或缺少**[设置GitLab同步的marketplace](#h_6be3dfbfbc)**下**开始前**部分中列出的范围或角色。创建新令牌并将其粘贴到配置中（**编辑 > 访问令牌**）。
