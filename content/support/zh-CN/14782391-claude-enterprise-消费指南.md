# Claude Enterprise 消费指南

Claude Enterprise 为您的组织提供强大的 AI 访问权限，涵盖聊天、Claude Code、Claude Cowork、Claude Design 以及您的团队已在使用的工具中的 Claude，包括 Microsoft 365、Chrome 和 Slack。随之而来的是有效管理消费的责任——确保您的团队获得最大价值，同时保持使用情况可预测且在预算范围内。

本指南将引导 Enterprise 管理员了解可用于控制和优化令牌消费的关键手段：设置支出上限、配置基于角色的访问控制、用户教育、为正确的任务选择合适的模型和工作量级别，以及衡量您的支出产生的价值。

---

## 为什么消费管理很重要

Claude Enterprise 采用按座位、基于使用情况的定价模式。您组织的消费池在所有用户之间共享，某些界面（特别是 Claude Code 和 Cowork）的令牌消费速率明显高于标准聊天。

主动配置支出限制并对用户进行教育的管理员可以减少浪费，并确保高价值用例获得所需的容量。

## 了解各界面的令牌强度

| **界面**        | **令牌强度及其驱动因素**                                   |
| ------------- | ------------------------------------------------ |
| 核心聊天          | 强度较低。标准的来回对话、摘要、起草和问答。令牌使用量随消息长度和对话历史记录而变化。      |
| Claude Code   | 强度较高。每个编码会话包括系统提示、文件上下文、工具调用和多轮推理——每个会话的令牌数比聊天多。 |
| Claude Cowork | 强度较高。代理工作流、多步骤任务执行和技能生成大量中间令牌使用，最终用户可能看不到。       |

其他界面也会占用您组织的使用量，并在分析、支出导出和分析 API 中显示为单独的产品：(a) Claude for M365（Excel、PowerPoint、Word、Outlook 加载项），受相同的组织、群组和按用户支出限制以及模型限制；(b) Claude Design（测试版），按标准 API 费率从您组织的消费中计费，应用组织、群组和按用户限制；(c) Chrome 中的 Claude，其侧面板作为 Claude Cowork 会话运行，因此多步骤浏览任务的消费方式与其他 Cowork 代理工作相同（在组织设置 > Cowork 下管理）；(d) Claude Tag（Slack 中的 Claude，测试版），其频道工作计费到组织的使用余额而不是单个座位，因此按用户和群组限制不会限制它；在 **[claude.ai/admin-settings/usage/claude-tag](https://claude.ai/admin-settings/usage/claude-tag)** 设置 Claude Tag 支出限制（以及可选的按频道限制）。与 Claude Tag 的直接消息计费到发送者自己的座位。

**管理员提示：与您的团队设定期望**

运行 Claude Code 或 Cowork 工作流的用户可能没有意识到他们的会话有多么令牌密集。单个 Cowork 任务或 Claude Code 调试会话可能消耗比聊天多得多的令牌。在您发送的任何用户入职信息中包含此背景。

## 基于角色的访问控制

基于角色的访问控制 (RBAC) 让您可以将用户分组，并作为一个整体而不是逐个管理他们对 Claude 界面和消费预算的访问。这是在较大组织中管理使用情况的最可扩展方式。

### 如何构建群组

根据工作职能和用例而不是组织层级来考虑群组。以下是一些原则：

- 创建映射到不同使用模式的群组，而不是组织结构框。“工程”和“销售”比“北美”和“欧中东非”对消费管理更有用。职能群组也使智能报告更有用，因为限定于团队的报告会产生足够具体的发现以便采取行动。

- 限制群组数量增长。超过 8-10 个群组会变得难以管理。从 4-6 个开始，仅在使用模式明显不同时才拆分。

- 使用群组来限制对高强度界面的访问。例如：只有“工程”群组的成员可以访问 Claude Code；其他用户只能看到聊天和 Cowork。访问权限由您分配给每个群组的自定义角色授予，仅对组织角色设置为自定义的成员生效。保留在内置用户角色上的成员在组织范围内保持所有功能启用。群组可以手动创建或从您的身份提供商同步。请参阅 **[在 Enterprise 计划上设置基于角色的权限](https://support.claude.com/en/articles/13930458-set-up-role-based-permissions-on-enterprise-plans)**。

- 首先分配群组级支出上限，然后在用户级别为异常值覆盖（例如，需要 Claude Code 进行特定项目的非技术产品经理）。

### 群组支出管理

配置群组后：

- 在初始推出期间每周审查群组消费，之后每月审查一次。

- 当群组持续接近其限制时（请参阅使用情况页面上的“达到限制的时间”），在自动提高限制之前进行调查。限定于该群组的智能报告显示支出产生的价值，或者您可以向该群组发送简短调查以直接询问。正确的响应可能是较低的工作量上限或更清晰的模型指导。如果报告显示高价值工作，请提高限制，因为达到限制的成员通常是您的顶级采用者。

- 考虑在每个部门分配一个“群组所有者”，负责审查使用情况并回答团队的问题。这分散了管理负担，并让具有业务背景的人参与其中。您不需要让这些人成为所有者或管理员：创建一个授予分析（可查看）管理员权限的自定义角色——以及可选的计费（可查看）以便他们可以看到使用情况页面——并将其分配给一个小的“使用情况审查者”群组。管理员权限仅适用于角色设置为自定义的成员，分析查看访问权限是组织范围的，而不是限制在他们的群组。

- 要让群组所有者只查看他们的团队，您可以让他们运行限定于其群组的智能报告。请参阅 **[让团队成员为特定群组运行智能报告](https://support.claude.com/en/articles/16948886-let-team-members-run-smart-reports-for-specific-groups)**。

**治理提示：将界面访问作为第一道关卡**

在担心令牌级限制之前，请确保合适的人员可以访问合适的界面。在第一天就给所有人 Claude Code 和 Cowork 访问权限是生成意外消费的最快方式。分阶段推出高强度界面，从最可能高效使用它们的团队开始。

## 设置支出限制

支出限制是您控制消费的主要工具。Claude Enterprise 允许管理员在三个级别设置限制：组织级别、群组级别（使用 RBAC）和单个用户级别，加上可选的池化预算，为群组提供一个共享的月度金额。**我们推荐的方法是从 RBAC 群组级限制和按用户限制开始**——这些提供精确、有针对性的控制，而不会因为达到限制而切断整个组织的风险。

### 组织级支出限制

组织级限制可用作所有用户和界面的硬性上限，但要谨慎使用：达到它会同时影响所有人，这可能会造成中断。大多数管理员发现在群组和用户级别管理消费会产生更好的结果，运营风险更低。

### 群组支出限制

群组支出限制让您可以为整个群组分配按用户月度支出限制，因此该群组的每个成员都继承相同的限制，无需单独设置。这是在中型到大型组织中管理消费的最可扩展方式，也是管理员应该开始的地方。

请注意以下优先级规则：

- **个人限制始终覆盖群组限制**，无论哪个更高。

- **如果用户属于多个具有不同限制的群组**，**支出默认值**下的**多群组支出限制**设置控制应用更高还是更低的限制。座位类型默认限制包含在此比较中。

- **组织范围的限制仍然是硬性上限。**

- **任何地方都没有限制 = 没有限制。**如果成员没有个人限制，其群组也没有限制，则其支出不受限制。

**如何配置：**组织设置 → 使用情况 → 按群组/层级。将限制设置为特定美元金额或“无限制。”

### 池化群组预算

群组支出上限为每个成员提供相同的个人限制。池化预算为整个群组提供一个共享的月度金额，每个成员都从中提取。当团队有固定预算但成员之间使用情况不均匀时使用。

每个请求都计入成员自己的月度限制和群组池。当成员自己的限制用完或他们可以使用的每个池化预算都用完时，成员停止。使用情况可能在限制暂停之前略微超过限制。将按成员限制设置为护栏，而不是池的相等份额。**当池用完时，没有其他可用池化预算的群组成员的使用情况暂停**，直到管理员提高池或在下个月重置。计费管理员在池的 50%、75%、95% 和 100% 处收到电子邮件警报。

如果成员属于多个池化群组，首先使用最大的池。您可以在**池化预算优先级**下设置自定义顺序。

**配置方法：****组织设置 > 使用情况 > 支出限额 > 按组/层级**。打开组的菜单，选择“编辑限额，”然后设置**月度汇总预算**。**成员月度限额**是可选的。如果组还没有支出限额，请点击同一标签页上的添加按钮，在添加组时设置汇总预算。所有者、主所有者、账单角色以及具有账单（可管理）权限的自定义角色可以设置池。账单权限适用于整个组织，因此任何可以编辑一个组池的人都可以编辑每个组的池。池目前还不能通过管理员 API 使用。请参阅**[在企业计划中管理汇总组预算](https://support.claude.com/en/articles/17005973-manage-pooled-group-budgets-on-enterprise-plans)**。

### 用户级支出上限

用户级上限让您为个人账户设置消费限额。这对于使用情况在不同角色间差异很大的组织至关重要——每天使用 Claude Code 的开发人员的需求与使用聊天进行文案撰写的营销人员的需求完全不同。

**用户级上限的最佳实践：**

- 在推出前根据角色类型定义消费层级。分层结构（例如轻量级、标准、高级）使得一致地分配和调整上限更容易。

- 保守开始。根据用户的请求增加上限比处理超额对话要容易得多。

- 为高级用户（工程师、数据科学家、研究人员）提供更高或无上限的个人限额，但通过确保他们为正确的任务使用正确的 Claude 模型来抵消这一点。

- 每月在“使用情况”页面检查“达到限额的时间”，以查看成员达到限额的频率。还要注意消费很少的用户，他们可能还未激活。

## 模型选择指南

管理员可以做的最有影响力的事情之一是为用户设置清晰的指导，说明哪个模型用于哪些任务。模型选择对支出有直接且重大的影响。

努力级别是第二个消费杠杆。用户可以选择 Claude 对每个响应应用多少思考，更高的努力级别比更低的级别消耗更多令牌。鼓励用户仅为最具挑战性的任务保留最大努力，并为日常任务使用较低的努力。

### 正确任务的正确模型

| **模型**        | **最适合**                        | **令牌强度** | **推荐用途**                          |
| ------------- | ------------------------------ | -------- | --------------------------------- |
| Claude Fable  | 最困难、开放式的工作：深度研究、复杂分析和长期运行的代理工作 | 非常高      | 我们最先进的通用模型，用于您最困难和最高价值的工作。        |
| Claude Opus   | 复杂推理、研究、写作、分析、编码和多步骤任务         | 高        | 大多数角色的强大默认选择，以及复杂的多步骤工作           |
| Claude Sonnet | 日常任务、写作、分析、问答                  | 中等       | 轻量级日常任务的快速选项，或进行高容量、更简单工作的组的默认选择。 |
| Claude Haiku  | 简单查询、摘要、快速响应                   | 低        | 高容量、轻量级自动化任务                      |

### 设置您的组织默认模型

除了指导用户选择正确的模型外，您还可以设置组织中每个人的新对话开始使用的模型。这是最直接的消费杠杆之一——默认值决定了大多数用户每天运行的内容。

您有两个选项：

- **Anthropic 推荐**——随着新模型的发布自动更新，因此您的组织始终在我们当前推荐的每个产品模型上开始，无需手动维护。目前，聊天和统一 Claude 体验中是 Sonnet，Claude Code 和 Claude Cowork 中是 Opus。

- **选择您自己的**——将特定模型设置为组织默认值，并将其保持在那里直到您更改它。当您想要标准化为已知模型以实现消费可预测性时使用此选项（例如，默认为 Opus 并为进行最困难工作的角色提供 Fable）。

此设置适用于聊天、Claude Cowork、统一 Claude 体验、Claude Code（CLI 2.1.199 或更高版本）和 Claude for Microsoft 365 中的新对话。如果所选模型在产品中不可用，则使用 Anthropic 的推荐默认值。如果您还通过托管设置为 Claude Code 固定模型，该设置对 CLI 和 IDE 优先。请参阅**[为您的组织设置默认模型](https://support.claude.com/en/articles/15330088-set-a-default-model-for-your-organization)**。

**粘性默认值 - 始终以默认模型和努力级别开始。**默认情况下，模型选择器是粘性的：新对话从成员最后使用的任何模型开始。要更改此设置，请在**组织设置 > 模型**中打开**始终以默认模型和努力级别开始**。之后每个新对话都在组织的默认模型和默认努力级别上开始。成员仍然可以在对话中更改两者。

粘性默认值自动升级。当发布更改默认模型时，粘性模型会移动到新默认值，因此没有人会停留在较旧的模型上。设置自己默认模型的角色在角色编辑器中有相同的开关。它适用于聊天、Claude Cowork、Claude Code、Claude for Microsoft 365、Claude Design 和 Claude Science。请参阅**[为您的组织设置默认模型](https://support.claude.com/en/articles/15330088-set-a-default-model-for-your-organization)**。

您还可以通过自定义角色按角色设置默认值。例如，您可能会将 Claude Opus 设置为组织默认值，将 Claude Fable 设置为研究和分析角色的默认值。这建立在您已经设置的基于角色的访问控制组上（请参阅上面的**基于角色的访问控制**）。

**配置方法：**组织默认值为**组织设置 > 模型**。对于角色默认值，请转到**组织设置 > 角色 > 选择角色 > 模型标签页**。

### 为您的组织管理模型访问权限

除了设置默认值外，您还可以限制哪些模型可用——这是比仅指导更强的杠杆。这在两个级别上工作：

- **组织级别：**每个模型对所有人（包括所有者和管理员）启用或禁用。在此处禁用模型会将其从整个组织的每个选择器中删除。

- **自定义角色级别：**对于自定义角色上的成员，每个角色授予对组织级别启用内容的*子集*的访问权限。角色无法授予组织已禁用的模型——组织设置始终是上限。

如果成员属于具有不同自定义角色的多个组，访问权限是**累加的**——他们获得其任何角色授予的每个模型（只要它在组织范围内启用）。

**按角色限制努力级别**

除了限制角色可以使用的模型外，您还可以限制该角色上的成员每个模型可以选择的**最大努力级别**——这是上面已涵盖的努力指导的更精细版本。您还可以为整个组织设置努力上限，这是任何角色可以允许的最高级别。如果成员有多个角色，这些角色中最高的努力上限获胜。

您还可以为角色的默认模型设置**默认努力级别**，以便新对话以您选择的级别开始，可以是 Anthropic 的推荐默认值或特定级别。默认值不能高于该模型的努力上限。请参阅**[为您的组织设置默认模型](https://support.claude.com/en/articles/15330088-set-a-default-model-for-your-organization?utm_source=it&utm_medium=email&utm_campaign=2026_Q3_PMM_MKTG_EntAdmin_Newsletter_Sept16&utm_term=ent_admins&utm_content=inline_link&campaign=19893371#h_d5373c4106)**以了解更多信息。

**此功能适用于**

模型访问和工作量限制在大多数 Claude 产品中强制执行，包括聊天（网页、桌面、移动）、Claude Cowork 和 Claude Code（CLI 2.1.199 或更高版本——早期版本仍显示受限选项，但使用这些选项的请求会被拒绝）。Claude in Chrome 和 Claude Security 目前不支持此功能。有关当前支持的产品列表，请参阅**[为您的组织管理模型访问](https://support.claude.com/en/articles/15694740)**。

**配置方式：****组织设置 > 角色 > 选择角色 > 模型选项卡**。设置模型访问、每个模型的可选工作量上限、可选的角色级默认模型、默认工作量级别和**始终使用默认模型和工作量级别**开关。要在整个组织中管理配置，请转到**组织设置 > 模型**。  更多详情请参阅**[为您的组织管理模型访问](https://support.claude.com/en/articles/15694740)**。

### 管理员配置建议

- 如果您有高容量、低复杂度的工作流（例如，总结支持工单、生成初稿电子邮件），请评估 Haiku 是否更合适——它可以显著降低这些用例的消耗。

- 定期审计用户实际选择的模型。如果使用情况与您的默认设置相差很大，请检查您的模型指导是否有效。

### 向用户说明模型选择

**Sonnet 适用于日常工作。**它速度快、功能强大，专为范围明确的任务而设计——写作、分析和问答。

**Opus 适用于更难、更复杂的工作，包括编码和代理任务。**当您处理真正复杂的多步骤问题，或质量比速度更重要时，请使用它。

**如有疑问，请从****您组织的默认设置开始。**Anthropic 推荐的默认设置是聊天和统一 Claude 体验中的 Sonnet，以及 Claude Code 和 Claude Cowork 中的 Opus**。**如果您需要更深入的内容，可以随时在对话中途切换模型。

## 使用组织说明来塑造用户行为

组织说明让管理员在整个组织的每个 Claude 对话中注入常设指导——有效地为 Claude 提供反映您团队规范、最佳实践和护栏的系统提示。这是一个高杠杆工具，可以改变用户行为而不增加摩擦，因为指导在使用时显示在产品中，而不是在用户必须查找的文档中。

您可以通过以下几种方式使用组织说明来管理消耗和使用模式：

- **劝阻令牌密集型输出格式。**如果您注意到特定工件类型的增加（例如，在更简单的格式就足够的跨职能线程中共享 HTML 仪表板），您可以指示 Claude 在生成之前与用户确认。这增加了一个轻量级检查，而不会完全删除该功能。

- **将用户指向内部资源。**在偏好设置中直接引用您团队的 wiki、最佳实践文档或使用指南。Claude 会在相关时显示它们——引导用户获取正确的内部背景，而不是每次都重新发明。

- **强化模型选择规范。**提醒 Claude（进而提醒用户）哪个模型是您的默认模型，哪些工作流需要不同的模型。这补充了用户教育，而不需要每个人预先内化它。

## 跟踪使用情况和支出

### 分析页面

用户菜单中的分析页面（**claude.ai/analytics**）是快速了解您组织情况的最快方式。它显示每周活跃用户、座位利用率、热门连接器、总支出（MTD/QTD/YTD）、按模型的支出和前 10 名按支出排名的用户排行榜。聊天、Claude Code、Cowork 和 Claude Design 的产品特定视图分别显示每个界面的活动。**[了解更多](https://support.claude.com/en/articles/12883420-view-usage-analytics-for-team-and-enterprise-plans)**。

### 技能分析和每项技能的投资回报率

每项技能代表一个可重复的工作流——准备销售电话、审查合同——因此其成本可以直接与该工作流的价值进行权衡。分析中的技能视图显示您组织中每项技能的用户、每次使用的成本和总使用次数，可按组（“我的法律团队使用哪些技能？”）或产品界面进行筛选。

要运行投资回报率分析：

1. 从技能视图将技能表导出为 CSV。

2. 为每项技能分配每次运行的价值——完成任务价值的粗略估计，例如它替代的员工时间（例如，“准备销售电话对我们来说价值约 20 美元”）。

3. 在您的电子表格中计算：（每次运行的价值 − 每次使用的成本）× 总使用次数 = 每项技能产生的净价值。

计算目前在产品外进行，但 CSV 导出使其成为快速的电子表格练习。即使是粗略估计也能讲述一个引人注目的故事：每次运行成本为 0.90 美元、价值为 20 美元的电话准备技能每次使用都能获得 20 倍的回报。

### 支出报告 CSV 导出

如果您需要一次性详细分解，可以从分析页面将按用户、按模型的支出报告导出为 CSV：在概览选项卡的支出部分（“Claude 的成本是多少？”）中，单击“导出支出报告”并选择 MTD、上个月、过去 90 天或最多 90 天前的自定义范围。

### 按项目支出（测试版）

符合条件的组织可以添加项目标签（例如 WBS 代码或客户事项编号），以在**组织设置 > 使用情况 > 按项目支出**中按标签查看支出。项目标签仅在项目内工作，并非每个 Claude 产品都涵盖。标签名称和值对您组织中的所有用户可见，金额可能与您的发票不匹配。了解有关**[使用项目标签按成本代码跟踪支出](https://support.claude.com/en/articles/18251257-track-spend-by-project-with-tags)**的更多信息。

### 分析聊天

分析聊天让您可以用自然语言提问关于您组织使用情况的问题。输入一个问题——“显示过去 30 天的每日支出，”“谁是我们的最大支出者，”“我们的座位利用率是多少”——Claude 会返回一个图表和一份关于其发现的简短书面总结。您可以跟进以细化、深入或转向，而无需重新开始。

当您有具体问题且不想浏览仪表板时，或当您探索趋势并想要快速来回时，请使用此视图。结果默认涵盖过去 30 天；如果您需要，请在问题中指定不同的范围。数据每天刷新。**[了解更多](https://support.claude.com/en/articles/14729354-use-analytics-chat-to-ask-claude-about-usage)**。

### 分析 API

对于程序化访问，请使用 Claude Enterprise 分析 API。拉取按令牌使用或美元支出排名的用户列表，或查看按产品、模型、RBAC 组、上下文窗口、区域或服务层（标准与快速）分解的使用和成本趋势。按 RBAC 组对成本报告进行分组可获得部门级支出以进行退款，而无需导出按用户行。每个请求的宽度上限为 31 天，从过去 365 天内开始，不早于 2026 年 1 月 1 日。

您的主要所有者可以在**组织设置 > API** 下使用 read:analytics 范围创建密钥。成本和使用数据通常在约四小时内到达（偶尔长达 24 小时），并可在其所属月份结束后的七天内进行修订。对于最终总数，请在该窗口关闭后再查询一个月。用户、技能、插件和连接器等参与端点每天更新，大约有一天的延迟。**[了解更多](https://platform.claude.com/docs/en/manage-claude/analytics-api)**并查看**[API 参考指南](https://platform.claude.com/docs/en/api/admin/analytics)**。

### 按用户的技能、插件和连接器使用情况

分析 API 还按用户分解技能、插件和连接器使用情况。`skills`、`plugins` 和 `connectors` 端点各支持 `group_by[]=user_id` 参数，将您在仪表板中看到的组织范围总数转换为每个用户每项技能（或插件或连接器）一行——因此您可以准确看到谁在运行给定的技能、频率如何，以及哪些团队成员实际调用了您推出的插件。您还可以按 RBAC 组或产品界面分组，或按名称筛选到单个技能、插件或连接器。

这对于上述相同的按技能投资回报率问题很有用，只是按个人用户分解而不是导出到电子表格——例如，确认插件推出确实与分发给它的团队一起进行，而不仅仅是检查它是否已安装。在 API 参考中了解更多：**[技能](https://platform.claude.com/docs/en/api/admin/analytics/skills/list)**、**[插件](https://platform.claude.com/docs/en/api/admin/analytics/plugins/list)**、**[连接器](https://platform.claude.com/docs/en/api/admin/analytics/connectors/list)**。

### 管理员 API

对于在许多组中管理限制的组织，**[管理员 API](https://support.claude.com/en/articles/15330651-claude-enterprise-admin-api-reference-guide)** 将成本控制工作流移入脚本——自动化增加请求审查、标记接近限制的成员，以及大规模显示快速变化的使用情况。该 API 读取每个成员的有效限制和本月迄今为止的支出，并设置或清除按用户覆盖。组、座位类型、组织级限制和汇总组预算仍在组织设置中配置。管理员 API 的用户管理端点（目前对企业组织处于测试版）还允许您以编程方式创建组、添加或删除成员以及读取您的自定义角色。请参阅**[用户管理](https://platform.claude.com/docs/en/manage-claude/user-management)**。

管理员 API 还可以列出项目标签（测试版）、向标签列表添加值以及设置项目的标签。了解有关**[使用项目标签按成本代码跟踪支出](https://support.claude.com/en/articles/18251257-track-spend-by-project-with-tags)**的更多信息。

### 支出阈值警报

支出阈值警报在达到组织级支出限制的 75% 和 90% 时通知管理员，让您有时间在任何人被阻止执行任务之前提高上限。汇总组预算在达到池的 50%、75%、95% 和 100% 时向计费管理员发送自己的警报。

### 产品内调查

上述分析告诉您您的团队使用 Claude 的频率；调查告诉您他们用它做什么以及什么阻碍了他们。从**[分析 > 调查](https://claude.ai/analytics/surveys)**，管理员可以向用户发送一份简短调查，该调查在 Cowork 或聊天中的自然休息时出现。按组选择受众、设置窗口并在控制台中查看汇总结果，包括响应率、按界面和组的分解以及书面答案的源，每份调查都有 CSV 导出。了解有关**[为您的组织创建调查](https://support.claude.com/en/articles/16764057)**的更多信息。

### 达到限制的时间（使用情况页面）

在**组织设置 > 使用情况**中的使用情况页面打开时，显示成员达到其支出限制的频率。它显示本月每个活跃座位的达到限制的时间，适用于所有成员和您的高级用户（按支出排名的前 10%），与之前的月份相比并带有预测。它还指出哪个组或限制类型占达到限制时间最多，因此您知道首先查看的位置。

使用此视图检查限制是否适合人们的工作方式。达到限制的时间增加意味着成员在执行任务中途被阻止。您可以从同一页面调整限制：提高默认值，或增加达到限制的成员的限制。

### 智能报告

分析显示每个团队的支出情况。智能报告展示这些支出产生的成果。您可以按团队、日期范围和要包含的产品来确定报告范围。Claude 会审查样本转录记录，并按工作流和输出类型按原价分解支出。

对于消费管理，请关注以下部分：

- **按输出类型划分的每次会话成本。**查看哪些类型的工作生成成本高，以及该成本是否与其价值相匹配。

- **最常见的摩擦**和**低效率。**返工循环和没有可用输出的会话是没有回报的支出。重复出现的摩擦通常指向您可以在几分钟内启用的连接器或设置。

- **建议。**查看可以转化为技能的重复工作流。将重复工作打包为共享技能可以让整个团队更快地获得一致的结果。推出后，在“技能”视图中跟踪其成本和投资回报率。

- **成本最高的会话。**查看支出集中的地方。

智能报告旨在帮助您了解采用情况和规划投资，而不是评估个人绩效。有关可用性、设置以及如何创建和共享报告，请参阅**[智能报告入门](https://support.claude.com/en/articles/16893491-get-started-with-smart-reports)**。

### 调查

您可以在 Claude 中运行简短调查，了解人们使用 Claude 的目的、其价值以及他们遇到的困难。然后将他们的答案与您的支出数据进行比较。

调查在 Claude Cowork 中的任务之间显示为卡片，或在聊天中的回复后显示，永远不会中断正在运行的任务。您可以发送给所有成员或特定群组，选择 Cowork、聊天或两者，并设置开始和结束日期。每个用户只会看到一次调查。结果在调查进行期间实时更新：响应率、多选题的条形图以及可按群组筛选的书面答案反馈。您也可以将其导出为 CSV。

对于消费管理，调查在以下方面很有用：

- **检查高支出背后的价值。**当某个群组经常达到其限额时，在提高或降低上限之前，询问它使用 Claude 的目的。

- **填补您的投资回报率数据。**询问 Claude 在关键工作流上节省了多少时间，并将答案用作技能投资回报率分析中的每次运行价值估计。

- **发现摩擦。**询问 Claude 在哪些方面没有帮助。答案通常指向需要更改的连接器、技能或模型设置。

**如何配置：****分析 > 调查 > 新建调查**。主要所有者、所有者、管理员和具有分析视图访问权限的自定义角色可以创建调查并查看结果。响应发送给您组织的管理员，Anthropic 仅在需要时访问它们以运行服务。不要在响应中放置受管制的数据（如 PHI）。响应不是匿名的：导出包括每个受访者的电子邮件。对于使用客户管理的加密密钥 (CMEK) 的组织，调查尚不可用。请参阅**[为您的组织创建调查](https://support.claude.com/en/articles/16764057-create-surveys-for-your-organization)**。

## 最终用户教育

技术控制可以解决大部分问题，但用户行为决定了其余部分。了解消费工作原理的团队将独立做出更好的选择，并为您减少需要排查的边界情况。

### 与最终用户沟通的内容

在引入用户时，分享以下内容：

**Claude 如何计费**

- 使用量以令牌衡量。较长的提示和较长的对话会消耗更多令牌。

- Claude Code 和 Cowork 会话的令牌消耗量明显高于聊天。单个较长的编码会话可能会消耗比典型聊天会话多得多的令牌。

- 通过切换到**设置 → 使用情况**在设置中检查您的使用情况。

**如何选择模型**

- Sonnet 可以很好地处理大多数日常任务。对于复杂的多步骤工作（如编码），请使用 Opus。

- 您的组织为新对话设置了默认模型；您仍然可以选择不同的模型。在任务开始时选择它。

- 模型选择器在界面中可见——提醒用户检查它，特别是如果他们正在运行复杂任务。

- 除非您的管理员启用了“始终从默认模型开始”，否则模型选择器会记住您的最后选择，因此在开始任务前请检查它。

- 努力级别显示在模型名称旁边。更高的努力意味着更全面的响应，但令牌消耗更高，因此请将其与任务相匹配。

**当他们达到上限时会发生什么**

- 当用户接近其支出限额时会收到产品内通知，一旦达到限额，可以点击“请求更多使用量”向管理员发送增加请求，无需离开 Claude。告诉用户谁是他们的批准者以及您的预期周转时间。

- 他们已经生成的任何内容都不会丢失。已在进行中的请求会完成，但进一步的请求会被阻止，因此多步骤 Claude Code 或 Claude Cowork 任务可能会在完成前暂停。一旦管理员提高限额，或在每月 1 日 00:00 UTC 时限额重置后，他们可以立即继续工作。

- 如果您的群组使用共享预算，当共享池用尽时，使用可能会暂停，即使您尚未达到自己的限额。
