# 覆盖模型的数据保留实践

为了确保我们负责任地部署覆盖模型，**我们要求有限的数据保留和审查作为我们安全工作的一部分。提交给覆盖模型的提示和由覆盖模型生成的输出将保留30天****以支持我们的安全工作，在提供这些模型的每个平台上。**

这适用于Mythos级模型和我们指定为**[覆盖模型](https://support.claude.com/en/articles/15425695)**的具有类似功能的未来模型。对于所有其他模型，您使用的所有内容都不受影响，并保持在当前条款下。

本政策（如下所述）将于2026年6月9日生效。

## 适用范围

消费者计划（Claude Free、Pro、Max和Ultra）在我们的网络、桌面和移动应用程序上（包括Claude.ai和Claude Code）不受此更新影响，因为我们已经在这些平台上保留输入和输出。了解更多关于**[我们如何保留数据](https://privacy.claude.com/en/articles/10023548-how-long-do-you-store-my-data)**的信息，适用于消费者计划。

此更改仅适用于在Claude Console中设置了**[零数据保留](https://privacy.claude.com/en/articles/8956058-i-have-a-zero-data-retention-agreement-with-anthropic-what-products-does-it-apply-to)**（ZDR）工作区的组织、在Claude Enterprise中使用带ZDR的Claude Code的组织，或通过AWS Bedrock、Google Cloud Agent Platform或Microsoft Foundry（带ZDR）访问Claude的组织。其中一些组织将收到通知，他们有资格使用带ZDR的Fable，如此处所述：**[零数据保留和企业前沿保障](https://support.claude.com/en/articles/15425695-covered-models#h_077fc48764)**。本文的其余部分仅适用于具有零数据保留且未收到此通知的组织。

## 我们为什么这样做

Mythos级模型代表了模型能力的大幅提升，其中一些可用于良性和恶意目的。Claude Fable 5和Claude Fable 5.1与Claude Mythos 5和Claude Mythos 5.1共享相同的底层模型，但具有额外的保障措施，特别是在网络和生物领域。虽然这些保障措施使我们能够更广泛地共享此智能，但我们采取了保守的方法，使我们能够寻找这类模型和我们发布的具有类似或更强能力的未来模型的滥用模式。某些攻击只有在多个请求中才会显现。例如，**[最佳N越狱](https://arxiv.org/abs/2412.03556)**发送数百个提示的细微变化，希望其中一个能够成功。更大规模的滥用模式，如**[国家赞助的间谍活动](https://www.anthropic.com/news/disrupting-AI-espionage)**或**[数据勒索活动](https://www.anthropic.com/news/detecting-countering-misuse-aug-2025)**，只有当我们的保障措施分类器能够跨多个请求进行分析时才会显现。检测这些威胁需要临时保留提示和输出，以便将它们一起分析，而不是逐个分析。

## 我们如何保护您的数据

默认情况下，Anthropic的任何人员都无法读取您保留的对话。人工审查只能通过受控访问路径进行——例如，当内容被我们的自动信任和安全系统标记为可能有害时。这些审查只能由一小组经批准的审查员执行。每次访问都记录在防篡改日志中，审查员无法抑制或修改该日志。30天后，数据会自动删除，除非在极少数情况下被我们的自动信任和安全系统标记或我们在法律上被要求保留。符合条件的组织还可以选择添加客户管理的加密密钥和访问透明度审计日志。

Anthropic维护一个有文件记录的信息安全计划，具有旨在保护客户数据的安全性、机密性和完整性的技术和组织措施。我们的基于风险的计划为防御已知和预期的威胁模型而构建，并不断发展，定期进行测试。

## 我需要配置什么（如果有的话）？

此更改仅适用于在Claude Console中设置了零数据保留（ZDR）工作区的组织、在Claude Enterprise中使用带ZDR的Claude Code的组织，或通过AWS Bedrock、Google Cloud Agent Platform或Microsoft Foundry（带ZDR）访问Claude的组织。对于所有其他组织，没有变化，也没有什么需要配置的。本部分的其余内容适用于当今在没有数据保留的情况下访问Claude的组织，他们需要设置数据保留以便在指定模型可用时使用它们。

### 如果您的开发人员使用Claude API

- **直接从Anthropic通过Claude Platform：**在Claude Console中为您想要使用覆盖模型的工作区启用保留：转到**数据保留**页面（platform.claude.com/settings/privacy）并从页面顶部的下拉菜单中选择工作区。您的其他启用ZDR的工作区保持ZDR。了解如何**[在零数据保留组织中为工作区启用数据保留](https://support.claude.com/en/articles/16824617-turn-on-data-retention-for-a-workspace-in-a-zero-data-retention-organization)**，或参考**[Anthropic信任中心以获取其他文档](https://trust.anthropic.com/)**。

- **通过AWS上的Claude Platform：**保留的工作方式与直接Claude API相同。它在工作区级别配置，保留的数据由Anthropic在相同的控制下处理。

- **通过Amazon Bedrock：**需要启用保留以访问覆盖模型，保留的数据保留在AWS中。参考AWS Bedrock的**[文档](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html)**。

- **通过Google Cloud的Agent Platform：**需要启用保留以访问覆盖模型，保留的数据保留在GCP中。参考Google Cloud的Agent Platform**[文档](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/partner-models/claude/fable-5)**。

- **通过Claude in Azure Foundry：**保留为每个Azure订阅配置。如果您配置了零数据保留，则需要创建并使用单独的Azure订阅来访问这些模型。

### 如果您的团队使用Claude Code

- **通过Anthropic API：**Claude Code的数据处理实践由其运行的工作区管理。如果该工作区启用了保留，Claude Code可以使用指定的模型。对于直接登录的开发人员，在您组织的Claude Code工作区启用保留。

- **通过Amazon Bedrock或Google Cloud Agent Platform：**Claude Code使用您的云凭证，因此遵循您的云环境的保留设置。必须在您的云环境中启用保留，保留的数据保留在您的提供商的环境中。通过Amazon Bedrock或Google Cloud的Agent Platform访问的Cowork也适用相同的规则。

- **通过Claude Enterprise with ZDR：**我们在管理控制台中发布了控制，以便您的主要所有者可以直接更改保留设置。如果您暂时不想触及您的生产组织，我们可以帮助您设置单独的沙箱组织。

### 如果您的团队通过Claude for Enterprise使用Claude chat或Cowork

- 这些平台已经使用标准保留进行操作，因此当新模型可用时，您将能够访问它们。
