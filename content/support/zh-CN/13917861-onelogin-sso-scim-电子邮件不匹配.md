# OneLogin SSO/SCIM 电子邮件不匹配

Claude 使用电子邮件作为主要标识符来匹配 SSO 登录与已配置的席位。在 OneLogin 中，SCIM 配置和 SAML SSO 在应用的不同选项卡中配置，可能引用不同的用户配置文件字段，导致不匹配从而阻止访问。

**适用于：**使用 SCIM 配置的企业计划和 Console 组织。Team 计划没有 SCIM 配置，因此不适用此不匹配场景——请参阅**[设置 JIT 或 SCIM 配置](https://support.claude.com/en/articles/13133195)**了解各计划的可用功能。

---

## 症状

人员在尝试通过 SSO 访问您的组织时可能会遇到以下一种或多种情况：

- **“账户创建被阻止”**——该人员通过 SSO 进行身份验证，但 Claude 找不到匹配的已配置账户。如果您的组织限制了组织创建（推荐），该人员将被完全阻止。

- **登录到免费个人账户**——如果未限制组织创建，该人员将完全绕过您的组织，创建或登录到免费个人账户，而不是其已配置的席位。

- **“检查您登录的账户”不匹配**——SSO 回调显示的电子邮件与该人员在登录时输入的电子邮件不同。

- **Claude Code 身份验证失败**——Claude Code CLI 在身份验证流程中显示电子邮件不匹配错误。

---

## 发生原因

OneLogin 用户配置文件包含用户名和电子邮件的不同字段，可能包含不同的值。SCIM 配置参数和 SAML 属性语句是独立配置的，每个都可以从不同的字段中提取：

| **OneLogin 字段** | **典型值**                               | **常用于**               |
| --------------- | ------------------------------------- | --------------------- |
| `用户名`           | `testuser1` 或 <testuser1@example.com> | 有时用于 SCIM userName 映射 |
| `电子邮件`          | <test.user.one@example.com>           | 建议用于 SCIM 和 SAML      |
| `登录名`           | 如果 SSO 用于非电子邮件登录，可能与电子邮件不同            | 旧版或自定义配置              |
| 自定义用户字段         | 按组织定义的自定义属性                           | 高级属性映射                |

常见的不匹配：SCIM 参数选项卡将电子邮件属性映射到用户名（可能是员工 ID 或短名称），而 SAML 属性语句发送电子邮件字段。Claude 需要**完全字符串匹配**。

**常见混淆：**OneLogin 的 SCIM 参数和 SAML 属性语句位于同一应用的不同选项卡中——SCIM 使用**参数**，SSO 使用**SSO**（或带有 SAML 特定字段的**参数**）。两者都必须检查并对齐。

---

## 诊断步骤

## 步骤 1——确认不匹配

1. **检查 SCIM 电子邮件：**在 OneLogin 管理门户中，转到**应用程序 → [Claude 应用] → 参数**。找到映射到 Claude 接收的电子邮件的字段。注意**OneLogin 值**列——这显示发送的是哪个用户字段。

2. **检查 SAML 电子邮件：**在同一应用中，转到**SSO**选项卡。点击**更多操作 → 编辑 SAML 响应**或检查**SAML 属性语句**部分。找到电子邮件属性并注意其源字段。

3. **检查特定人员：**在**用户 → [用户]**中，比较**用户名**和**电子邮件**字段。如果它们不同，使用其中一个的任何映射都会导致不匹配。

## 步骤 2——确定问题范围

- 如果**大多数或所有**已配置的人员共享相同的电子邮件格式不匹配，这是**系统属性映射问题**。修复方法在您的 IdP 的 SCIM 属性映射中。

- 如果只有**一两个人**受影响，问题可能特定于这些账户。直接检查他们的配置文件。

## 步骤 3——查看用户字段值

1. 转到**用户 → [受影响的用户] → 用户信息**。

2. 检查**用户名**和**电子邮件**字段。

3. 如果用户名的格式不符合有效电子邮件，SCIM 可能发送无效或不匹配的值。

---

## 解决方案

## 将两个映射对齐到电子邮件字段

OneLogin 的电子邮件字段是 SCIM 和 SAML 最可靠的来源，因为它设计用于保存有效的电子邮件地址。

1. **更新 SCIM 参数：**在**应用程序 → [Claude 应用] → 参数**中，找到 Claude 接收的电子邮件属性所在的行。将**值**更改为**电子邮件**（OneLogin 电子邮件字段）。

2. **更新 SAML 属性语句：**在**SSO**选项卡（或用于 SAML 属性的**参数**）中，更新电子邮件属性值以使用相同的**电子邮件**字段。

3. 点击“保存。”

## 触发完整重新同步

**关键——需要完整同步：**增量同步*不会*在您更改属性映射后更新现有记录。您必须触发配置周期的**完整重启**。

1. 在应用的**配置**选项卡中，查找**重新同步**或**同步全部**选项并运行它。

2. 重新配置个人：转到**用户 → [用户] → 应用程序**，找到 Claude 应用，并使用**重新配置**。

3. 检查 OneLogin 配置活动日志中的错误。

4. 在要求人员重试登录之前，验证更新的电子邮件值是否出现在日志中。

---

## 修复后清理

更正属性映射并完成完整同步后：

- **流氓免费账户：**如果在修复前未限制组织创建，某些人员可能无意中创建了免费个人 Claude 账户。联系**[我们的支持团队](https://support.claude.com/en/articles/9015913)**将其删除。

- **幽灵账户（错误电子邮件席位）：**原始配置的具有不正确电子邮件的账户可能仍然存在于您的组织中，占用永远无法使用的席位。联系我们的支持团队以取消配置这些账户。

- **席位可用性：**如果幽灵账户占用了所有合同席位，即使映射修复后，新登录也会因席位不足错误而失败。

- **重新添加受影响的人员：**删除幽灵账户后，具有更正电子邮件的人员可能需要重新邀请或重新配置。

- **防止未来发生：**在您的组织的身份和访问设置中启用“限制组织创建”。

---

## 验证

1. 检查已配置人员的样本——确认配置日志中的电子邮件与 SSO 发送的电子邮件格式匹配。

2. 要求受影响的人员清除 claude.ai 的浏览器 Cookie，然后通过 SSO 登录。

3. 确认人员未创建免费账户。

4. 如果 Claude Code 受影响，让该人员重新运行 `claude auth login --enterprise` 并确认电子邮件与其已配置的席位匹配。

## 常见问题

| **问题**                   | **解决方案**                            |
| ------------------------ | ----------------------------------- |
| 用户名字段包含短名称或员工 ID，而不是电子邮件 | 将 SCIM 切换为使用**电子邮件**字段。             |
| SAML 属性已更新但 SCIM 参数未更改   | 参数选项卡（用于 SCIM）和 SSO/SAML 属性都必须独立更新。 |
| 重新同步似乎未触发                | 尝试从应用中删除并重新分配受影响的人员。                |
| 自定义用户字段已映射但某些人员为空        | 切换到标准**电子邮件**字段。                    |
| SCIM 中的电子邮件已更新但人员仍无法登录   | 检查流氓免费组织或幽灵账户。清除浏览器 Cookie 并重试。     |
| “邀请域不允许”尝试重新添加人员时        | 您的组织域可能未在 Claude 中验证。联系支持。          |

## 何时联系支持

当出现以下情况时，请联系**[我们的支持团队](https://support.claude.com/en/articles/9015913)**，并提供您的组织域、受影响人员的电子邮件和属性映射的屏幕截图：

- SCIM 和 SSO 属性看起来相同，但人员仍无法访问其席位。

- 您需要确认 Claude 在 SCIM 配置期间为特定人员记录的电子邮件。

- 您需要帮助清理幽灵账户或流氓免费组织。

- 人员遇到席位不足错误，尽管有可用的合同席位。
