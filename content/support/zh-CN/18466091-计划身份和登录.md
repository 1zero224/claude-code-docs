# 计划身份和登录

Claude Desktop 在第三方部署上有多个独立的登录方式，大多数可以使用不同的身份系统。在安排迁移前，请列出所有登录方式。如果您还要更改身份提供商 (IdP)，两个项目的顺序很重要，因为默认情况下 claude.ai 一次只接受一个 IdP。

本指南适用于 Claude Enterprise 计划组织的管理员。

本文是 **[从 Claude Enterprise 迁移到云提供商上的 Claude Desktop](https://support.claude.com/en/articles/18426225)** 的一部分，该文定义了波次、重叠期和截止日期等术语。

## 用户将看到的登录方式

| **登录**                             | **谁会看到**                                                                                                                   | **使用的内容**                                                                                                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| claude.ai（您的 Claude Enterprise 组织） | 每个用户，直到他们最后一次导入。导入向导 **[在浏览器中打开 claude.ai 以登录和授权](https://claude.com/docs/third-party/claude-desktop/import)**。            | 由您的 **[父组织](https://support.claude.com/en/articles/10276682-important-considerations-before-enabling-single-sign-on-sso-and-jit-scim-provisioning)** 持有的 SSO 连接。            |
| Enterprise Admin Console           | 仅限应用从控制台管理的用户。使用 MDM、本地文件或引导服务器时，**[用户没有 Anthropic 账户](https://claude.com/docs/third-party/claude-desktop/data-storage)**。 | 用户工作邮箱下的 Claude 账户，**[通过您连接的 SSO](https://claude.com/docs/third-party/claude-desktop/admin-console)**。建议使用 SSO，但不是必需的。登录大约每月过期一次。                                           |
| 您的提供商                              | 每个用户，除非您部署共享密钥、凭证文件或凭证助手。                                                                                                  | IAM Identity Center、Google Workforce Identity 或 Entra ID。它 **[独立于 Claude 登录](https://claude.com/docs/third-party/claude-desktop/admin-console)**，应用永远不会将 Claude 凭证发送给您的提供商。 |
| 引导服务器                              | 仅限使用具有按用户登录的引导服务器的部署。                                                                                                      | 您自己的 IdP。它 **[独立于推理登录](https://claude.com/docs/third-party/claude-desktop/bootstrap)**，除非在设备代码模式下，如果网关和引导服务器共享源，则一个登录涵盖两者。                                                  |
| 连接器                                | 每个用户，每个连接器一次。                                                                                                              | **[连接器供应商的 IdP](https://claude.com/docs/third-party/claude-desktop/mcp-sign-in)**。应用在设备上存储每个连接器令牌，因此用户需要在新应用中再次连接每个连接器。                                                     |
| Claude Code CLI                    | 开发人员。                                                                                                                      | 云提供商自己的凭证链。请参阅**迁移 Claude Code CLI 用户**。                                                                                                                                    |

## 将您的 IdP 连接到云提供商

每个提供商的设置指南说明了如何连接您的 IdP。

- **Amazon Bedrock：**将您的 IdP **[设为 IAM Identity Center 的身份源](https://claude.com/docs/third-party/claude-desktop/bedrock)**。AWS 允许 **[AWS Organizations 中每个组织仅有一个身份源](https://docs.aws.amazon.com/singlesignon/latest/userguide/manage-your-identity-source.html)**。在更改之前，请阅读 AWS 的 **[更改身份源的注意事项](https://docs.aws.amazon.com/singlesignon/latest/userguide/manage-your-identity-source-considerations.html)**。

- **Google Cloud：**使用 **[Workforce Identity Federation](https://docs.cloud.google.com/iam/docs/workforce-identity-federation)** 与 **[池中的 OIDC 提供商](https://claude.com/docs/third-party/claude-desktop/vertex)**。一个池可以联合一个或多个 IdP。

- **Microsoft Foundry：**Foundry 直接使用 **[Entra ID](https://claude.com/docs/third-party/claude-desktop/foundry)**。如果您有条件访问规则，请参阅 **[通过操作系统身份代理登录](https://claude.com/docs/third-party/claude-desktop/entra-broker)**。

- **LLM 网关：**用户登录到 **[您的 IdP](https://claude.com/docs/third-party/claude-desktop/gateway)**，您的网关检查每个用户的令牌。

## 如果您要更改 IdP

- **默认情况下，claude.ai 采用一个 IdP。****[每个父组织链接到一个 IdP](https://support.claude.com/en/articles/10276682-important-considerations-before-enabling-single-sign-on-sso-and-jit-scim-provisioning)**，**[所有已验证的域必须使用它](https://support.claude.com/en/articles/13132885-set-up-single-sign-on-sso)**。例外是测试版：注册了集中管理的父组织可以 **[连接多个 IdP](https://support.claude.com/en/articles/18246779-set-up-multiple-identity-providers-and-split-domains)**。当任何组织使用 JIT 预配或为该域启用 Microsoft Login 时，域无法获得第二个 IdP。在测试版之外，您无法在那里并行运行旧 IdP 和新 IdP。

- **按照我们的步骤切换 IdP。**请参阅 **[切换到不同的身份提供商 (IdP)](https://support.claude.com/en/articles/13443687-switching-to-a-different-identity-provider-idp)**。重置 SSO 连接会将所有用户登出。在新连接生效前，他们可以通过电子邮件链接登录。对于 Entra ID，请参阅 **[Microsoft Entra ID SSO 设置](https://support.claude.com/en/articles/13917889-microsoft-entra-id-sso-setup)**。

- **确保电子邮件地址完全匹配。**Claude **[通过电子邮件将 SSO 登录与席位匹配](https://support.claude.com/en/articles/13917829-microsoft-entra-id-sso-scim-email-mismatch)**。新 IdP 中的不匹配 **[会创建重复账户](https://support.claude.com/en/articles/13443687-switching-to-a-different-identity-provider-idp)**，SCIM 电子邮件更改 **[会删除旧用户并创建新用户](https://support.claude.com/en/articles/14499648-how-scim-sync-works-for-enterprise-organizations)**。在任何人导入前修复不匹配。

- **检查您的 Enterprise Admin Console 组织是否共享该连接。**如果它 **[使用现有 SSO 连接、SCIM 目录和已验证的域](https://claude.com/docs/third-party/claude-desktop/admin-console)**，一个 IdP 可以同时服务两者。在重置 SSO 或关闭较旧的组织前，请咨询您的 Anthropic 账户团队这如何影响 Enterprise Admin Console 组织及其管理的设备。

我们建议按以下顺序进行：

1. 首先将新 IdP 连接到您的云提供商，并在那里试用登录。在 AWS 上，如果 IAM Identity Center 已使用旧 IdP，此步骤会替换该组织的一个身份源。您无法在同一 AWS 组织中并行试用这两个。

2. 如果旧 IdP 将继续服务足够长的时间，请在最后一波导入前保持 claude.ai SSO 连接不变。

3. 如果旧 IdP 更早停用，请在波次之间进行切换。不要在波次导入时切换。首先比较两个 IdP 中的电子邮件属性。

4. 保持 claude.ai 登录和成员数据导出正常工作，直到最后一次导入完成。

## 重叠期的设置

- **登录屏幕：**用户可以选择 claude.ai 或您的提供商配置。**[`deploymentMode`](https://claude.com/docs/third-party/claude-desktop/mdm#restrict-a-device-to-one-deployment-mode)** 设置为 `3p` 会隐藏 claude.ai 选项（Claude Desktop 4.16336.0 或更高版本）。在同时设置您的连接的设备配置文件中设置它。对于早期版本，还要将 `disableDeploymentModeChooser` 设置为 `true`。您无法在控制台中设置任一密钥。不要在控制台管理的设备上设置它们，因为它们 **[会导致应用停止使用控制台](https://claude.com/docs/third-party/claude-desktop/admin-console#keep-a-device-on-its-managed-profile)**。

- **组织锁定：****[`forceLoginOrgUUID`](https://claude.com/docs/third-party/claude-desktop/admin-console#keep-a-device-on-its-managed-profile)** 将设备上的标准登录限制为您的组织。它还接受 **[组织 ID 列表](https://support.claude.com/en/articles/12622667-enterprise-configuration-for-claude-desktop)**。使用控制台时，包括您的 Enterprise Admin Console 组织的 ID 以及您的 Claude Enterprise 组织的 ID，并首先将设备更新到 2.37337.0 或更高版本。否则，控制台的设置不适用。

- **网络允许列表：****[租户限制](https://support.claude.com/en/articles/13198485-enforce-network-level-access-control-with-tenant-restrictions)**使用列出允许的组织 ID 的标头。确保它包括您的用户仍然登录的每个组织。

- **两个组织中的用户：**同时属于另一个组织的控制台用户 **[被询问是否切换，每次切换都会重启应用](https://claude.com/docs/third-party/claude-desktop/admin-console)**。启用**在 Claude Desktop 中要求此组织**，以便用户无法关闭提示。如果您的 Claude Enterprise 组织在 Claude Desktop 中阻止其他账户，首先将 Enterprise Admin Console 组织的 ID 添加到其允许的组织列表中。

- **Claude Code CLI：**在重叠期间在 `allowedProviders` 中列出两个提供商。**[`CLAUDE_CONFIG_DIR`](https://code.claude.com/docs/en/authentication)** 为每个账户提供其自己的配置目录。
