# 在零数据保留组织中为工作区启用数据保留

本文介绍了当您的组织使用零数据保留 (ZDR) 时，如何在 Claude 控制台组织中为工作区启用 30 天数据保留。

此功能仅适用于使用零数据保留的 Claude API 组织。已保留 30 天数据的组织没有此设置。

## 工作区为什么需要数据保留

**[受支持的模型](https://support.claude.com/en/articles/15425695-covered-models)**（如 Claude Fable 5.1）需要 30 天数据保留，除非 Anthropic 明确为您的组织授权（例如，在企业前沿保障措施下），否则在零数据保留下不可用。如果没有，您需要启用数据保留。数据保留在工作区级别配置，因此您需要为每个要使用受支持模型的工作区启用它。

来自禁用保留的工作区的受支持模型请求会返回如下错误：

"为了访问此模型，您的组织或工作区必须启用数据保留。"

## 开始前

开始前，请确保：

- 您是组织的管理员、所有者或主要所有者。具有其他角色且是工作区成员的用户可以看到此设置，但无法更改它。

- 您在默认工作区以外的工作区中工作。默认工作区的保留在组织级别管理，因此如果需要，请创建新工作区。详细了解**[创建和管理工作区](https://support.claude.com/en/articles/9796807)**。

## 为工作区启用数据保留

该设置位于您组织的**数据保留**页面上，页面顶部的下拉菜单允许您选择组织或工作区。

为工作区启用数据保留：

1. 登录**[Claude 控制台](https://platform.claude.com/login)**。

2. 转到**数据保留**页面 (platform.claude.com/settings/privacy)。

3. 从页面顶部的下拉菜单中选择工作区。

4. 选择"标准数据保留（30 天保留）"，然后点击"保存"。

5. 在确认对话框中查看并接受条款。接受即表示您确认**服务特定条款**的第 F 部分适用于此工作区，并补充您的组织与 Anthropic 的协议。只有在您接受后，数据保留才会为工作区启用。

## 查看哪些工作区启用了保留

要查看哪些工作区启用了数据保留，请导航到**工作区**页面 ([https://platform.claude.com/settings/workspaces)，然后点击要检查的工作区右侧的菜单按钮。选择](https://platform.claude.com/settings/workspaces\)%EF%BC%8C%E7%84%B6%E5%90%8E%E7%82%B9%E5%87%BB%E8%A6%81%E6%A3%80%E6%9F%A5%E7%9A%84%E5%B7%A5%E4%BD%9C%E5%8C%BA%E5%8F%B3%E4%BE%A7%E7%9A%84%E8%8F%9C%E5%8D%95%E6%8C%89%E9%92%AE%E3%80%82%E9%80%89%E6%8B%A9)"数据保留"以查看工作区是使用**零数据保留**还是**30 天保留**。

## 启用后会发生什么变化

- 更改立即应用于新请求。在极少数情况下，可能需要长达一小时。

- 来自此工作区的输入、输出和其他数据默认保留 30 天，可能被 Anthropic 用于安全和安保目的。

- 此更改不具有追溯力。它仅适用于启用保留后发送的请求。

- 启用保留时，您组织的零数据保留不再适用于此工作区。其他工作区不受影响。

- 来自此工作区 API 密钥的受支持模型请求现在成功，只要您的组织已有权访问该模型。您不需要新的 API 密钥。

**重要提示：**此设置涵盖来自工作区的 API 请求和响应。它不涵盖需要存储数据才能工作的功能，例如批处理 API、文件 API 和 Claude 托管代理会话。详细了解**[哪些功能符合零数据保留的条件](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention#feature-eligibility)**。

## 为工作区关闭数据保留

您可以从**数据保留**页面 (platform.claude.com/settings/privacy) 再次关闭保留。如果工作区使用客户管理的加密密钥，则无法关闭保留。如果工作区上的程序需要保留，关闭它会删除该程序。
