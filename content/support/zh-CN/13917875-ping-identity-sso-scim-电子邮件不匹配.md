# Ping Identity SSO/SCIM 电子邮件不匹配

Claude 使用电子邮件作为主要标识符来匹配 SSO 登录和已配置的座位。Ping Identity 产品（PingOne 和 PingFederate）具有灵活的分层属性配置。当 SCIM 配置和 SAML/OIDC SSO 从不同的用户属性中提取时，不匹配会阻止访问。

**适用于：**使用 SCIM 配置的企业计划和 Console 组织。Team 计划没有 SCIM 配置，因此此不匹配场景不适用——请参阅**[设置 JIT 或 SCIM 配置](https://support.claude.com/en/articles/13133195)**了解每个计划上的可用功能。

---

## 症状

人员在尝试通过 SSO 访问您的组织时可能会遇到以下一种或多种情况：

- **“账户创建被阻止”**——该人员通过 SSO 进行身份验证，但 Claude 找不到匹配的已配置账户。

- **登录到免费个人账户**——如果未限制组织创建，该人员会完全绕过您的组织。

- **“检查您登录的账户”不匹配**——SSO 回调显示的电子邮件与该人员在登录时输入的电子邮件不同。

- **Claude Code 身份验证失败**——Claude Code CLI 在身份验证流程中显示电子邮件不匹配错误。

---

## 发生原因

Ping Identity 产品允许在多个级别（目录、IdP 适配器、SP 连接器、应用程序）进行细粒度属性映射。SCIM 和 SSO 可以各自通过这些层中的不同路径，导致到达 Claude 的电子邮件值不同：

| **Ping 属性**                 | **典型值**                               | **常用于**                |
| --------------------------- | ------------------------------------- | ---------------------- |
| `email`（PingOne）            | `test.user.one@example.com`           | 建议用于 SCIM 和 SAML/OIDC  |
| `username`（PingOne）         | `testuser1` 或 `testuser1@example.com` | 默认登录标识符；可能与电子邮件不同      |
| IdP 适配器属性（PingFederate）     | 因适配器类型（LDAP、HTML 表单等）而异               | PingFederate 身份源       |
| LDAP `mail` 属性              | `test.user.one@example.com`           | PingFederate 中的目录源电子邮件 |
| LDAP `sAMAccountName` 或 uid | 可能是员工 ID 或短用户名                        | 有时被错误地映射到电子邮件          |
| 自定义群体属性                     | 每个环境定义的自定义字段                          | 高级 PingOne 配置          |

Claude 要求 SCIM 配置的电子邮件与 SSO 声明的电子邮件完全字符串匹配。

**PingFederate 注意：**PingFederate 的属性合同系统特别复杂——电子邮件可以通过多个层（LDAP → IdP 适配器 → 适配器合同 → SP 连接器 → 断言）传递。任何层的不匹配都会导致错误的值到达 Claude。端到端追踪该值。

---

## 诊断步骤

### 步骤 1——确认不匹配（PingOne）

1. **检查 SCIM 属性映射：**在 PingOne Admin 中，转到**连接 → 应用程序 → [Claude 应用] → 属性映射**。找到映射到 emails[primary].value 或 email 的属性。记下用作源的 PingOne 用户属性。

2. **检查 SSO 属性映射：**在同一应用中，转到**SAML**或**OIDC**选项卡，找到映射到电子邮件的属性或声明。记下其源属性。

3. 如果 SCIM 和 SSO 引用不同的 PingOne 属性，您已确认不匹配。

### 步骤 1（备选）——确认不匹配（PingFederate）

1. 在 PingFederate Admin 控制台中，找到 Claude 的 **SP 连接**。

2. 在**属性合同履行**中，找到电子邮件属性并将其源追踪回 IdP 适配器或 LDAP 数据存储。

3. 分别检查 Claude 的 SCIM 配置连接器或出站配置通道，并追踪正在发送的电子邮件属性的源。

4. 如果两条追踪线索指向不同的目录属性，您已确认不匹配。

### 步骤 2——确定问题的范围

- 如果**大多数或所有**已配置的人员共享相同的电子邮件格式不匹配，这是一个**系统属性映射问题**。修复方案在您的 IdP 的 SCIM 属性映射中。

- 如果只有**一两个人**受到影响，问题可能特定于这些账户。直接检查他们的个人资料。

### 步骤 3——检查特定人员的属性值

1. **PingOne：**转到**身份 → 用户 → [用户]**并比较用户名和电子邮件字段值。

2. **PingFederate 与 LDAP：**检查该人员的 LDAP 记录并比较 mail、userPrincipalName、sAMAccountName 和您的适配器映射中使用的任何其他属性。

---

## 解决方案

### PingOne——将两个映射对齐到电子邮件属性

1. 在**连接 → 应用程序 → [Claude 应用]**中，打开**属性映射**。

2. 对于 SCIM：确保 emails[primary].value 映射到 PingOne 的**电子邮件地址**属性。

3. 对于 SAML/OIDC：确保电子邮件属性或声明也映射到 PingOne 的**电子邮件地址**属性。

4. 保存更改。

### PingFederate——在所有层中对齐属性合同

1. 在 Claude 的 SP 连接中，转到**属性合同履行**。

2. 找到电子邮件属性。确保其源是您的 SCIM 出站配置通道中使用的相同 LDAP 或数据存储属性。

3. 如果使用自定义 IdP 适配器，确保适配器的合同包含规范电子邮件属性，并且它正确映射到 SP 连接。

4. 更新 SCIM 配置以使用相同的源属性。

### 触发完整重新同步

**关键——需要完整同步：**增量同步不会在您更改属性映射后更新现有记录。您必须触发配置周期的**完整重启**。

1. **PingOne：**在应用的配置设置中，触发完整配置周期。您可能需要禁用并重新启用配置以强制完整重新推送。

2. **PingFederate：**在您的出站配置通道中触发完整同步。检查您的配置日志以确认更新的电子邮件值正在被发送。

3. 在要求人员重试登录之前，验证更新的电子邮件值出现在配置日志中。

---

## 修复后清理

在更正属性映射并完成完整同步后：

- **流氓免费账户：**如果在修复前未限制组织创建，某些人员可能无意中创建了免费个人 Claude 账户。联系**[我们的支持团队](https://support.claude.com/en/articles/9015913-how-to-get-support)**以删除这些账户。

- **幽灵账户（错误电子邮件座位）：**联系我们的支持团队以取消配置这些账户。

- **座位可用性：**如果幽灵账户占用了所有合同座位，新登录将失败。联系我们的支持团队。

- **重新添加受影响的人员：**删除幽灵账户后，人员可能需要被重新邀请或重新配置。

- **防止未来发生：**在您的组织的身份和访问设置中启用“限制组织创建”。

---

## 验证

1. 检查已配置人员的样本——确认他们在配置日志中的电子邮件与 SSO 发送的电子邮件格式匹配。

2. 要求受影响的人员清除 claude.ai 的浏览器 Cookie，然后通过 SSO 登录。

3. 确认人员没有创建免费账户。

4. 如果 Claude Code 受到影响，让该人员重新运行 `claude auth login --enterprise` 并确认电子邮件与其已配置的座位匹配。

## 常见问题

| **问题**                                 | **解决方案**                                            |
| -------------------------------------- | --------------------------------------------------- |
| 使用了 PingOne `username` 字段而不是 `email`   | 将 SCIM 映射切换到 PingOne 的**电子邮件地址**属性。                 |
| PingFederate 属性在合同层中不匹配                | 端到端追踪电子邮件属性：LDAP 源 → IdP 适配器 → 适配器合同 → SP 连接器 → 断言。 |
| LDAP `sAMAccountName` 或 `uid` 映射为电子邮件源 | 改用 LDAP `mail` 属性。                                  |
| 增量配置同步不更新现有记录                          | 更改属性映射后需要完整重新同步。                                    |
| PingFederate 中的属性合同已更新但 SCIM 连接器未更新    | SP 连接和出站 SCIM 配置通道必须独立更新。                           |
| SCIM 中的电子邮件已更新但人员仍无法登录                 | 检查流氓免费组织或幽灵账户。清除浏览器 Cookie 并重试。                     |
