# 付费 Claude 计划的上下文窗口有多大？

本文介绍了在付费 Claude 计划（Pro、Max、Ultra、Team、Enterprise）中与 Claude 聊天或使用 Claude Code 或 Claude Cowork 时的上下文窗口大小。

| **模型**            | **上下文窗口**   |
| ----------------- | ----------- |
| Claude Fable 5.2  | 1M tokens   |
| Claude Fable 5.1  | 1M tokens   |
| Claude Fable 5    | 500K tokens |
| Claude Opus 5.5   | 1M tokens   |
| Claude Opus 5     | 1M tokens   |
| Claude Opus 4.8   | 500K tokens |
| Claude Opus 4.7   | 500K tokens |
| Claude Opus 4.6   | 500K tokens |
| Claude Sonnet 5.5 | 1M tokens   |
| Claude Sonnet 5   | 1M tokens   |
| Claude Sonnet 4.6 | 500K tokens |
| Claude Haiku 5.5  | 1M tokens   |

除了这些模型外，Claude 的上下文窗口大小为 200K，这意味着在使用付费 Claude 计划与 Claude 聊天时，它可以摄取 200K+ tokens（约 500 页或更多文本）。

## 自动上下文管理

对于启用了代码执行的付费计划用户，Claude 会自动管理您的对话上下文。当对话接近上下文窗口限制时，Claude 会总结早期消息以为新内容腾出空间。这允许对话在大多数情况下无限期继续。触发自动上下文管理的较长对话会使用更多的使用额度。

您的完整聊天历史记录会被保留，以便 Claude 可以参考它，即使早期部分已被总结。在长对话中，您可能偶尔会注意到 Claude "整理思路"——这就是自动上下文管理在起作用。

**注意：**必须启用代码执行才能使自动上下文管理工作。在极少数情况下（例如非常大的首条消息或系统错误），您仍可能遇到上下文窗口限制。

## 最大化您的上下文窗口

虽然对于大多数对话上下文是自动管理的，但您仍然可以优化如何使用可用的上下文空间：

- **有效利用项目：**项目使用检索增强生成 (RAG)，这允许 Claude 通过仅将相关内容加载到上下文窗口中来处理更大量的信息。

- **保持项目说明简洁：**当您使用项目说明来提供项目的一般背景、关键指南和 Claude 的角色时，Claude 表现最佳。

- **管理工具和连接器：**这些功能需要大量 token，因此注意您有多少个处于活跃状态有助于最大化您的可用上下文。
