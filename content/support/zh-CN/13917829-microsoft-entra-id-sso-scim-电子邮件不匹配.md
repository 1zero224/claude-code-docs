# Microsoft Entra ID SSO/SCIM 电子邮件不匹配

Claude 使用电子邮件作为主要标识符来匹配 SSO 登录和已配置的席位。在 Microsoft Entra ID 中，SCIM 配置和 SSO 身份验证配置在*不同的位置*，可能从不同的用户属性中提取电子邮件——导致不匹配，从而阻止访问。本指南将介绍如何识别问题、修复属性映射以及清理任何副作用。

**适用于：**使用 SCIM 配置的企业计划和控制台组织。Team 计划没有 SCIM 配置，因此不适用此不匹配场景——请参阅**[设置 JIT 或 SCIM 配置](https://support.claude.com/en/articles/13133195)**了解各计划的可用功能。

---

## 症状

人员在尝试通过 SSO 访问您的组织时可能会遇到以下一种或多种情况：

- **“账户创建被阻止”**——该人员通过 SSO 进行身份验证，但 Claude 找不到匹配的已配置账户。如果限制了组织创建（推荐），该人员将被完全阻止。

- **登陆到免费个人账户**——如果未限制组织创建，该人员将绕过您的组织并创建或登陆到免费个人账户。

- **“检查您登录的账户”不匹配**——SSO 回调显示的电子邮件与该人员在登录时输入的电子邮件不同。

- **Claude Code 身份验证失败**——Claude Code CLI 在身份验证流程中显示电子邮件不匹配错误。

---

## 发生原因

Microsoft Entra ID 用户账户有多个类似电子邮件的属性，可以保存*不同的值*。SCIM 配置和 SSO 身份验证在不同的管理区域中配置，每个都可以从不同的属性中提取：

| **Entra 属性**        | **典型值**                              | **常用于**             |
| ------------------- | ------------------------------------ | ------------------- |
| `userPrincipalName` | `testuser1@example.com`（可能是员工 ID 格式） | 默认 SCIM userName 映射 |
| `mail`              | `test.user.one@example.com`（标准电子邮件）  | OIDC / SAML 电子邮件声明  |
| `proxyAddresses`    | `SMTP:test.user.one@example.com`     | Exchange / M365 主地址 |
| `otherMails`        | 可能包含别名或辅助地址                          | 替代联系电子邮件            |

当 SCIM 从一个属性提取电子邮件而 SSO 从另一个属性发送电子邮件时，就会发生不匹配。即使是细微的差异也会阻止访问——Claude 需要**完全匹配的字符串**。

**常见混淆：**Entra 有两个独立的管理区域。**SCIM 配置应用**位于**企业应用程序**下（Microsoft 对集成应用的术语——与您的 Claude 计划无关）。**SSO/OIDC 应用**位于**应用注册**下。IT 管理员经常导航到错误的位置。

---

## 诊断步骤

### 步骤 1——确认不匹配

1. **检查 SCIM 电子邮件：**在 Entra 管理中心 → **企业应用程序 → [Claude SCIM 应用] → 配置 → 配置日志**中，找到最近配置的人员并检查**修改的属性**。映射到 emails[type eq “work”].value 的值是 SCIM 发送给 Claude 的内容。

2. **检查 SSO 电子邮件：**在**企业应用程序 → [Claude 应用] → 单一登录 → 属性和声明**中，找到电子邮件声明。对于 OIDC 应用，检查**应用注册 → [Claude 应用] → 令牌配置**。

3. 如果两个源属性指向**不同的字段**，您已确认不匹配。

### 步骤 2——确定范围

- 如果**大多数或所有**已配置的人员共享相同的格式不匹配，这是一个**系统属性映射问题**。修复方法在 SCIM 属性映射配置中。

- 如果只有**一两个人**受到影响，请直接在 Entra 中检查他们的用户配置文件。

### 步骤 3——检查 OIDC 令牌声明（仅限 OIDC 应用）

1. 在 Entra 管理中心，转到**应用注册**（不是企业应用程序）。

2. 找到 Claude OIDC 应用并单击“令牌配置。”

3. 检查电子邮件可选声明。

4. 与您的 SCIM 属性映射交叉引用以确认它们是否匹配。

---

## 解决方案

### 修复 SCIM 属性映射

导航到**SCIM 配置应用**——不是 SSO/OIDC 应用：

1. 转到**Entra 管理中心 → 企业应用程序**。

2. 搜索 Claude SCIM 应用。查找具有**配置**部分的应用。

3. 单击**配置 → 编辑配置 → 属性映射**。

4. 找到 SCIM 属性为 emails[type eq “work”].value 的行。单击它进行编辑。

5. 将**源属性**更改为与 SSO 发送的内容匹配——通常是 mail。

6. 还要检查 userName 映射，如果需要则更新。

7. 单击“保存。”

### 触发完整配置同步

**需要完整同步——增量同步不起作用。**您必须触发配置周期的**完整重启**。

1. 转到**配置**概览页面。

2. 单击**重启配置**。

3. 等待同步完成。

4. 在配置日志中验证电子邮件已更新为正确的格式。

---

## 修复后清理

更正属性映射并完成完整同步后：

- **流氓免费账户：**如果在修复前未限制组织创建，某些人员可能已创建免费个人 Claude 账户。请联系**[我们的支持团队](https://support.claude.com/en/articles/9015913-how-to-get-support)**进行删除。

- **幽灵账户（错误电子邮件席位）：**最初配置的具有不正确电子邮件的账户可能仍然存在于您的组织中，占用永远无法使用的席位。请联系我们的支持团队以取消配置这些账户。

- **席位可用性：**如果幽灵账户占用了所有合同席位，即使映射已修复，新登录也会因席位不足错误而失败。

- **重新添加受影响的人员：**删除幽灵账户后，具有更正电子邮件的人员可能需要重新邀请或重新配置。

- **防止将来发生：**在您的组织的身份和访问设置中启用“限制组织创建”。

---

## 验证

1. 检查已配置人员的样本——确认配置日志中的电子邮件与 SSO 发送的电子邮件格式匹配。

2. 要求受影响的人员清除 claude.ai 的浏览器 Cookie，然后通过 SSO 登录。他们应该直接登陆到您的组织工作区。

3. 确认人员未创建免费账户——在限制组织创建的情况下，被阻止的人员会看到清晰的错误，而不是登陆到个人账户。

4. 如果 Claude Code 受到影响，让该人员重新运行 `claude auth login --enterprise` 并确认电子邮件与其配置的席位匹配。

## 常见问题

| **问题**                                | **解决方案**                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------ |
| SCIM 映射已更新但未检查 SSO 声明（或反之）            | 两者都必须更新。SCIM 在**企业应用程序 → 配置**下；SSO 声明在**单一登录 → 属性和声明**或**应用注册 → 令牌配置**下。 |
| userPrincipalName 采用员工 ID 格式，不是真实电子邮件 | 将 SCIM 切换为使用 mail 属性。                                                    |
| 增量同步运行但电子邮件未更新                        | 属性映射更改后需要**重启配置**。                                                       |
| OIDC 应用电子邮件声明未配置为可选声明                 | 在**应用注册 → 令牌配置**下添加电子邮件。                                                 |
| 电子邮件已更新但人员仍无法登录                       | 查找流氓免费组织或幽灵账户。清除浏览器 Cookie 并重试。                                          |
