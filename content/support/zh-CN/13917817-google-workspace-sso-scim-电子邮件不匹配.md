# Google Workspace SSO/SCIM 电子邮件不匹配

Claude 使用电子邮件作为主要标识符来匹配 SSO 登录与已配置的席位。在 Google Workspace 中，SCIM 自动配置和 SAML SSO 可能会发送不同的电子邮件值——尤其是当用户拥有电子邮件别名时——导致不匹配，从而阻止访问。

**适用于：**使用 SCIM 配置的企业计划和 Console 组织。Team 计划没有 SCIM 配置，因此不适用此不匹配情况——请参阅**[设置 JIT 或 SCIM 配置](https://support.claude.com/en/articles/13133195)**了解各计划的可用功能。

---

## 症状

用户在尝试通过 SSO 访问您的组织时可能会遇到以下一种或多种情况：

- **“账户创建被阻止”**——用户通过 SSO 进行身份验证，但 Claude 找不到匹配的已配置账户。如果您的组织限制了组织创建（推荐），该用户将被完全阻止。

- **登陆到免费个人账户**——如果未限制组织创建，用户将完全绕过您的组织，创建或登陆到免费个人账户，而不是其已配置的席位。

- **“检查您登录的账户”不匹配**——SSO 回调显示的电子邮件与用户在登录时输入的电子邮件不同。

- **Claude Code 身份验证失败**——Claude Code CLI 在身份验证流程中显示电子邮件不匹配错误，阻止用户连接到您的组织。

---

## 发生原因

Google Workspace 账户有一个主电子邮件和可能有多个别名。SCIM 配置和 SAML SSO 在 Google 管理控制台中单独配置，可以从不同的地址字段提取：

| **Google 属性**  | **典型值**                                         | **常用于**          |
| -------------- | ----------------------------------------------- | ---------------- |
| `primaryEmail` | `test.user.one@example.com`                     | 建议用于 SCIM 和 SAML |
| 电子邮件别名         | `testuser1@example.com`、`t.userone@example.com` | 有时在 SCIM 中被错误映射  |
| 自定义架构字段        | 按组织定义的自定义属性                                     | 高级属性映射           |
| 组织单位电子邮件       | OU 派生的地址变体                                      | 在复杂的组织结构中很少见     |

最常见的不匹配：SCIM 配置为发送别名地址，而 SAML 发送主电子邮件（或反之）。由于别名和主电子邮件是不同的字符串，Claude 无法匹配它们。Claude 需要**完全字符串匹配**。

**常见混淆：**在 Google 管理控制台中，SCIM 自动配置设置和 SAML 属性映射位于同一应用内的不同选项卡上。管理员有时会更新其中一个而忽略另一个。请验证两个位置。

---

## 诊断步骤

### 步骤 1——确认不匹配

1. **检查 SCIM 电子邮件：**在 **Google 管理控制台**中，转到 **应用 → Web 和移动应用 → [Claude 应用] → 自动配置**。检查哪个属性映射到发送给 Claude 的电子邮件字段。

2. **检查 SAML 电子邮件：**在同一应用中，转到 **SAML 属性映射**部分。找到映射到电子邮件的属性并记下其来源。

3. **检查特定人员：**在 **目录 → 用户 → [用户]** 中，比较 **主电子邮件**与任何列出的 **别名电子邮件**。

### 步骤 2——确定问题范围

- 如果**大多数或所有**已配置的人员共享相同的电子邮件格式不匹配，这是一个**系统属性映射问题**。解决方案在您的 IdP 的 SCIM 属性映射中。

- 如果只有**一两个人**受到影响，问题可能特定于这些账户。直接检查他们的个人资料。

### 步骤 3——检查 SAML 配置中的名称 ID

1. 在应用设置中，转到 **SAML → 服务提供商详情**。

2. 确认**名称 ID**设置为**基本信息 → 主电子邮件**。

3. 如果名称 ID 设置为自定义架构字段或别名，它可能会发送与 SCIM 不同的值。

---

## 解决方案

### 将两个映射对齐到 primaryEmail

Google Workspace 的 primaryEmail 是 SCIM 和 SAML 最可靠的来源。

1. **更新 SCIM 配置：**在 **应用 → Web 和移动应用 → [Claude 应用] → 自动配置 → 属性映射**中，确保电子邮件属性映射到 primaryEmail。

2. **更新 SAML 名称 ID：**在 **SAML → 服务提供商详情**中，将**名称 ID**设置为**基本信息 → 主电子邮件**。

3. **更新 SAML 属性映射：**在**属性映射**步骤中，确保电子邮件属性映射到**基本信息 → 主电子邮件**。

4. 保存所有更改。

### 触发完整重新同步

**关键——需要完整同步：**增量同步*不会*在您更改属性映射后更新现有记录。您必须触发配置周期的**完整重启**。

1. 在 Google 管理控制台中，转到应用的**自动配置**设置。

2. 暂时暂停配置，然后重新启用。这会触发所有已分配人员的完整同步。

3. 或者，从应用分配中删除并重新添加受影响的人员，以强制其个人记录重新配置。

4. 监控配置日志中的错误，并在要求用户重试之前确认电子邮件已更新以匹配 SAML 格式。

---

## 修复后清理

更正属性映射并完成完整同步后：

- **流氓免费账户：**如果在修复前未限制组织创建，某些用户可能已无意中创建了免费个人 Claude 账户。请联系**[我们的支持团队](https://support.claude.com/en/articles/9015913)**将其删除。

- **幽灵账户（错误电子邮件席位）：**原始配置的具有不正确电子邮件的账户可能仍然存在于您的组织中，占用席位。请联系我们的支持团队取消配置这些账户。

- **席位可用性：**如果幽灵账户占用了所有合同席位，新登录将失败并显示席位不足错误。取消配置幽灵账户会释放这些席位。

- **重新添加受影响的人员：**删除幽灵账户后，具有更正电子邮件的人员可能需要重新邀请或重新配置。

- **防止未来发生：**在您的组织的身份和访问设置中启用“限制组织创建”。这可以防止尚未配置的人员意外创建免费个人账户。

---

## 验证

1. 检查已配置人员的样本——确认配置日志中的电子邮件与 SSO 发送的电子邮件格式匹配。

2. 要求受影响的人员清除 claude.ai 的浏览器 Cookie，然后通过 SSO 登录。他们应该直接登陆到您的组织工作区，不会出现任何错误。

3. 确认用户未创建免费账户——限制组织创建后，被阻止的用户会看到清晰的错误，而不是登陆到个人账户。

4. 如果 Claude Code 受到影响，让用户重新运行 `claude auth login --enterprise` 并确认电子邮件与其已配置的席位匹配。

## 常见问题

| **问题**                          | **解决方案**                              |
| ------------------------------- | ------------------------------------- |
| SCIM 发送别名，而 SAML 发送主电子邮件        | 始终对两者使用 `primaryEmail`。               |
| 未检查 SAML 设置中的名称 ID              | 名称 ID 字段确定登录时发送的电子邮件。这与属性映射部分分开。检查两者。 |
| 某些人的自定义架构字段为空                   | 坚持使用标准 Google 属性，如 `primaryEmail`。    |
| 映射更改后重新配置不会自动触发                 | 您可能需要手动暂停并重新启用配置以强制完整同步。              |
| 某人的主电子邮件已更改，但旧电子邮件仍显示在 Claude 中 | 主电子邮件更改后需要完整重新同步。                     |
| SCIM 中的电子邮件已更新，但用户仍无法登录         | 检查流氓免费组织或幽灵账户。清除浏览器 Cookie 并重试。       |

## 何时联系支持

当出现以下情况时，请使用您的组织域、受影响人员的电子邮件和属性映射的屏幕截图联系**[我们的支持团队](https://support.claude.com/en/articles/9015913)**：

- SCIM 和 SSO 属性看起来相同，但用户仍无法访问其席位。

- 您需要确认 Claude 在 SCIM 配置期间为特定人员记录的电子邮件。

- 您需要帮助清理幽灵账户或流氓免费组织。

- 用户遇到席位不足错误，尽管有可用的合同席位。
