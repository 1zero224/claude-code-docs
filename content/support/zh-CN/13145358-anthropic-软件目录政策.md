# Anthropic 软件目录政策

Anthropic 允许用户通过目录、存储库、界面或类似的服务（统称为"目录"）发现高质量的 Model Context Protocol 服务器、技能文件夹、插件、应用程序和其他软件、容器或数据（"软件"），这些软件可在 Claude 中无缝运行。我们审查提交到目录的内容，以确保它们符合我们在安全性、安全保障和与 Anthropic 服务及其他软件兼容性方面的标准。我们对软件进行初始和持续审查，可能要求开发者解决合规问题以继续被纳入我们的目录。所有软件必须保持对这些要求的合规性，包括任何未来的更改，才能保留在我们的目录中。

# 1. 安全性和安全保障

A. 软件不得违反或促进违反我们的[使用政策](https://www.anthropic.com/legal/aup)，包括围绕法律、医疗保健、保险、金融和其他领域的高风险用例。所有软件必须符合我们的通用使用标准和高风险用例要求，以及我们关于 [Anthropic 目前支持的国家和地区](https://www.anthropic.com/supported-countries)的政策。

B. 当软件提供高风险用例时，开发者必须遵守人工干预措施，并向消费者提供直接披露（如我们的 [AUP](https://www.anthropic.com/legal/aup) 中所述），才能被纳入我们的目录。

C. 软件不得规避或使用户能够绕过 Claude 的安全防护、系统指令或沙箱环境。

D. 软件必须优先保护用户隐私和第三方的隐私权益。开发者必须谨慎处理个人和其他敏感数据，遵循隐私最佳实践，并确保符合适用法律。

E. 软件只能从用户的上下文中收集执行其功能所需的数据。软件不得收集无关的对话数据，即使是出于日志记录目的。

F. 软件不得侵犯他人的知识产权。

G. 软件不得查询或提取 Claude 的记忆、聊天历史、对话摘要或用户生成或上传的文件中的数据，也不得持久存储或使用对话内容来构建用户档案或尝试对 Claude 的跨会话行为进行任何更改。

# 2. 兼容性

本部分适用于通过自然语言描述为 Claude 提供工具或功能的软件，包括 MCP 服务器、技能文件夹和类似软件（"指令软件"）。

A. 指令软件必须通过狭义、明确的自然语言定义每个工具或功能，指定其功能和何时应调用它。

B. 指令软件工具或功能描述必须精确匹配实际功能，确保指令软件在正确和适当的时间被调用。描述不得包含意外功能或承诺未交付的功能。

C. 指令软件工具或功能描述不得与我们目录中的其他软件造成混淆或冲突。

D. 指令软件不得故意调用或强制 Claude 调用其他外部软件、工具、数据库或资源，除非用户请求和打算这样做。同样，指令软件工具或功能描述不得以故意导致其他软件无关调用它们的方式编写。

E. 指令软件不得尝试干扰 Claude 调用来自其他软件、工具、数据库或资源的工具，除非用户请求和打算这样做。

F. 指令软件不得指导 Claude 从外部来源动态提取行为指令以供 Claude 执行。

G. 指令软件不得包含隐藏、混淆或编码的指令。所有行为指导必须是人类可读的，并清晰呈现。

# 3. 开发者要求

A. 收集用户数据或连接到远程服务的软件开发者必须提供清晰、易于访问的隐私政策链接，说明数据收集、使用和保留情况。开发者必须向 Anthropic 提供所有适用隐私政策的链接，并确保根据法律要求向用户呈现此类政策。

B. 开发者必须为有产品或安全问题的用户提供经过验证的联系信息和支持渠道。

C. 开发者必须记录其软件的工作方式、预期用途以及用户如何排除故障。

D. 开发者必须为 Anthropic 提供带有示例数据的标准测试账户，以验证完整的软件功能。

E. 开发者必须提供至少三个有效的提示或用例示例，以演示核心功能。

F. 开发者必须验证他们拥有或控制其软件连接到的任何 API 端点、域或用户界面，以及它检索或呈现的任何外部资源。插件是例外，可以连接到软件目录中批准的任何连接器。

G. 开发者必须维护其软件并在合理的时间范围内解决问题。

H. 开发者必须在软件被纳入目录后，将其功能、工具或功能描述、数据实践或连接端点的重大更改通知 Anthropic。重大更改可能需要重新审查。

I. 开发者必须同意我们的 [软件目录条款](https://support.claude.com/en/articles/13145338-anthropic-software-directory-terms)，并遵循 Anthropic 发布的适用于软件的设计指南。

# 4. 不支持的用例

除非我们另有明确书面许可，否则我们不允许具有某些功能的软件进入我们的目录。随着我们的目录和 Anthropic 服务的发展，我们可能会重新考虑这些限制。

A. 在没有人工干预保障措施的情况下，转移资金或其他金融资产或代表用户自主执行金融交易的软件。我们通常不允许加密货币软件进入我们的目录。

B. 使用 AI 模型生成图像、视频或音频内容的软件。只有使用 AI 模型专门创建视觉辅助工具（如幻灯片、图表、图表、UI 模型、徽标或其他设计资产）的设计重点图像软件才被允许。这些服务器可以作为仅设计工作流的一部分生成图像，前提是开发者不在我们的产品中提供独立的图像生成服务。这包括：

a. 视频生成模型（文本到视频、使用 AI 的视频扩展、视频编辑、视频到视频、视听生成）

b. 音频和语音模型（语音到语音/原生音频模型、文本到语音、音乐模型）

c. 非纯设计重点的图像生成模型（文本到图像、图像编辑、人物生成功能）

C. 提供 [广告](https://www.anthropic.com/news/claude-is-a-space-to-think)、赞助内容、付费产品展示位置或主要作为广告或宣传工具存在的软件。

D. 主要向用户提供成人和/或性内容（18+ 内容）的软件。

E. 可能将用户重定向以规避我们的防护措施并违反我们的 AUP 以进行高危害滥用的软件。

# 5. Model Context Protocol 服务器的其他要求

A. MCP 服务器必须优雅地处理错误并提供有用的反馈，而不是通用错误消息。

B. MCP 服务器必须节约使用令牌。给定工具调用使用的令牌数量应大致与任务的复杂性或影响相当。在可能的情况下，应向用户提供排除不必要文本的选项。

C. MCP 工具名称不得超过 64 个字符。

D. 连接到远程服务并需要身份验证的远程 MCP 服务器必须使用具有来自公认权威机构的证书的安全 OAuth 2.0。

E. MCP 服务器必须为其工具提供所有适用的 [注释](https://modelcontextprotocol.io/specification/2025-11-25/schema#toolannotations)，特别是 *readOnlyHint*、*destructiveHint* 和 *title*。

F. 远程 MCP 服务器应支持 [可流式 HTTP](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports#streamable-http) 传输。服务器可能暂时支持 [SSE](https://modelcontextprotocol.io/specification/2024-11-05/basic/transports#http-with-sse)，但将来会被弃用。

G. 本地 MCP 服务器必须使用所有依赖项的合理当前版本构建，包括 *node_modules* 中的包。

查看此政策的先前版本：[Anthropic MCP 目录政策](https://support.claude.com/en/articles/11697096-anthropic-mcp-directory-policy)。
