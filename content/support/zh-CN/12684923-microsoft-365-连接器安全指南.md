# Microsoft 365 连接器安全指南

Microsoft 365 连接器是一个**由 Anthropic 托管的集成**，使 Claude 能够通过用户委派权限安全地访问 Microsoft 365 服务（Outlook、SharePoint、OneDrive、Teams）。Anthropic 已完成 Microsoft 的发布者验证流程，将我们经过验证的 Microsoft 合作伙伴网络账户与这些应用程序关联，以确认我们的组织身份。

Microsoft 365 连接器可在所有 Claude 计划上使用：免费版、专业版、Max、Ultra、Team 和企业版。

本指南为每种账户类型都有一个部分：

- **[工作或学校账户](#h_887146248e)**

- **[个人 Microsoft 账户](#h_66d5bff0e6)**

## 工作或学校账户

连接器作为**安全代理**运行，您的 Microsoft 365 文档、电子邮件和文件保留在您的租户中。连接器仅在活跃查询期间按需检索数据，不缓存文件内容。凭据由 Anthropic 的后端基础设施加密和管理。MCP 服务器本身不存储或管理这些凭据。Microsoft 的 Azure SDK 处理代表用户的令牌交换和缓存，用于访问 Graph API。

### 限制访问

连接器提供**多层访问控制**以满足您的安全需求。有关 Microsoft 365 连接器管理的详细信息，请参阅**[设置 Microsoft 365 连接器](https://support.claude.com/en/articles/12542951-set-up-the-microsoft-365-connector)**。

**1. Microsoft Entra 租户要求**

连接工作或学校账户的人员必须使用与 Microsoft Entra 租户关联的 Microsoft 365 账户进行身份验证，在所有 Claude 计划上都是如此。Microsoft Entra 全局管理员必须完成一次性同意流程，然后租户中的任何人才能连接。

**2. 组织级别限制（Team 和企业计划）**

在 Team 和企业计划上，访问连接器需要两步审批流程。首先，所有者必须通过导航到“组织设置”>“连接器”>“浏览连接器”>“添加 “Microsoft 365””，在 Claude 组织设置中明确启用 Microsoft 365 连接器。在授予此批准之前，团队成员无法访问。

其次，所有者启用连接器后，Microsoft Entra 全局管理员必须完成个人身份验证并代表整个组织授予同意，然后任何团队成员才能连接。

**3. 细粒度权限撤销**

您可以通过 Microsoft Entra 管理中心选择性地禁用特定功能。例如：

| **限制**       | **操作**                                                         | **效果**                |
| ------------ | -------------------------------------------------------------- | --------------------- |
| 所有访问         | 在 Claude 组织设置中禁用连接器                                            | 完全关闭                  |
| 仅 SharePoint | 在 Entra 中撤销 Sites.Read.All 权限                                  | 阻止 SharePoint         |
| 电子邮件访问       | 在 Entra 中撤销 Mail.Read 权限                                       | 阻止 Outlook            |
| Teams 聊天     | 在 Entra 中撤销 Chat.Read 权限                                       | 阻止 Teams              |
| Teams 消息（写入） | 在 Entra 中撤销 ChatMessage.Send、ChannelMessage.Send 和 Chat.Create | 阻止 Claude 发送 Teams 消息 |
| OneDrive 文件  | 撤销 Files.Read 和/或 Files.Read.All                               | 阻止从 OneDrive 读取文件     |

更改对组织中的所有人立即生效。人员也可以在聊天期间通过选择性地关闭连接器的工具来禁用功能。

**4. Microsoft 条件访问**

您的条件访问策略适用于连接器，但不一定以它们适用于直接在 Microsoft 365 中工作的用户的方式适用。当用户连接时，Entra 根据其登录评估您的策略。之后的每个请求都由 Claude 的服务器发出。在我们的测试中，Entra 将这些请求评估为来自**[Anthropic 的出站 IP 地址](https://platform.claude.com/docs/en/api/ip-addresses#outbound-ip-addresses)**，识别成员并携带他们连接时记录的设备，而不是成员的当前设备或网络。这对每种策略类型的含义如下：

- **基于组的访问**：支持。将您的策略范围限定为特定安全组，或在**[设置 Microsoft 365 连接器](https://support.claude.com/en/articles/12542951-set-up-the-microsoft-365-connector)**中所述的两个 Claude 应用程序上设置**需要分配**。

- **多因素身份验证 (MFA)**：支持。当成员登录以连接时强制执行 MFA。如果您的 MFA 策略不适用于连接器登录，例如因为它针对特定应用程序或具有可以在那里跳过 MFA 的条件，请创建一个没有条件的单独策略，要求对两个 Claude 应用程序进行 MFA。

- **设备合规性**：支持，但检查时间有所不同。在我们的测试中，策略根据成员连接的设备进行评估。不符合策略的设备不会在连接屏幕处被阻止；其请求从之后的第一个工具调用开始失败。连接随后携带该设备记录，持续访问根据记录而不是当前使用的设备进行检查，直到成员下次重新连接。每个成员最近的连接是计数的。仅当成员的浏览器可以向 Entra 证明设备时才创建记录，因此使用未登录到您的组织的浏览器配置文件的合规设备被视为不合规。被阻止的成员（`AADSTS53000`）可以通过从符合策略的设备重新连接，在登录到您的组织的浏览器中来修复。保持策略分配给 Claude 应用程序；排除它们会移除检查。

- **位置和网络限制**：不支持。在我们的测试中，服务器端请求始终显示为来自 Anthropic 的 IP 范围，无论成员在哪里，因此限制登录到您的网络或 VPN 的策略会为每个成员阻止连接器。同样适用于登录频率策略。了解如何在**[设置 Microsoft 365 连接器](https://support.claude.com/en/articles/12542951-set-up-the-microsoft-365-connector)**中排除 Anthropic 的 IP 范围。

**警告：**不要将设备策略更改为要求合规设备*或*多因素身份验证作为解决方法。在我们的测试中，MFA 证明以相同的方式通过存储的连接进行，因此策略最终可能对每个成员都满足，设备要求停止做任何可靠的事情。

要阻止成员将工作 Microsoft 365 账户连接到组织外的 Claude 账户，请启用**[将已验证域连接器限制到您的企业](https://support.claude.com/en/articles/15402193-restrict-verified-domain-connectors-to-your-enterprise)**。

**5. 用户级权限**

- Microsoft 365 连接器使用**[委派权限](https://learn.microsoft.com/en-us/graph/permissions-overview?tabs=http#delegated-permissions)**。

- 用户只能访问他们**已有权限**的 Microsoft 365 数据

- SharePoint 搜索需要 Sites.Read.All 权限。不支持特定于站点的权限设置（使用 *.Selected 权限），因为底层搜索是租户范围的。

- 用户无法绕过 SharePoint 共享设置或文件夹权限。

- 用户无法访问其他用户的私人文件或电子邮件。用户可以搜索他们在 Microsoft 365 中被授予委派访问权限的共享邮箱，包括完全访问权限和文件夹级别的委派。共享邮箱访问保持只读状态，通过 `Mail.Read.Shared` 权限。电子邮件搜索无法访问用户的单独的在线存档（就地存档）邮箱。

- 委派权限意味着 Claude 以用户自己的访问权限行动。连接器不会自行评估您的 Microsoft Purview 数据丢失防护 (DLP) 策略。

**6. 令牌管理**

- 刷新令牌在默认情况下在 90 天不活动后过期，需要重新身份验证。这可以在 Microsoft Entra ID 中使用令牌生命周期策略进行自定义。

- 访问令牌通常在 Microsoft Entra ID 默认设置下在 60-90 分钟内过期，并自动刷新。

- 管理员或用户可以随时通过 Microsoft Entra ID 撤销访问权限。

- Microsoft 365 连接器不会查看或存储密码。

**7. 敏感度标签（测试版，企业计划）**

所有者和主要所有者可以连接 Microsoft Entra 租户并选择 Microsoft Purview 敏感度标签进行阻止。连接器随后在将内容提供给 Claude 之前检查 SharePoint 和 OneDrive 文件、电子邮件和电子邮件附件：

- **读取和更改：**连接器拒绝具有被阻止标签的文件或电子邮件，以及其标签无法确定的文件或电子邮件。当 Microsoft 报告任何标签时，它拒绝替换文件的内容。

- **搜索：**仅当 Microsoft 的搜索索引包含该标签时，结果才会排除被阻止的项目。在此之前，搜索可以返回被阻止文件的名称或被阻止电子邮件的主题、发件人、收件人和日期。

- **列表：**邮件文件夹列表排除被阻止的电子邮件和连接器无法确定其标签的电子邮件。SharePoint 和 OneDrive 文件夹列表仍显示被阻止文件的名称、大小、修改时间和链接。

- **检查运行位置：**对于 SharePoint 或 OneDrive 文件，连接器在下载文件前读取标签。Microsoft 的搜索结果可以包含文件的简短摘录。连接器在 Claude 看到它之前将其删除。对于电子邮件或附件，连接器的服务器检索项目以读取其标签，如果被阻止或其标签无法确定，则将其从 Claude 中扣留。

- **范围：**标签对从租户使用工作或学校帐户连接的所有人被阻止。对于从另一个租户或使用个人帐户连接的人，它们不被阻止。

- **未检查且未阻止：**Office、PDF 和 MP4 以外的文件类型（如文本文件、图像和存档）、未被阻止的电子邮件上的图像和文本附件、日历事件、Teams 消息、会议记录、SharePoint 页面和列表、Claude 移动、复制或删除的文件夹内的文件、回复中的引用文本以及 Claude 创建的内容。

- 请参阅 **[通过敏感度标签阻止 Claude 中的文件和电子邮件](https://support.claude.com/en/articles/18549037-block-files-and-email-from-claude-by-sensitivity-label)**。

### 安全架构摘要

**身份验证流程**

- **OAuth 2.0 代表流程 (OBO)：**行业标准的委派身份验证

- **PKCE 保护**：公共客户端使用代码交换证明密钥来防止授权代码拦截

- **两阶段令牌交换**：用户进行身份验证以获取 MCP 服务器的访问令牌，然后 MCP 服务器使用 OBO 流与机密客户端凭据交换它以获取 Graph API 访问权限。在此流程中，甚至用户或其 Claude 客户端都无法访问 OBO 令牌。只有 MCP 服务器可以访问和使用具有通过 Microsoft Graph API 访问用户数据权限的令牌。

- **无凭据存储**：用户永远不会与 Anthropic 共享 Microsoft 密码

- **加密令牌存储**：访问和刷新令牌在由 Claude 后端缓存时被加密

**数据流**

- 文档和其他内容仅在**活跃查询期间**检索

- 连接器的**工具调用结果**是**存储聊天的一部分时被保留**

- **请求 Claude 聊天的用户**可以看到工具调用结果和 Claude 的响应，其中包含数据

- **在聊天上共享的其他用户**只能看到 Claude 的响应，其中包含工具调用结果

- 每个请求创建一个新的数据流，在返回响应后进行清理

**多租户隔离**

- Microsoft Entra 租户使用通用范围的多租户配置**在密码学上彼此分离**

- 多租户隔离通过数字签名的访问令牌在密码学上强制执行，该令牌将每个用户绑定到其组织的租户

此限制不适用于在 2026 年 11 月 9 日之后首次添加 Microsoft 365 连接器的组织。在这些组织中，管理员可以将这些工具中的每一个设置为**始终允许**、**需要批准**或**已阻止**，就像任何其他写入工具一样。删除连接器并重新添加通常会保留组织的原始安装日期，因此通常不会改变限制是否适用。其他组织中看到这些工具通知的管理员可以立即在**审查写入工具**、**审查工具限制**或**工具**选项卡中将其设置为**始终允许**。管理员将每个工具设置为**始终允许**后，该限制立即结束，用户可以为其选择**始终允许**。某些用户可能在过去为该工具选择过**始终允许**。该早期选择可以立即生效，因此 Claude 可以停止询问他们。Claude 默认会询问其他所有人，直到他们做出选择。

如果组织有多个 Microsoft 365 连接器，该工具必须在每个连接器上保存。在 2026 年 11 月 9 日之前保存的**始终允许**不会结束限制，直到管理员再次保存。对于其余这些工具，用户必须继续批准每次使用，直到限制在 2026 年 12 月 9 日或之后被移除。管理员到那时未设置的任何这些工具将更改为**需要批准**，除非整个连接器设置为**已阻止**。

启用了 HIPAA 的组织不属于这些默认阻止和限制的更改：他们不会收到通知，设置**始终允许**或首次添加连接器都不会结束此限制。

在 Cowork 中，只有当组织设置**允许连接器工具的“始终允许”**打开时，用户才能选择**始终允许**。管理员保存的更改立即应用。设置为**始终允许**的工具如果默认被阻止，会立即打开。使用**始终允许**，Claude 可能会在不先询问任何人的情况下使用工具，包括在“自动批准”模式和某些计划任务中，例如设置为“自动批准”的云计划任务或 Claude Code 例程。计划任务可能会失去对**需要批准**工具的访问权限。在 Free、Pro、Max 和 Ultra 计划中，用户可以为这些工具选择**始终允许**。

当组织启用写入工具时，连接器还会公开用于发送和组织电子邮件、管理草稿和日历事件、更新邮箱设置、在 OneDrive 和 SharePoint 中创建和更新文件以及发送 Teams 消息的写入工具。在 2026 年 9 月 Teams 写入工具推出之前添加连接器的组织中，管理员可以在**[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)**中的“Microsoft 365”内单独设置每个 Teams 写入工具。如果 Teams 写入工具默认被阻止，将连接器的默认限制设置为“无限制”不会打开它。Claude 可以在 Teams 中发送消息，但无法更改 Teams 设置、成员身份或权限。

写入工具包括以下内置保护措施：

**归属。**Claude 发送的电子邮件包含标识为代理启动的归属标头。文件写入、日历写入和 Teams 消息目前未标记。

**速率限制。**按用户限制适用于写入、发送和收件人。

**附件限制。**任何写入工具都不支持附件——发送、转发和草稿都会拒绝带有附件的消息。

**默认阻止至少到 2026 年 12 月 9 日。**在写入工具或 Teams 写入工具推出之前使用连接器的组织默认阻止了某些写入工具。管理员现在可以在**[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)**中为这些工具中的每一个选择设置。

在 2026 年 12 月 9 日或之后，管理员未更改的任何这些工具将设置为**需要批准**，除非整个连接器设置为**已阻止**。如果这些工具之一属于 Anthropic 将在该日期或之后移除限制的 11 个 Outlook、日历和 Teams 工具，管理员现在可以将其设置为**始终允许**。它会立即打开。

一旦在组织的每个 Microsoft 365 连接器上保存，该工具的限制就会结束，成员可以为其选择**始终允许**。Claude 随后可能会在不先询问任何人的情况下使用它，包括在“自动批准”模式和某些计划任务中，例如设置为“自动批准”的云计划任务或 Claude Code 例程。计划任务可能会失去对**需要批准**工具的访问权限。启用了 HIPAA 的组织不属于这些默认阻止和限制的更改。

**需要确认。**在“自动批准”和“跳过所有批准”模式之外，在聊天和 Cowork 中，Claude 会要求用户确认，然后才能发送或转发电子邮件、发送 Teams 消息、创建、更改、删除或响应日历事件，或设置自动回复。在**[“自动批准”模式](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork#h_c274f6c9b5)**中，这些操作可以在不询问用户的情况下运行，除非自动检查将其标记为有风险或用户的组织需要批准。检查可能会遗漏有风险的操作。要批准它们，用户可以使用手动或将工具的权限设置为**[“始终询问”](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork#h_c274f6c9b5)**（如果该选项可用）。在 Team 和 Enterprise 计划中，除非管理员在 2026 年 11 月 9 日或之后将该工具设置为**始终允许**，否则用户无法为这些工具选择**始终允许**。否则用户确认每次使用。例外是在 2026 年 11 月 9 日之后首次添加 Microsoft 365 连接器的组织。在这些组织中，管理员可以将这些工具中的每一个设置为**始终允许**、**需要批准**或**已阻止**，当管理员将工具设置为**始终允许**时，每个用户可以为其选择**始终允许**。

在 Cowork 中，只有当组织设置**允许连接器工具的“始终允许”**打开时，用户才能为这些工具选择**始终允许**。删除连接器并重新添加通常会保留组织的原始安装日期，因此通常不会改变限制是否适用。在其他组织中，看到这些工具通知的管理员现在可以将其设置为**始终允许**。管理员将每个工具设置为**始终允许**后，该限制立即结束，每个用户随后可以为其选择**始终允许**。

某些用户可能在过去为该工具选择过**始终允许**。该早期选择可以立即生效，因此 Claude 可以停止询问他们。如果组织有多个 Microsoft 365 连接器，该工具必须在每个连接器上保存。对于其余这些工具，用户必须继续确认每次使用，直到限制在 2026 年 12 月 9 日或之后被移除。

使用**始终允许**，Claude 可能会在不先询问任何人的情况下使用工具，包括在“自动批准”模式和某些计划任务中，例如设置为“自动批准”的云计划任务或 Claude Code 例程。在 Free、Pro、Max 和 Ultra 计划中，在“自动批准”模式之外，Claude 默认会询问，每个用户可以为这些工具中的任何一个选择**始终允许**。Claude 随后会在不询问他们的情况下使用该工具。

启用了 HIPAA 的组织不属于这些默认阻止和限制的更改。

### 当前限制

- **Teams 写入访问仅限于消息传递**：Claude 可以发送聊天消息、在频道中发布或回复，或启动新聊天，但无法修改 Teams 设置、成员身份或权限。所有写入工具都需要管理员启用。

- **仅限用户级访问**：不支持使用服务主体身份验证进行访问。

- **不搜索在线存档邮箱**：电子邮件搜索涵盖每个用户的主邮箱（包括其存档文件夹）和他们可以访问的任何共享邮箱。它不涵盖单独的在线存档邮箱（也称为就地存档），因此保留策略移至该处的邮件不会出现在搜索结果中。

### 常见问题

**我们能否在企业范围推出前用小型试点组进行测试？**

可以。建议的方法是使用应用分配来限制谁可以使用连接器：

- 启用连接器（团队和企业所有者在组织设置中启用；个人计划用户可以直接连接）。

- Microsoft Entra 管理员完成预同意设置

- 使用 Microsoft Entra 企业应用分配来限制对特定用户或组的访问（例如，仅将 “IT 安全测试组” 分配给该应用）。

- 逐步扩展组以进行渐进式部署

**我们如何确保在多租户环境中我们的组织与其他组织之间不会发生数据泄露？**

多租户隔离确保完全分离：

- 服务器使用通用租户配置来接受来自任何 Microsoft Entra ID 租户的令牌

- 每个用户的令牌包含其组织的租户 ID（tid 声明），该 ID 会被验证

- 通过 OBO 获得的 Graph API 令牌会自动限定于用户及其租户

- 跨租户令牌访问通过 Microsoft Graph 的 OAuth 2.0 实现的设计在密码学上被阻止。

**如果有人尝试使用个人 Microsoft 账户连接会发生什么？**

这取决于他们选择的选项：

- **工作或学校选项：**使用个人账户登录会出现身份验证错误。

- **个人账户选项：**在免费、专业、最大和超级计划上，用户可以在此处连接个人账户。此选项不会在团队和企业计划上显示。

详细了解 **[个人 Microsoft 账户](https://support.claude.com/en/articles/15183774-connect-to-microsoft-365#h_cffabf2c6c)**。

**你们是否有合规性审计日志？**

是的。连接器进行的所有 Graph API 调用都记录在你的组织的 Microsoft 365 审计日志中，你可以通过 M365 合规中心访问。这些日志显示时间戳、用户、执行的操作和访问的资源，保留期与你的 Microsoft 365 审计策略相匹配。此外，Anthropic 记录身份验证和工具执行事件。标签阻止拒绝的内容不会在 Claude 的审计日志中记录为单独的事件。对于企业组织，连接或断开 Microsoft Entra 租户以及更改被阻止的标签会记录在你的组织的审计日志中。

**如果我们发现未授权使用，我们能否撤销访问权限？**

有多种撤销方法：

- **个人：**用户通过 **自定义 > 连接器** 断开连接

- **管理员级别**：在团队和企业计划上，所有者在 Claude 组织设置中禁用连接器（影响所有团队成员）。

- **权限级别**：在 Microsoft Entra 管理中心撤销特定权限

- **租户级别**：在 Microsoft Entra 管理中心撤销所有权限

## 个人 Microsoft 账户

在免费、专业、最大和超级计划上，用户可以连接个人 Microsoft 账户，例如 Outlook.com、Hotmail、Live 或 MSN 账户。此选项不会在团队和企业计划上显示。详细了解 **[连接到 Microsoft 365](https://support.claude.com/en/articles/15183774-connect-to-microsoft-365)**。

- **单独的应用程序：**个人账户使用自己的 Microsoft 应用程序，这些应用程序仅接受个人账户。你的租户的应用程序和同意不涉及。

- **同意：**每个人为自己的账户同意。没有管理员步骤，Microsoft Entra 控制（如条件访问和应用分配）不适用。

- **工具：**个人账户获得可用功能中的工具，加上 `search_people`，除了 Teams 工具、`chat_message_search`、`find_meeting_availability`、`outlook_create_filter`、`outlook_delete_filter` 和 `outlook_set_vacation`。`read_resource` 无法读取 Teams 内容。`sharepoint_*` 工具在个人的 OneDrive 上工作，包括他们添加到其中的共享项目，不使用 `Sites.Read.All`。

- **写入工具：**没有管理员设置，因此连接后写入工具可用。归属、速率限制和附件限制仍然适用。可用功能中的 “始终允许” 限制不适用于个人账户。

- **权限：**个人账户请求这些 Microsoft Graph 权限：`User.Read`、`offline_access`、`Mail.Read`、`Mail.ReadWrite`、`Mail.Send`、`MailboxSettings.Read`、`MailboxSettings.ReadWrite`、`Calendars.Read`、`Calendars.ReadWrite`、`Files.Read.All`、`Files.ReadWrite.All` 和 `People.Read`。登录还请求 `openid` 和 `email`，因此 Claude 会收到账户的电子邮件地址。

- **条款：**在免费、专业、最大和超级计划上，此连接受 Anthropic 的 **[消费者服务条款](https://www.anthropic.com/legal/consumer-terms)** 和 **[隐私政策](https://www.anthropic.com/legal/privacy)** 约束。

- **访问移除：**用户在自定义 > 连接器中断开连接，并可以在其 Microsoft 账户中移除权限。

- **数据处理：**连接器按需检索数据，不缓存文件内容。你的电子邮件和文件保留在你的 Microsoft 账户中，但 Claude 检索的内容成为你的聊天的一部分。凭证由 Anthropic 的后端基础设施加密和管理，连接器不会看到或存储密码。存储的聊天中的工具调用结果会被保留。
