# 业务关联协议 \(BAA\) 下的覆盖模型

本文适用于在业务关联协议 (BAA) 下使用 Anthropic HIPAA 就绪服务的组织。它说明了哪些配置是 BAA 下的合格服务，以及您是否可以访问覆盖模型。**您的组织负责确保其对这些服务的使用符合适用的法律义务。**了解**[商业客户的业务关联协议 (BAA)](https://support.claude.com/en/articles/8114513-business-associate-agreements-baa-for-commercial-customers)**和**[覆盖模型](https://support.claude.com/en/articles/15425695-covered-models)**。

**重要提示：**您可以通过以下方式在 Anthropic 的 BAA 下访问覆盖模型：

- 通过 HIPAA 就绪 API

- 通过 HIPAA 就绪企业计划上的聊天

- 通过 HIPAA 就绪企业计划上的**[Claude Code（本地模式）和 Cowork（本地模式）](https://support.claude.com/en/articles/17318731)**，应用 HIPAA 配置到两个产品，Claude Code 不启用零数据保留 (ZDR)

## 覆盖模型和数据保留

**[覆盖模型](https://support.claude.com/en/articles/15425695-covered-models#h_008eefd6e6)**在提供的每个平台上都需要 30 天的数据保留，作为我们安全工作的一部分，无法从启用了零数据保留 (ZDR) 的组织或工作区访问。了解**[覆盖模型的数据保留实践](https://support.claude.com/en/articles/15425996)**。

新发布的覆盖模型在订阅和基于席位的企业计划上分阶段推出，因此模型可能不会立即出现在您的组织中——无需进行配置更改。某些覆盖模型仅在有限访问计划下提供给批准的合作伙伴。

## 如何在 BAA 下访问覆盖模型

要在 BAA 下覆盖的配置中访问覆盖模型：

- **对于 API 工作负载：使用 HIPAA 就绪 API 组织。**此配置使用标准保留运行，因此您的应用程序可以访问覆盖模型。如果您的组织还没有 HIPAA 就绪 API 组织，请联系您的 Anthropic 账户团队进行设置。请注意，Claude Code 不是 HIPAA 就绪 API 组织上的合格服务。了解更多**[关于 HIPAA 就绪 API 访问](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention#hipaa-readiness)**。

- **对于聊天：使用 HIPAA 就绪 Claude 企业计划。**聊天使用标准保留运行，因此可以访问覆盖模型，无需配置更改。如果您的组织尚未在其企业计划上激活 HIPAA 就绪，请在**[HIPAA 就绪企业计划](https://support.claude.com/en/articles/13296973-hipaa-ready-enterprise-plans)**中了解如何操作。

- **对于 Claude Code（本地模式）和 Cowork（本地模式）：使用应用 HIPAA 配置到两个产品的 HIPAA 就绪企业计划。**Anthropic 在标准保留下保留来自两个产品的请求，因此成员可以使用覆盖模型。在**[在 HIPAA 就绪企业计划上使用 Claude Code（本地模式）和 Cowork（本地模式）](https://support.claude.com/en/articles/17318731)**中了解如何获取配置。

**重要提示：**如果未将 HIPAA 配置应用到 Claude Code（本地模式）和 Cowork（本地模式），BAA 仅在启用 ZDR 的情况下覆盖 Claude Code，启用 ZDR 的 Claude Code 无法使用覆盖模型，除非 Anthropic 已明确为您的组织授权。如果没有 HIPAA 配置，Cowork 不是 BAA 下的合格服务。在这些情况下，您可以在 Claude Code 或 Cowork 中使用覆盖模型，但该使用不在您的 BAA 覆盖范围内，因此不要提交受保护的健康信息 (PHI)。

## 如何在 BAA 外访问覆盖模型

要在 BAA 下不覆盖的配置中访问覆盖模型：

- **在启用零数据保留的 1P API 组织上，您有两个选项：**

  - 在专用工作区中启用标准保留：转到**数据保留**页面 (platform.claude.com/settings/privacy)，从页面顶部的下拉菜单中选择工作区。您的其他工作区保持 ZDR。有关说明，请参阅**[Mythos 级模型的数据保留实践](https://support.claude.com/en/articles/15425996-data-retention-practices-for-mythos-class-models#h_7008995545)**。

  - 联系您的 Anthropic 账户团队以从组织中完全移除 ZDR。

- **对于通过启用零数据保留的 Claude 企业版的 Claude Code：**联系您的 Anthropic 账户团队以更改保留设置或设置单独的沙箱组织。您也可以通过具有标准保留的 1P API 组织访问 Claude Code。要改为在 BAA 下使用覆盖模型中的 Claude Code，请将 ZDR 替换为应用到 Claude Code（本地模式）和 Cowork（本地模式）的 HIPAA 配置。请参阅本文中的**如何在 BAA 下访问覆盖模型**。

**注意：**这些配置不在 BAA 覆盖范围内。不要通过它们提交受保护的健康信息 (PHI)。

## 更改配置前

某些组织可能会考虑设置单独的非 ZDR 组织以在 Claude Code、Cowork、聊天或 API 中生产环境中访问覆盖模型。在执行此操作之前，请记住：

- **在 HIPAA 就绪企业计划上，主所有者可以将 HIPAA 配置应用到 Claude Code（本地模式）和 Cowork（本地模式），而不是设置单独的组织。**您的 Anthropic 账户团队首先启用它。请参阅本文中的**如何在 BAA 下访问覆盖模型**。

- **没有 ZDR 或 HIPAA 配置的标准 API 组织不是 Anthropic BAA 下的合格服务。**不要通过它提交受保护的健康信息 (PHI)。

- **HIPAA 就绪和 ZDR 不能在单个 1P API 组织上共存。**如果您的组织需要 HIPAA 就绪生产 API 使用和 Claude Code 的 ZDR，您将需要单独的组织 ID。

- **Claude Desktop 中的 Cowork 仅在应用 HIPAA 配置到 Claude Code（本地模式）和 Cowork（本地模式）时才是合格服务。**如果没有该配置，不要将 Cowork 与 PHI 一起使用。BAA 不覆盖云中的 Cowork，该配置不可用。

- **如果您的团队在具有不同覆盖范围的多个组织中工作，您负责确保 PHI 仅通过合格服务提交**，根据**[HIPAA 实体实施指南](https://trust.anthropic.com/resources?s=rgirr4qe8u7ek8c2igx3&name=claude-for-enterprise-hipaa-ready-offering-implementation-guide)**配置。
