# 网络验证计划安全要求

客户必须满足并维持以下安全要求，适用于客户持有的每个网络验证计划访问级别（"**访问级别**"）。这些要求适用于获批用户和授予的工作区。

## 1. 所有访问级别。

1. **安全联系人。**客户必须向 Anthropic 提供一名指定的安全联系人，该联系人可以接收安全和滥用警报并能够对其采取行动。

2. **事件报告。**客户必须在 72 小时内向 Anthropic 报告涉及该授权的可疑泄露或滥用，或在 24 小时内报告安全事件。报告可通过 <security@anthropic.com> 或您的账户团队联系人进行。

3. **配合。**客户必须在 48 小时内调查 Anthropic 发现的任何滥用行为，与 Anthropic 合作进行补救，并在七 (7) 天内回应滥用查询。

4. **个人访问。**每个获批用户必须以自己的身份登录。不允许共享登录、座位、会话和工作负载身份，以及暴露会话给不是明确满足以下所有要求的获批用户的浏览器扩展或代理工具。

5. **使用归属。**用户配置文件必须在授予的工作区中保持启用，以便请求可以归属于指定用户或工作负载身份。

6. **变更通知。**客户必须在其安全态势、所有权、总部或安全联系人发生重大变更后的三十 (30) 天内通知 Anthropic。

7. **持续审查。**Anthropic 可能要求客户提供符合这些网络验证计划安全要求的证据。

## 2. 防御访问。

1. **多因素身份验证。**在客户访问 CVP 时，所有可以登录授予的工作区或持有其凭证的账户必须启用多因素身份验证。到 2026 年 12 月 15 日（"截止日期"），所有此类账户必须使用抗钓鱼多因素身份验证，如 CISA 事实表"实施抗钓鱼 MFA"和 NIST SP 800-63B-4 中所定义，即 (i) FIDO2/WebAuthn 安全密钥、(ii) 设备上或密码管理器中的通行密钥，或 (iii) 智能卡/PIV，且必须禁用电子邮件魔法链接登录。短信、语音、电子邮件代码、身份验证器应用代码和推送批准不符合条件。

2. **凭证管理。**到截止日期，不得使用下载、导出或其他长期静态凭证（包括 API 密钥）来访问模型。以下要求适用于客户基于其访问模型的部署平台。对于每个适用平台，所有获批用户和所有工作负载必须使用该平台本机身份服务颁发和管理的短期凭证进行身份验证。

  1. **Anthropic（第一方 API 和控制台）。**不允许使用静态或长期 API 密钥，包括对 Claude 控制台、Claude for Enterprise、Claude Code 和其他 Anthropic 应用表面的交互式访问。

  2. **Google Vertex。**不允许下载的服务账户 JSON 密钥文件。

  3. **Amazon Web Services（Amazon Bedrock）。**不允许 IAM 用户访问密钥对（访问密钥 ID 和秘密访问密钥），但短期 Bedrock API 密钥除外，这些密钥在 12 小时内或 Bedrock 会话长度内过期，以较短者为准。

  4. **Microsoft Azure（Azure AI Foundry）。**不允许 API 密钥和导出的服务主体客户端密钥或证书。

3. **临时 API 密钥。**在截止日期之前，API 密钥仅在防御访问授权下允许，条件是每个密钥 (i) 存储在密钥管理器或密码管理器中、(ii) 分配给单个人员或工作负载、(iii) 保持在源代码之外，以及 (iv) 至少每 7 天替换一次。Anthropic 可能会将防御访问授权下的 API 密钥生命周期限制为 7 天，并可能从截止日期起禁用授予的工作区上的 API 密钥。

4. **获批用户。**此访问级别的获批用户数量没有默认限制。

## 3. 个人防御访问。

1. 个人仅有资格获得防御访问。当授权由个人持有时，本部分适用

  1. **多因素身份验证。**个人必须仅通过 Google 或等效身份提供商登录持有授权的 Anthropic 账户。从授予访问权限之日起，该账户必须启用多因素身份验证。到 2026 年 12 月 15 日（"截止日期"），该账户必须使用抗钓鱼多因素身份验证，即安全密钥、通行密钥或智能卡/PIV，且个人不得使用电子邮件魔法链接登录。短信、语音、电子邮件代码、身份验证器应用代码和推送批准不符合条件。

  2. **凭证管理。**到截止日期，不得使用静态或长期凭证（包括 API 密钥）来访问模型。Claude Code、Claude 控制台和 claude.ai 通过 OAuth 进行身份验证。工作负载的程序化访问（如果提供）必须使用工作负载身份联合。在截止日期之前，仅允许一个 API 密钥，条件是 (i) 存储在密码管理器或本地密钥存储中、(ii) 从不共享或放在源代码中，以及 (iii) 至少每 7 天替换一次。Anthropic 可能会将授权下的 API 密钥生命周期限制为 7 天，并可能从截止日期起禁用 API 密钥。

  3. **个人访问。**仅该个人可以使用该访问权限。不允许共享登录或会话，以及暴露会话给他人的浏览器扩展或代理工具。

  4. **监控。**授权下的所有流量都被保留和监控。零数据保留不可用。

  5. 在所有访问级别要求中，事件报告、配合和持续审查适用于个人。

## 4. 红队访问。

1. **凭证管理。**以下要求适用于客户基于其访问模型的部署平台。对于每个适用平台，所有获批用户和所有工作负载必须使用该平台本机身份服务颁发和管理的短期凭证进行身份验证。

  1. **Anthropic（第一方 API 和控制台）。**不允许使用静态或长期 API 密钥，包括对 Claude 控制台、Claude for Enterprise、Claude Code 和其他 Anthropic 应用表面的交互式访问。

  2. **Google Vertex。**不允许下载的服务账户 JSON 密钥文件。

  3. **Amazon Web Services（Amazon Bedrock）。**不允许 IAM 用户访问密钥对（访问密钥 ID 和秘密访问密钥），但短期 Bedrock API 密钥除外，这些密钥在 12 小时内或 Bedrock 会话长度内过期，以较短者为准。

  4. **Microsoft Azure（Azure AI Foundry）。**不允许 API 密钥和导出的服务主体客户端密钥或证书。

2. **多因素身份验证。**在客户访问 CVP 时，抗钓鱼多因素身份验证必须保护 (i) 所有可以登录授予的工作区或持有其凭证的账户、(ii) 获批用户在客户身份提供商处的账户、(iii) 可以调用模型的 AWS、Google Cloud 或 Azure 身份、(iv) 对任何颁发或存储模型凭证的内容的管理访问，以及 (v) 用于满足这些要求的任何虚拟桌面或飞地。抗钓鱼多因素身份验证是指 (i) FIDO2/WebAuthn 安全密钥、(ii) 设备上或密码管理器中的通行密钥，或 (iii) 智能卡/PIV，与 CISA 事实表"实施抗钓鱼 MFA"和 NIST SP 800-63B-4 一致。短信、语音、电子邮件代码、身份验证器应用代码和推送批准不符合条件，且必须禁用电子邮件魔法链接登录。

3. **组织账户。**获批用户必须使用客户域上的账户登录。不允许个人和网络邮箱账户。

4. **获批用户。**授予的工作区限制为七十五 (75) 名获批用户，他们亲自执行或直接监督获批工作。工作负载身份不计入该数字。客户可以书面请求（电子邮件即可）额外的获批用户座位。仅指定的管理员可以添加成员、更改角色或在授予的工作区上创建工作负载身份或凭证。

5. **网关。**如果客户在模型前面运营网关或代理，它必须仅允许获批用户或其工作负载身份、使用自己的短期凭证，并将其日志和记录限制在获批用户和客户的安全、IT 管理或信任与安全团队。

6. **客户运营的凭证系统。**由客户自己的系统颁发的凭证必须在 12 小时内过期，必须仅在抗钓鱼多因素身份验证（对于人员）或经过验证的工作负载身份（对于服务）后颁发，且必须在端点、源代码或共享存储中不留下任何静态凭证。可以颁发模型凭证的密钥和密钥必须保存在具有访问日志记录的密钥管理器或密钥管理服务中。

7. **撤销。**客户必须能够在 24 小时内撤销任何受损的凭证或身份。

8. **离职。**客户必须在三 (3) 个工作日内从授予的工作区中移除已离职或重新分配的获批用户及其工作负载身份。

9. **网络出口。**无论模型在何处执行攻击性或代理工作，出站流量必须限制在主机外强制执行的允许列表，并且必须被记录。仅用于交互式提示的工作站可以使用主机上的允许列表，如果代理工作本身在无法更改该列表的沙箱中运行。

10. **托管设备。**获批用户必须仅从客户控制的接收自动或定期操作系统更新的设备访问授予的工作区，而不是个人设备。

11. **背景调查。**每个获批用户（包括承包商）必须通过身份检查，以及在法律允许的情况下，犯罪历史检查。在当地法律限制犯罪检查的地方，接受身份、工作权利或就业验证。政府审查或许可满足此要求。

12. **事件程序。**客户必须维持一份关于授权的可疑泄露或滥用的书面程序，涵盖凭证撤销和座位暂停。

13. **政府实体。**具有年度独立监察长评估（针对 NIST SP 800-53）的 FISMA 运营授权，或等效的国家计划，满足托管设备、背景调查和事件程序要求。所有其他要求继续适用。
