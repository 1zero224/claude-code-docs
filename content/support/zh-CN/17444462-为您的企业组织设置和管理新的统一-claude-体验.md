# 为您的企业组织设置和管理新的统一 Claude 体验

新的统一 Claude 体验将聊天和 Cowork 整合在网页、桌面和移动设备上。成员不再需要在开始前选择聊天或 Cowork。每个对话都以聊天开始，当任务需要运行代码或处理文件时，Claude 会在由 Anthropic 管理的隔离云沙箱中继续同一对话，然后返回完成的工作供审查。

本文介绍管理员如何启用新的统一 Claude 体验、哪些设置适用于它，以及它如何适配您的安全、合规和数据保留设置。

新的统一 Claude 体验适用于企业计划，在管理员设置中显示为**聊天和 Cowork 统一**。在现有组织中默认关闭，将在 2026 年 11 月 16 日默认启用。

---

## 新的统一 Claude 体验如何工作

1. 一个对话，两种模式。新的统一 Claude 体验以聊天开始，当任务需要代理工作时进入 Cowork 云会话，不需要时返回聊天。成员无需切换模式。

2. 代理工作在隔离的云沙箱中运行。每个需要沙箱的对话都有自己的虚拟机，由 Anthropic 管理。闲置几分钟后，虚拟机停止，其磁盘保存为加密快照。沙箱环境在创建后 30 天过期。

3. 对话保持记录。聊天历史、共享、导出、合规 API 和您的数据保留设置都从对话中工作。

4. 工作跨设备移动。成员可以在桌面应用上启动任务，然后在网页或移动设备上继续。

5. 本地访问保持可选。通过 Claude 桌面应用，成员可以链接他们的计算机，以便 Claude 可以处理本地文件夹、本地 MCP 服务器和应用程序。您的远程控制和设备策略管理这一点。

## 开始前

新的统一 Claude 体验需要为您的组织启用两项功能：

1. 聊天，因为每个对话都从聊天开始。

2. 云代码执行和文件创建，因为代理工作远程运行。

它不需要启用 Cowork 或云中的 Cowork。它旨在随着时间推移替代两者。

| **您的组织现状**                    | **要做的事**                                                        |
| ----------------------------- | --------------------------------------------------------------- |
| 仅聊天                           | 启用**聊天和 Cowork 统一**。您无需单独启用 Cowork 或云中的 Cowork。确保启用了云代码执行和文件创建。 |
| 仅 Cowork，或 Cowork 和云中的 Cowork | 启用聊天功能，然后启用**聊天和 Cowork 统一**。确保**云代码执行和文件创建**已启用。               |
| 聊天和 Cowork                    | 确保**云代码执行和文件创建**已启用，然后启用**聊天和 Cowork 统一**。                      |

新的统一 Claude 体验尚不适用于使用零数据保留 (ZDR)、HIPAA 就绪配置或客户管理的加密密钥 (CMEK) 的组织。请参阅下面的**[当前限制](#h_8b973139dd)**。

## 启用新的统一 Claude 体验

### 对于整个组织

1. 以所有者或主要所有者身份登录 Claude。

2. 转到**[组织设置 > 功能](https://claude.ai/admin-settings/capabilities)**。

3. 启用**聊天和 Cowork 统一**。

4. 如果成员没有立即看到新体验，请要求他们刷新 Claude 应用。

这为具有用户、管理员、所有者或主要所有者角色的成员启用新的统一 Claude 体验。具有自定义角色的成员仅在其角色也包括聊天和 Cowork 统一时才能获得它。

计划的任务和会话历史将在更改后继续工作。您无需更新或重新创建任何内容。

### 如果您尚未更改此设置

在**[组织设置 > 功能](https://claude.ai/admin-settings/capabilities)**中，在聊天和 Cowork 统一下，所有者和主要所有者会看到"将在 2026 年 11 月 16 日自动启用"。选择立即启用以提前启用，或保持禁用以保持关闭。您仍然可以稍后关闭它。如果设置已经启用或禁用，该选择将保持不变。

如果聊天或云代码执行和文件创建已关闭，则没有通知，也不会启用任何内容。2026 年 11 月 16 日之后，一旦两者都启用，新体验就会启用。

### 对于特定成员，使用角色

上述组织设置也必须启用。启用后，所有具有用户、管理员、所有者或主要所有者角色的人都可以访问。在启用之前，将不应该拥有它的任何人移至关闭了聊天和 Cowork 统一的自定义角色。新角色从所有功能开始，其中包括它。

如果您的组织使用自定义角色，您可以向特定角色授予新的统一 Claude 体验：

1. 转到**[组织设置 > 角色](https://claude.ai/admin-settings/roles)**。

2. 打开要更新的角色并转到"功能"。

3. 为该角色启用**聊天和 Cowork 统一**。

4. 将角色分配给应该有权访问的成员。您可以通过 SCIM 同步角色成员资格以分阶段添加成员。

每个请求都会检查访问权限。如果您删除成员的角色或关闭设置，他们将失去对新的统一 Claude 体验的访问权限。

要了解如何创建角色，请参阅**[在企业计划上设置基于角色的权限](https://support.claude.com/en/articles/13930458)**。

### 推荐的推出

1. 与您的 IT、安全和采购团队分享本文。

2. 完成您的安全审查。大多数团队审查他们已经了解的两个组件：Claude 聊天和云中的 Cowork。如果已经在进行云中 Cowork 的审查，它会继续进行。

3. 如果您有沙箱组织，请从沙箱组织开始，或通过角色与试点组开始。

4. 在启用体验之前，查看您的网络出口、连接器、共享和远程控制设置。

5. 监控使用情况并收集两到四周的反馈，然后分阶段扩展。

## 数据保留和删除

1. **对话。**对话保留至成员删除它们或根据您组织的自定义数据保留设置（如果您已设置一个，最少 30 天）。请参阅**[自定义数据保留](https://support.claude.com/en/articles/10440198)**。项目中的对话在用户删除项目后或项目及其所有对话在项目保留期内处于非活动状态后被删除。该期限从对话中最近的活动或从其启动的任何云会话中的活动开始计算。

2. **从对话启动的云会话。**当对话被删除时（无论是由成员删除、删除其项目还是根据您的保留期），Claude 在其中启动的云会话也会被删除，包括其记录。删除在对话被移除后在后台完成。

3. **记忆。**账户记忆由您的聊天自定义数据保留设置覆盖，项目记忆在项目删除时被删除，包括您的项目数据保留期。迁移到新体验后，记忆将移至新的记忆系统，旧记忆可能在 14 天后被删除，或如果超过数据保留期则更早删除。

4. **工件。**工件（包括 Claude 在对话中创建的工件）遵循您的私有和共享工件保留期，或您的所有数据期限，而不是对话的期限。这些期限不会删除使用公共链接发布的工件。某些工件（如研究报告和某些较旧对话中的工件）会与其对话一起被删除。

5. **Claude 提供给您的文件。**Claude 在 2026 年 10 月 8 日或之后在对话中提供给您的几乎所有文件（如文档或电子表格）都会与其一起被删除，包括在您的保留期内，除非您组织中的另一个对话或项目使用它们。较旧的文件在其对话被删除后可能仍然存在。

6. **不与对话一起删除。**自定义数据保留不涵盖：

  1. 成员直接启动的 Cowork 云会话，包括在项目中的会话。这些保留至成员删除它们。

  2. 计划任务及其运行，包括从对话创建的任务。这些任务在该对话被删除后继续运行。要停止它们运行，请关闭计划任务。

  3. 存储在成员计算机上的 Cowork 历史记录。

  4. 已离开您组织的成员的记忆。

  5. 由 Claude Code（包括网络上的 Claude Code）、Claude Tag 和聊天和 Cowork 之外的其他产品保留的记录和记忆。

删除在期限结束后进行，而不是在确切的时刻进行，已删除的数据从我们的后端系统中移除。与聊天一样，我们可能会保留由我们的信任和安全系统标记的内容或法律要求的内容。请参阅**[您存储我的组织数据多长时间？](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)**

## 使用和分析

新的统一 Claude 体验在您的报告中有自己的行。当成员有权访问新的统一 Claude 体验时，他们的聊天和 Cowork 使用情况在**聊天和 Cowork 统一**下报告，而不是在聊天或 Cowork 下。可以将其视为相同工作的新文件夹：只有使用情况的归档位置发生变化，因此将使用情况移至此行不会改变其计数或计费方式。

### 如何计算使用情况

- **计数跟随每个成员。**如果成员在使用情况发生时有权访问新的统一 Claude 体验，则使用情况计入新的统一 Claude 体验。如果您首先为某些角色启用它，您的报告可以在同一天显示聊天、Cowork 和**聊天和 Cowork 统一**。

- **它涵盖聊天和 Cowork。**成员的聊天、他们的云会话和他们对 Cowork 桌面应用的使用计入新的统一 Claude 体验。

- **其他产品保持自己的行。**例如，Claude Code 和 Chrome 中的 Claude 使用情况仍在这些产品下报告。

- **过去的使用情况保持原样。**新的统一 Claude 体验的数据从成员首次获得访问权限的那一天开始。之前的使用情况保持在聊天或 Cowork 下。如果您关闭新的统一 Claude 体验，过去的统一使用情况保持其**聊天和 Cowork 统一**标签，新使用情况返回到聊天和 Cowork。

- **在您汇总时包括它。**当您汇总聊天和 Cowork 的支出、令牌或消息时，也包括**聊天和 Cowork 统一**。否则，您的聊天和 Cowork 数字在成员迁移时似乎会下降。对于人数，使用总体活跃用户计数，而不是将产品相加，因为一个人可以在多个产品中活跃。

### 在 API 中

**您的密钥已经有效。**如果您已经使用这些 API，您现有的访问密钥有效。如果您的脚本根据固定的字段或产品列表检查响应，请添加新的。

**成本和使用 API。**新的统一 Claude 体验的令牌和支出在产品值`chat_cowork_unified`下报告。您可以使用`products[]`过滤到它。`chat`和`cowork`值仍然有效，并涵盖在该时间没有新的统一 Claude 体验的成员的使用情况。

**分析 API。**成员、技能和连接器行有一个`chat_cowork_unified_metrics`对象，包含两部分：`chat`（用于聊天活动）和`sessions`（用于云会话和 Cowork 桌面应用）。每日摘要为新的统一 Claude 体验添加每日、每周和每月活跃用户计数，例如`chat_cowork_unified_daily_active_user_count`。

## 新的统一 Claude 体验的高效模式

启用后，组织成员在新的统一 Claude 体验中只能使用 Sonnet 和 Haiku 模型，新会话以低工作量的 Claude Sonnet 5.5 开始。其他产品不受影响。随着更低成本的模型推出，Anthropic 可能会更新默认模型和工作量级别，以保持性能和成本的最佳平衡。

**如何访问：**所有者可以在"模型"页面为整个组织启用此功能，或在每个角色的"模型"选项卡上为特定自定义角色启用此功能。

## 当前限制

1. **ZDR、HIPAA 和 CMEK。**新的统一 Claude 体验不适用于具有零数据保留、HIPAA 就绪配置或客户管理的加密密钥的组织。这些组织继续按照现在的方式使用聊天和 Cowork，管理员无法启用聊天和 Cowork 统一。HIPAA 支持预计在正式发布后提供；CMEK 支持计划在后续版本中提供。如果您的组织在启用新体验后启用 CMEK，该体验将变为不可用。
