# 在企业计划上管理自定义角色

自定义角色适用于企业计划组织。所有者、主要所有者以及权限集设置为“可管理”的**身份和访问**自定义角色可以转到**[组织设置 > 角色](https://claude.ai/admin-settings/roles)**来管理自定义角色。

## 什么是自定义角色？

自定义角色让您定义成员可以访问哪些功能。每个自定义角色包含一组权限，这些权限授予或限制对特定功能的访问，如聊天、Claude Cowork、Claude Code 和网络搜索，以及您的组织添加的连接器，如 Slack 或 Google Drive。

自定义角色还可以授予管理员权限，这使成员可以访问特定的管理区域（如计费、身份或隐私），而无需将其设为所有者。自定义角色也可以通过**所有者访问**权限授予所有者的所有管理员权限。

自定义角色与组一起工作。典型的工作流程是：创建自定义角色，将其分配给组，然后将成员的角色设置为“自定义”，以便其访问权限完全由分配给其组的自定义角色管理。

**注意：**自定义角色仅影响角色设置为“自定义”的成员。具有用户、管理员或所有者角色的成员直接从这些角色获得其权限，而不是从自定义角色获得。

**注意：**启用 SCIM 目录同步和组映射后，每个成员的角色由同步拥有。在启用组映射之前角色设置为“自定义”的成员将在下次完整同步时恢复为其映射的角色，除非他们在映射到“自定义”的 IdP 组中。请参阅**[在企业计划上管理组和组支出限制](https://support.claude.com/en/articles/13799932-manage-groups-and-group-spend-limits-on-enterprise-plans#h_05cb172230)**。

## 功能访问如何工作

功能访问由四级优先级链确定，其中最严格的级别获胜：

1. **平台级覆盖**：某些功能可能由 Anthropic 作为您合同的一部分为您的组织强制启用或强制禁用。这些无法在组织设置中更改。

2. **组织级设置**：所有者或主要所有者可以为整个组织切换功能的开启或关闭。如果在组织级别禁用了某个功能，则任何自定义角色都无法授予对其的访问权限。

3. **自定义角色权限**：如果在组织级别启用了该功能，成员的自定义角色将确定他们是否可以访问它。如果成员的任何自定义角色授予该功能，他们就拥有它。

4. **用户级设置**：如果在角色级别授予了该功能，除非成员在其自己的设置中禁用了它，否则该功能可用。

关键要点：组织级切换是主开关。自定义角色是其下的按成员切换。必须在组织级别启用功能，然后自定义角色才能控制谁获得访问权限。

**注意：**此优先级链适用于功能。管理员权限不受组织级切换或成员自己的设置的限制。如果成员的自定义角色授予管理员权限，他们就拥有该访问权限。

### 一次授予所有权限

您可以一次性为角色授予所有权限，而不是逐个切换权限。创建或编辑角色时，在 **Capabilities** 标签页上为 **Capability access** 选择一个选项：

- **All capabilities：**为角色授予所有权限，包括测试版和研究预览中的权限。

- **All generally available：**为角色授予所有通常可用的权限。

设置为任一选项的角色会在新权限推出时自动获取。设置为 “Only selected” 的角色仅包含您选择的权限。

## 创建自定义角色

1. 导航到 **[组织设置 > Roles](https://claude.ai/admin-settings/roles)**。

2. 点击 “Add role。”

3. 输入角色名称（例如 “Developer，” “Standard Access，” 或 “Restricted”）。

4. 选择要分配给该角色的群组。

5. 切换每个权限的开关以定义此角色授予的内容，或选择 “All capabilities” 或 “All generally available” 一次性授予所有权限。

6. 配置权限。您可以为每个管理设置选择 No access、Can view 和 Can manage。

7. 配置连接器。您可以为所有连接器选择 Always allow、Needs approval 或 Blocked，或按连接器或连接器工具自定义。

8. 配置模型。选择此角色可以使用的模型，可选择为每个模型设置最大工作量级别，并可选择为角色选择默认模型和默认工作量级别。

9. 点击 “Save role。”

## 编辑自定义角色

1. 导航到 **[组织设置 > 角色](https://claude.ai/admin-settings/roles)**。

2. 点击要编辑的角色。

3. 更新名称和组，或根据需要切换功能、权限、连接器和模型。

4. 点击 “保存角色” 以保存更改。

角色更改可能需要长达 15 分钟才能生效，成员可能需要刷新浏览器。分配给此角色的组中的所有成员都会受到影响。

## 删除自定义角色

点击任何自定义角色上的菜单按钮，然后选择 “删除角色。”删除角色会从分配给它的所有组中移除其权限。这些组中的成员会失去该角色授予的权限，除非其链中的另一个角色也授予了这些权限。

## 将组分配给自定义角色

自定义角色分配给组，而不是直接分配给个别成员。要将组分配给角色：

1. 导航到 **[组织设置 > 角色](https://claude.ai/admin-settings/roles)**。

2. 点击要分配的角色。

3. 在组选择器中，选择一个或多个组。

4. 点击 “保存角色。”

您也可以在 **[组织设置 > 组](https://claude.ai/admin-settings/groups)** 中创建或编辑组时分配自定义角色。请参阅 **[在企业计划中管理组和组支出限制](https://support.claude.com/en/articles/13799932-manage-groups-and-group-spend-limits-on-enterprise-plans)**。

## 权限如何跨多个角色组合

如果成员属于具有不同自定义角色的多个组，其权限是 **累加的**——他们获得其链中所有角色的所有权限的并集。如果任何角色授予某项功能，成员就可以访问它。

这意味着您不能使用一个角色来移除另一个角色授予的权限。这是设计使然——它支持分层方法，其中基础角色涵盖常见功能，其他角色在特定功能和管理员权限上分层。

**示例：**成员在两个组中。“所有用户” 组分配了具有网络搜索和记忆功能的 “标准访问” 角色。“工程” 组分配了具有 Cowork 和 Claude Code 的 “开发者” 角色。成员获得所有四项：网络搜索、记忆、Cowork 和 Claude Code。

## 查看成员或组的有效角色

当成员属于多个组且其角色授予不同功能时，很难判断他们实际可以做什么。“查看有效角色” 选项显示组合结果：成员拥有的每项功能、管理员权限和连接器，以及授予每项的角色。

1. 导航到 **[组织设置 > 成员](https://claude.ai/admin-settings/members)**（或 **[组织设置 > 组](https://claude.ai/admin-settings/groups)**）。

2. 找到成员或组，并打开其行右侧的 “⋮” 菜单。

3. 选择 “查看有效角色。”

模态框列出成员的分配角色和三个选项卡：

- **功能：**每项功能都带有 “由 *[角色名称]* 授予” 标签，显示哪个角色启用了它。

- **权限：**每个管理员权限区域及其有效级别（无访问权限、可查看或可管理）以及授予它的角色。

- **连接器：**每个连接器的有效权限级别以及授予它的角色。

此视图是只读的。要更改成员可以执行的操作，请编辑分配给其组的角色。

**注意：**“查看有效角色” 仅对角色设置为 “自定义” 且通过组分配了至少一个自定义角色的成员显示。具有内置角色（用户、管理员、所有者或主要所有者）的成员直接从该角色获得权限，因此没有什么需要计算的。

## 管理员权限

自定义角色除了可以授予功能和连接器权限外，还可以授予管理员权限。管理员权限使成员可以访问特定的管理区域（如计费或隐私），而无需成为所有者。您可以在角色编辑器的 **权限** 选项卡中配置管理员权限。

**注意：**管理员权限仅适用于角色设置为 “自定义” 的成员。具有用户、管理员、所有者或主要所有者角色的成员保留这些角色授予的访问权限。

### 管理员权限级别

在 **权限** 选项卡上，您将每个权限区域设置为以下三个级别之一：

- **无访问权限：**成员在其组织设置中看不到此区域。

- **可查看：**查看授予只读访问权限。成员看到的页面和设置与可以管理该区域的人相同，但每个控件都被禁用或显示为只读。对于合规审查员、财务审计员、安全团队或任何需要查看配置但不更改配置的人，请使用此权限级别。

- **可管理：**管理授予对该区域的完全读写访问权限，包括查看访问权限。

在一个区域内，您授予所有查看或所有管理权限。您不能授予或限制单个页面或设置。

### 所有者访问权限（测试版）

**所有者访问权限**权限为自定义角色提供所有者的所有管理权限。所有者直接从所有者角色获得权限并跳过自定义角色，因此到目前为止，您必须在将某人设为所有者和使用自定义角色管理其访问权限之间进行选择。通过所有者访问权限，用户可以拥有完整的管理员访问权限，同时其功能、连接器和模型仍由分配给其组的自定义角色管理。

所有者、主要所有者和**身份和访问**设置为“可以管理”的自定义角色可以启用所有者访问权限。它与所有者角色匹配，而不是主要所有者角色。

要为角色授予所有者访问权限：

1. 导航到**[组织设置 > 角色](https://claude.ai/admin-settings/roles)**。

2. 打开要编辑的角色，或单击“添加角色”以创建一个。

3. 在**权限**选项卡上，启用**所有者访问权限**。

4. 单击“保存角色。”

所有者访问权限仅适用于其角色设置为“自定义”且在分配给该角色的组中的用户。将所有者的角色更改为“自定义”会移除其内置所有者访问权限，因此在更改其角色之前将其添加到组中。如果角色来自具有组映射的目录同步，请将用户的身份提供者组映射到“自定义”而不是所有者。

## 连接器权限

自定义角色还控制角色可以使用哪些连接器以及这些连接器上的哪些工具。功能涵盖 Claude 的内置功能，连接器权限涵盖您已连接到组织的应用和服务，例如 Slack、Google Drive 或 Jira。您可以在角色编辑器的**连接器**选项卡上设置它们，该选项卡位于**功能**和**权限**选项卡旁边。

**注意：**连接器权限仅适用于角色设置为“自定义”的成员。具有用户、管理员或所有者角色的成员可以看到为您的组织启用的每个连接器，受您的组织范围内每个连接器的工具策略的限制。所有者和管理员始终可以看到每个连接器，以便他们可以配置它，无论任何角色的连接器权限如何。

### 权限级别

在**连接器**选项卡上，您可以将所有连接器、每个连接器或连接器上的每个工具设置为以下三个级别之一：

- **始终允许：**连接器上的每个工具都可用，成员可以将其自己的批准设置为“始终允许”以跳过每次调用确认。

- **需要批准：**每个工具都可用，但成员确认每次调用。“始终允许”选项从这些工具的个人批准菜单中删除。

- **已阻止：**连接器或工具被隐藏。Claude 无法看到或调用它。

连接器也可以设置为**自定义**，这允许您单独设置其每个工具。有关完整设置，请参阅**[在企业计划上设置基于角色的权限](https://support.claude.com/en/articles/13930458-)**。

### 如何确定连接器访问权限

连接器或工具在成员可以使用它之前要经过多个层级，按以下顺序评估：

1. **角色授予。**角色上的每个连接器或工具设置为“始终允许”、“需要批准”或“已阻止”。

2. **跨成员的角色。**如果成员的群组给予他们多个角色，则每个工具的最宽松授予适用。连接器权限在角色之间是累加的，与功能相同。

3. **组织范围的工具策略。**您在**[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)**下为每个连接器设置的每工具策略是上限。对于每个工具，Claude 将成员的角色授予与此策略进行比较，并应用两者中更严格的一个。角色授予在策略内缩小访问权限；它们无法超越它扩大。了解有关在**[使用连接器扩展 Claude 的功能](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)**中设置工具访问权限的更多信息。

4. **成员自己的设置。**上述步骤的结果是成员的有效上限。它限制了其个人每工具批准菜单中的选项（“始终允许”、“询问”或“从不”）。“需要批准”的上限删除“始终允许”。“已阻止”的上限使工具灰显。

对于使用 Claude Code 的成员，还应用一个额外的层级：托管设置策略和连接器权限按最严格的方式组合。只有当两者都允许时，工具才可以在没有提示的情况下调用。有关更多信息，请参阅**[Claude Code 设置](https://code.claude.com/docs/en/settings#settings-files)**。

对于使用 Claude Cowork 的成员，可写连接器工具还要通过一个额外的门。请参阅下面的**[Cowork 写工具批准设置](#h_85bd7c30e9)**。

此表显示组织范围的工具策略和成员的角色授予如何组合：

| **组织范围的工具策略** | **成员角色中的最高角色授予** | **有效上限** | **成员的个人选项** |
| ------------- | ---------------- | -------- | ----------- |
| 始终允许          | 始终允许             | 始终允许     | 始终允许、询问、从不  |
| 始终允许          | 需要批准             | 需要批准     | 询问，从不       |
| 始终允许          | 已阻止              | 已阻止      | 工具已灰显       |
| 需要批准          | 始终允许             | 需要批准     | 询问，从不       |
| 需要批准          | 已阻止              | 已阻止      | 工具已灰显       |
| 已阻止           | 任何               | 已阻止      | 工具已灰显       |

### 写入工具的协作批准设置

Claude Cowork 有一个单独的组织设置**允许连接器工具“始终允许”**，用于控制具有写入功能的连接器工具。该设置默认关闭，自定义角色授权无法覆盖它：即使组织范围的工具策略和每个角色授权都设置为“始终允许”，成员也需要在 Cowork 中按任务批准这些工具，直到启用该设置。详细了解**[Cowork 中的连接器工具批准](https://support.claude.com/en/articles/13455879-use-claude-cowork-on-team-and-enterprise-plans#h_1bd1fa754d)**。

### 连接器权限的适用范围

连接器权限在 Anthropic 的服务器上强制执行，因此适用于通过 Anthropic 路由连接器流量的每个 Claude 界面：

| **界面**                       | **覆盖范围**                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------- |
| 网页版和桌面版 Claude               | 完全强制执行。被阻止的连接器被隐藏，被阻止的工具被灰显，个人批准菜单仅限于上限允许的内容。                                                           |
| Claude Mobile（iOS 和 Android） | 已强制执行。被阻止的工具从 Claude 的视图中移除，对它们的调用被拒绝。被阻止的工具在移动连接器设置中可能仍显示为活跃，直到界面更新发布，但无法使用。                           |
| Claude Cowork（云端和桌面）         | 与网页版相同。                                                                                                 |
| Claude Code                  | 已强制执行。被阻止的工具被拒绝并显示为禁用。请参阅**[Claude Code 设置](https://code.claude.com/docs/en/settings#settings-files)**。 |

连接器权限管理您的组织在**[组织设置 > 连接器](https://claude.ai/admin-settings/connectors)**下添加的连接器。它们不管理成员在自己机器上本地运行的连接器，也不管理部署在第三方平台上的 Claude Cowork。对于第三方 Cowork 部署，请改用 MDM。请参阅**[第三方 Cowork：MCP、插件、技能和钩子](https://claude.com/docs/cowork/3p/extensions)**。

### 连接器受限时成员看到的内容

| **限制**                      | **成员看到的内容**                                             |
| --------------------------- | ------------------------------------------------------- |
| 连接器对其角色被阻止                  | 该连接器不会出现在其连接器菜单中。                                       |
| 工具在可见连接器上被阻止                | 该工具在其连接器设置中被灰显，并显示消息“此工具未为您的角色启用。请联系您的管理员。”             |
| 工具上限为“需要批准”                 | 该工具可用，但个人批准菜单仅提供“询问”和“从不”选项，Claude 在每次调用前询问。            |
| Cowork “允许连接器工具“始终允许””设置已关闭 | 在 Cowork 中，具有写入功能的工具可用，但“允许所有任务”被灰显，成员需要批准每个任务。         |
| 连接器权限无法短暂加载                 | 横幅报告连接器无法加载，并提供重试选项。被阻止的工具永远不会到达连接的服务。访问失败时倾向于拒绝，而不是授予。 |

成员无法判断哪一层限制了工具。无论限制来自组织范围的工具策略、角色授权还是两者，消息都是相同的。要找到来源，请将组织范围的策略与成员的角色授权进行比较。

## 模型访问

自定义角色还控制该角色可以使用哪些 Claude 模型，以及成员在每个模型上可以选择的最大工作量级别。您可以在角色编辑器的**模型**选项卡上设置这些，以及角色的默认模型和默认工作量级别。

组织级别的模型设置是上限。角色无法授予在组织级别禁用的模型。在成员的各个角色中，模型访问是累加的，工作量限制采用任何角色允许的最高上限。Haiku 模型始终可用，无法禁用。

有关设置步骤和成员看到的内容，请参阅**[管理组织的模型访问](https://support.claude.com/en/articles/15694740)**。有关默认模型行为，请参阅**[为组织设置默认模型](https://support.claude.com/en/articles/15330088)**。
